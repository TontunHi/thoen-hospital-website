# เทมเพลต Brief สำหรับสั่ง AI ออกแบบ UI (Mode B)

ใช้กรอกข้อมูลบริบทจริงของระบบโรงพยาบาลเถินก่อนส่งให้ AI ห้ามส่งเทมเพลตเปล่า

---

## 1. ข้อความ Prompt หลักสำหรับส่งให้ AI

```text
ช่วยออกแบบหน้า [ระบุชื่อหน้า เช่น รายการนัดหมายคลินิกพิเศษ] ใหม่ (แนบภาพหน้าเดิมหรือโครงสร้างเดิม)

บริบทระบบและกลุ่มผู้ใช้งาน:
- หน้าที่การทำงาน: [ระบุหน้าที่ เช่น แสดงรายการนัดหมาย คัดกรองสถานะ และยืนยันการมาถึงของผู้ป่วย]
- ผู้ใช้งานหลัก: [เช่น ผู้ป่วยทั่วไป / ญาติผู้สูงอายุ / พยาบาลหน้าห้องตรวจ] ซึ่งส่วนใหญ่ไม่คุ้นเคยกับเทคโนโลยี ต้องการความง่ายและชัดเจนสูงสุด
- เทคโนโลยี: Next.js 16 (App Router), React 19, CSS Modules (ใช้ตัวแปร CSS จาก globals.css), เชื่อมต่อผ่าน API Gateway

ปัญหาของหน้าเดิมที่ต้องแก้ (ระบุชัดเจน):
1. [เช่น หน้าจอแน่น อึดอัด ตัวหนังสือและแถวตารางบีบติดกันจนอ่านยาก]
2. [เช่น ปุ่มและฟังก์ชันดูไม่ออกว่าอะไรกดได้ ลำดับการใช้งานสับสน]

แนวทางดีไซน์ที่ต้องการ (Modern, Friendly & Spacious):
- โทน: ทันสมัย สะอาด สบายตา อบอุ่น เป็นมิตร (Modern & Reassuring Hospital Interface)
- ระยะห่างและพื้นที่หายใจ (Breathing Room): ห้ามบีบอัดข้อมูลจนแน่นเด็ดขาด! ใช้ Card padding 20-24px, Section gap 24-32px, แถวตารางสูงอย่างน้อย 52-56px เพื่อให้อ่านสบายตา
- ออกแบบเพื่อผู้ใช้ทั่วไป (Non-Tech UX):
  - Affordance ชัดเจน ปุ่มดูออกทันทีว่าเป็นปุ่ม ฟิลด์กรอกมีขอบเขตและตัวอย่างชัดเจน
  - ภาษาเข้าใจง่าย ไร้ศัพท์เทคนิคไอที (No Jargon)
  - ขนาดพื้นที่กด (Touch Target) บนมือถือและจอสัมผัส >= 44-48px
  - มีไอคอนนำสายตาที่มีหน้าที่ชัดเจน (Purposeful Visual Anchors) เช่น ไอคอนปฏิทิน, นาฬิกา, แว่นขยาย ช่วยให้สแกนหน้าจอได้ทันที
- การจัดแนวข้อมูลในตาราง (Table Alignment): ข้อมูลในเซลล์ (td) ต้องแสดงตรงกลางของหัวข้อ (th) เสมอสำหรับคอลัมน์ลำดับ, วันที่, เวลา, รหัส/HN, ป้ายสถานะ Badge, จำนวนนับ, และปุ่ม Action ป้องกันปัญหาข้อมูลเอียงริมซ้ายริมขวาสะเปะสะปะ โดย th และ td ต้องมี alignment ตรงกัน 100% (ยกเว้นข้อความบรรยายยาวที่ชิดซ้ายทั้งคู่ และยอดเงินที่มีจุดทศนิยมที่ชิดขวาทั้งคู่)
- กดดูข้อมูลผ่าน Record โดยตรง (Row-Clickable Records): ให้คลิกทั้งแถว (tr) เพื่อเปิดดูรายละเอียดใน Modal ได้โดยตรง ไม่ต้องเพิ่มคอลัมน์ปุ่มเปิดดูซ้ำซ้อน
- แถบเลือกช่วงเวลาในแถวเดียว (Single-Row Date Selector): แท็บสลับโหมดและตัวเลือกวันที่ต้องจัดวางในแถวเดียวกันในบรรทัดเดียว มีเส้นคั่นบางแนวตั้ง ไม่ตัดขึ้นบรรทัดใหม่
- การ์ดสรุป KPI สมมาตรแถวละเท่ากัน (Equal KPI Grid): จัดการ์ดสรุปสถิติให้แสดงแถวละเท่าๆ กันเสมอ (เช่น 4 คอลัมน์ x 2 แถว) ห้ามแถวบนและล่างมีจำนวนไม่เท่ากันจนแหว่ง
- ช่องค้นหาครอบคลุมในช่องเดียว (Unified Global Search): ช่องค้นหาต้องรองรับการพิมพ์ค้นหาทุกมิติได้พร้อมกันในช่องเดียว ไม่ต้องมีดรอปดาวน์เลือกฟิลด์มาเกะกะสายตา
- ฟอนต์: Sarabun, ตัวเลขในตารางและสถิติใช้ tabular-nums
- สี: สีหลักโรงพยาบาลคือเขียว (#0D7446) สำหรับปุ่มหลักและสถานะเลือก พื้นหลังโทนสว่างสบายตา (#FAFCFB)
- 1 สี = 1 ความหมาย: สีสถานะอื่นใช้พื้นอ่อน + ตัวอักษรเข้มคอนทราสต์ >= 4.5:1
- ต้องคงไว้: [ระบุข้อมูลหรือฟิลด์ที่ห้ามตัดออก]

ข้อห้ามเด็ดขาด (No AI Slop):
- ห้ามใส่ Emoji ในข้อความหรือหัวข้อระบบเด็ดขาด
- ห้ามใส่ไอคอนตกแต่งลอยๆ ไร้หน้าที่ (อนุญาตเฉพาะไอคอนนำสายตาที่มีความหมายสากล)
- ห้าม Gradient ม่วง-น้ำเงิน, Glassmorphism, หรือเงามืดหนาทึบ
- ห้ามแถบสีหนาเตอะขอบซ้ายของการ์ด
- ห้ามบีบอัดข้อมูลจนเบียดเสียด หรือใช้ตารางแคบจนตัวหนังสือชนขอบ
- ห้ามตารางเอียงสะเปะสะปะ (ห้าม th อยู่ตรงกลางแต่ td ชิดซ้าย หรือ th ชิดซ้ายแต่ td ชิดขวา หรือข้อมูลเอียงซ้ายขวาสลับไปมาไม่ตรงหัวข้อ)
- ห้ามใส่ Eyebrow Badge / Pill Badge ลอยเหนือหัวข้อหลัก (<h1>) เด็ดขาด (เช่น การแปะก้อนแคปซูลไอคอนหมวดหมู่/กองทุนไว้บนชื่อหน้า ให้ใช้ Breadcrumb ธรรมดาหรือระบุในหัวข้อ/คำอธิบายแทน)
- ห้ามใส่ดรอปดาวน์เลือกฟิลด์ค้นหา (เช่น "ค้นหาทุกฟิลด์", "ค้นหาด้วย HN") ให้ช่องค้นหาทำงานครอบคลุมทุกมิติได้ทันทีโดยไม่ต้องคลิกเลือกฟิลด์ก่อน
- ห้ามใส่ตัวเลขลำดับ 1. 2. 3. นำหน้าชื่อโหมดแท็บเลือกช่วงเวลา (เช่น "1. กำหนดเอง", "2. เดือน") ให้ใช้ชื่อโหมดตรงไปตรงมา ("กำหนดเอง", "เดือน", "ปีงบประมาณ")
- ห้ามแสดงช่วงวันที่ในวงเล็บ (1 ต.ค. ... - 30 ก.ย. ...) ในดรอปดาวน์ปีงบประมาณ ให้แสดงเฉพาะ "ปีงบประมาณ [พ.ศ.]"
- ห้ามตัดแถบเลือกช่วงเวลาขึ้นบรรทัดใหม่บนจอเดสก์ท็อป
- ห้ามใส่ปุ่มไอคอน Copy ข้าง HN หรือเลขบัตรในเซลล์ตารางทุกบรรทัด ให้คลิกดูใน Modal หรือไฮไลต์ข้อความเอง

มาตรฐานโรงพยาบาลที่ต้องปฏิบัติตาม:
- วันที่ต้องแสดงเป็น ปี พ.ศ. ไทย เสมอ (เช่น "12 ต.ค. 2569")
- ข้อมูลระบุตัวตน (เลขบัตรประชาชน / HN) ต้อง Mask เหลือเพียง 4 หลักท้าย
- มีสถานะครอบคลุม: ว่าง (Empty State พร้อมแนะนำทางไปต่ออย่างอบอุ่น), กำลังโหลด (Skeleton พอดีกล่อง), และข้อผิดพลาด

ผลลัพธ์ที่ต้องการส่งมอบ:
1. ต้นแบบหน้าจอที่ทดสอบคลิกได้จริง (Interactive Prototype)
2. เอกสาร Design Spec (.md) สรุปปัญหาเดิม/วิธีแก้, โครงสร้าง, ระยะห่าง Spacing, สี, Responsive, Accessibility, และฟิลด์ API
3. หมายเหตุแจ้งอย่างตรงไปตรงมาว่าจุดไหนเป็น Placeholder หรือยังไม่ได้ต่อระบบจริง
```

## 2. ส่วนเสริม: ขอเพิ่มมิติและความมีชีวิตชีวา (ไม่ดูแห้งแล้งหรือแข็งทื่อ)

```text
ตอนนี้หน้านี้ดูเรียบแบนและแห้งแล้งเกินไป อยากให้เพิ่มความ Modern และมิติที่น่าใช้งานขึ้น แต่ยังคงความสะอาดและเป็นมิตรกับผู้ใช้งานทั่วไป

เป้าหมาย:
1. ใช้เงานุ่มละมุนตา (Soft Tactile Elevation) ด้วย var(--shadow-card) และมุมโค้งมนสบายตา (Radius 12-16px)
2. มีไอคอนนำสายตา (Visual Anchors) ประกอบหัวข้อหรือช่องข้อมูลสำคัญ เพื่อให้ผู้สูงอายุและคนทั่วไปกวาดตาเห็นได้ทันที
3. เพิ่มแถบสรุปสถานะที่มีระยะห่างโปร่งสบาย (Spacious Metric Cards) แยกสีสื่อความหมายชัดเจน:
   - สำเร็จ / ปกติ -> โทนเขียวอ่อน (var(--success-*))
   - รอดำเนินการ / รอตรวจ -> โทนเหลืองอำพันอ่อน (var(--warning-*))
   - เสี่ยง / ปฏิเสธ -> โทนแดงชมพูอ่อน (var(--danger-*))
4. รับประกันว่าตัวอักษรทุกจุดคอนทราสต์ >= 4.5:1 และมีพื้นที่หายใจ (Breathing Room) อย่างกว้างขวาง
```

## 3. ตารางอธิบายเบื้องหลังข้อความใน Prompt

| ข้อความใน Prompt | สิ่งที่ช่วยแก้ปัญหาและป้องกัน |
|---|---|
| กำชับเรื่อง Breathing Room & ไม่บีบอัด | ป้องกันไม่ให้ AI สร้างหน้าจอที่อัดแน่นจนคนใช้งานอึดอัดและตาล้า |
| เน้นย้ำ Non-Tech & Elderly Friendly UX | ป้องกันไม่ให้ดีไซน์เนอร์ใส่ interaction ซับซ้อน หรือปุ่มเล็กจนคนทั่วไปกดไม่ถูก |
| Affordance ชัดเจน & ไอคอนนำสายตา | ช่วยให้ผู้ใช้สแกนหน้าจอและรู้ทันทีว่าตรงไหนคลิกได้ โดยไม่ต้องอ่านทุกตัวอักษร |
| รายการข้อห้าม (No AI Slop) | ตัดดีไซน์สำเร็จรูปที่ไม่เข้ากับโรงพยาบาล (Emoji, Gradient แฟนซี) |
| 1 สี = 1 ความหมาย | ป้องกันสีสับสน และช่วยให้ผู้ใช้รับรู้ความเร่งด่วนได้ถูกต้อง |
| กำชับปี พ.ศ. ไทย และ PHI Masking | ป้องกันการละเมิดมาตรฐานข้อมูลโรงพยาบาลและกฎหมาย PDPA |
