# เทมเพลต Brief สำหรับสั่ง AI ออกแบบ UI (Mode B)

ใช้กรอกข้อมูลบริบทจริงของระบบโรงพยาบาลเถินก่อนส่งให้ AI ห้ามส่งเทมเพลตเปล่า

---

## 1. ข้อความ Prompt หลักสำหรับส่งให้ AI

```text
ช่วยออกแบบหน้า [ระบุชื่อหน้า เช่น รายการยืม-คืนอุปกรณ์] ใหม่ (แนบภาพหน้าเดิมหรือโครงสร้างเดิม)

บริบทระบบ:
- หน้าที่การทำงาน: [ระบุหน้าที่ เช่น ติดตามสถานะคำขอยืมอุปกรณ์และอนุมัติ]
- ผู้ใช้งานหลัก: [เช่น บุคลากรโรงพยาบาล / เจ้าหน้าที่พัสดุ] เข้าใช้งานผ่านคอมพิวเตอร์และมือถือ PWA
- เทคโนโลยี: Next.js 16 (App Router), React 19, CSS Modules (ใช้ตัวแปร CSS จาก globals.css), เชื่อมต่อผ่าน API Gateway

ปัญหาของหน้าเดิมที่ต้องแก้ (ระบุชัดเจน):
1. [เช่น ข้อมูลในตารางล้นจอเมื่อเปิดบนมือถือ]
2. [เช่น สีปุ่มสับสน การกระทำหลักไม่เด่นชัด]

แนวทางดีไซน์ที่ต้องการ:
- โทน: ทันสมัย สะอาด สบายตา เป็นระเบียบ (Modern Hospital Interface)
- ฟอนต์: Sarabun, ตัวเลขในตารางใช้ tabular-nums
- สี: สีหลักโรงพยาบาลคือเขียว (#0D7446) สำหรับปุ่มหลักและสถานะเลือก พื้นหลังโทนสว่าง (#FAFCFB)
- 1 สี = 1 ความหมาย: สีสถานะอื่นใช้พื้นอ่อน + ตัวอักษรเข้มคอนทราสต์ >= 4.5:1
- ต้องคงไว้: [ระบุข้อมูลหรือฟิลด์ที่ห้ามตัดออก]

ข้อห้ามเด็ดขาด (No AI Slop):
- ห้ามใส่ Emoji ในข้อความหรือหัวข้อระบบเด็ดขาด
- ห้ามใส่ไอคอนตกแต่ง (อนุญาตเฉพาะไอคอนฟังก์ชันที่จำเป็นเท่านั้น)
- ห้าม Gradient ม่วง-น้ำเงิน, Glassmorphism, หรือเงามืดหนาทึบ
- ห้ามขอบสีด้านซ้ายของการ์ด
- ห้ามป้ายสีบอกสถานะซ้ำกันทุกบรรทัด (ให้ย้ายไปกรองที่หัวตาราง)
- ห้ามตัดทอนชื่อด้วย "..." จนอ่านไม่รู้เรื่อง (ให้ขึ้นบรรทัดใหม่)

มาตรฐานโรงพยาบาลที่ต้องปฏิบัติตาม:
- วันที่ต้องแสดงเป็น ปี พ.ศ. ไทย เสมอ (เช่น "12 ต.ค. 2569")
- ข้อมูลระบุตัวตน (เลขบัตรประชาชน / HN) ต้อง Mask เหลือเพียง 4 หลักท้าย
- ปุ่มและพื้นที่กด (Touch Target) บนมือถือต้องสูง >= 44px
- รองรับกรณีข้อมูลว่าง (Empty State), กำลังโหลด (Skeleton), และข้อผิดพลาด

ผลลัพธ์ที่ต้องการส่งมอบ:
1. ต้นแบบหน้าจอที่ทดสอบคลิกได้จริง (Interactive Prototype)
2. เอกสาร Design Spec (.md) สรุปปัญหาเดิม/วิธีแก้, โครงสร้าง, สี, Responsive, Accessibility, และฟิลด์ API
3. หมายเหตุแจ้งอย่างตรงไปตรงมาว่าจุดไหนเป็น Placeholder หรือยังไม่ได้ต่อระบบจริง
```

## 2. ส่วนเสริม: ขอเพิ่มสีสันให้มีมิติ (ไม่ดูแบนเป็นตัวหนังสือล้วน)

```text
ตอนนี้หน้านี้ดูเรียบเป็นตัวหนังสือล้วนจนแยกประเภทข้อมูลยาก ช่วยเพิ่มสีสันที่สื่อความหมาย (Semantic Colors)

เป้าหมาย: ช่วยให้เจ้าหน้าที่มองแวบเดียว (Scannability) แล้วแยกประเภท/ระดับความเร่งด่วนได้ทันที

ประเภทข้อมูลที่ต้องการแยกด้วยสี:
- [ประเภทที่ 1: เช่น อนุมัติแล้ว / ปกติ] -> ใช้โทนเขียวอ่อน
- [ประเภทที่ 2: เช่น รอตรวจสอบ] -> ใช้โทนเหลืองอำพันอ่อน
- [ประเภทที่ 3: เช่น ยกเลิก / มีความเสี่ยง] -> ใช้โทนชมพูแดงอ่อน

กติกา:
- 1 สี = 1 ความหมาย ห้ามใช้สีตกแต่งสุ่ม
- พื้นสีอ่อน + ตัวอักษรเข้มโทนเดียวกัน คอนทราสต์ >= 4.5:1 และมีข้อความระบุความหมายกำกับเสมอ
- มีแถบสรุปยอดตัวเลขเป็นช่องสีชัดเจนด้านบน
- ส่งมอบตารางรหัสสีที่ใช้พร้อมเหตุผล และอัปเดตไฟล์ Design Spec .md
```

---

## 3. ตารางอธิบายเบื้องหลังข้อความใน Prompt

| ข้อความใน Prompt | สิ่งที่ช่วยป้องกัน |
|---|---|
| ระบุปัญหาเป็นข้อๆ ที่ตรวจได้ | ป้องกันไม่ให้ AI เปลี่ยนแค่สี แต่ไม่แก้ปัญหาโครงสร้างจริง |
| รายการข้อห้าม (No AI Slop) | ตัดดีไซน์สำเร็จรูปที่ AI มักชอบแต่งเติมเอง (Emoji, Gradient, Glow) |
| 1 สี = 1 ความหมาย | ป้องกันไม่ให้เกิดสีสับสนที่ผู้ใช้งานต้องเดา |
| กำชับปี พ.ศ. ไทย และ PHI Masking | ป้องกันการละเมิดมาตรฐานข้อมูลโรงพยาบาลและกฎหมาย PDPA |
| ขอตาราง Design Spec คู่ต้นแบบ | ช่วยให้โปรแกรมเมอร์นำสเปกไปเขียนโค้ดต่อได้ทันทีโดยไม่ตกหล่น |
