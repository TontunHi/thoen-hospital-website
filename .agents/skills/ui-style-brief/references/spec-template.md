# โครงร่าง Design Spec ที่ต้องส่งมอบ (Spec Template)

ตั้งชื่อไฟล์: `<ชื่อหน้า>-design-spec.md` ใช้ภาษาไทยและเน้นตารางสรุปที่กระชับ

---

```markdown
# Design Spec: <ชื่อหน้า / ระบบ>

- **Path:** `<เส้นทางหน้า เช่น /member/events>`
- **กลุ่มผู้ใช้งาน:** <ผู้ป่วยทั่วไป / ผู้สูงอายุ / พยาบาล / บุคลากรทั่วไป / แอดมิน>
- **สไตล์หลัก:** Modern & Welcoming Hospital Interface (โปร่ง สบายตา เป็นมิตรต่อคนไม่เก่งไอที)
- **Design Tokens:** อิงตาม `src/app/globals.css` (สีหลัก `--primary: #0D7446`, Sarabun)

---

## 1. ปัญหาของหน้าเดิม และสิ่งที่แก้ไข
| # | ปัญหาเดิมที่พบ | สิ่งที่ได้รับการปรับปรุงในเวอร์ชันใหม่ |
|---|---|---|
| 1 | <เช่น ข้อมูลอัดแน่น แถวตารางเตี้ยและแคบจนตาล้า> | <ขยายแถวตารางเป็น 54px เพิ่ม Card padding 24px สร้าง Breathing Room> |
| 2 | <เช่น ผู้สูงอายุกดปุ่มผิดบ่อย ดูไม่ออกว่าอะไรกดได้> | <เพิ่ม Affordance ชัดเจน, ขยายพื้นที่สัมผัสเป็น 48px, เพิ่มไอคอนนำสายตา> |

---

## 2. โครงสร้างหน้าและระยะห่าง (Layout & Breathing Room)
| ลำดับ | ส่วนประกอบ | รายละเอียดการจัดวาง & Spacing |
|---|---|---|
| 1 | ลิงก์กลับ | `← กลับ...` พร้อมลูกศร สูง ≥ 44px เว้นระยะล่าง 12px |
| 2 | ส่วนหัว (Header) | ชื่อหน้า H1 + คำอธิบายบทบาทเป็นมิตร + ปุ่ม Action หลัก |
| 3 | บล็อกสถิติ (Metrics) | การ์ดสรุปยอดสถานะแบบโปร่ง (`gap: 16px`, padding 20px) |
| 4 | แถบเครื่องมือ (Toolbar) | แท็บคัดกรอง + ช่องค้นหา Live พร้อมไอคอนแว่นขยาย (`gap: 16px`) |
| 5 | เนื้อหาหลัก (Content) | ตารางข้อมูลแถวโปร่ง หรือ การ์ดรายการรายบุคคล (Section Gap: 24-32px) |

---

## 3. มิติความโปร่งสบายและมาตราส่วนระยะห่าง (Spacing Specs)
| จุดที่ใช้งาน | ขนาดที่กำหนด | วัตถุประสงค์ |
|---|---|---|
| **Card Padding** | `24px` (มือถือ `16px`) | เว้นขอบให้เนื้อหาดูไม่อึดอัด |
| **Table Row Height** | `52px - 56px` | แถวตารางสูงพอดี สบายตาต่อผู้ใช้ทั่วไป |
| **Section Gap** | `24px - 32px` | ให้พื้นที่สายตาได้พักระหว่างบล็อกข้อมูล |
| **Touch Target** | `min-height: 44px - 48px` | ป้องกันการกดพลาดบนมือถือและจอสัมผัส |

---

## 4. กติกาการแสดงผลและเพื่อผู้ใช้ทั่วไป (Non-Tech Friendly Rules)
| หัวข้อ | กติกาที่กำหนด |
|---|---|
| **Affordance & ปุ่ม** | ปุ่มหลักมีขอบเขตและเงา `--shadow-card` ชัดเจน คลิกได้แน่นอน |
| **คำแนะนำกำกับ (Microcopy)** | มี Helper Text แนะนำตัวอย่างใต้ช่องกรอก (ไร้ศัพท์เทคนิค) |
| **การจัดแนวข้อมูลในตาราง** | **แสดงตรงกลางของหัวข้อ (`center`) เสมอ** สำหรับคอลัมน์ลำดับ, วันที่, เวลา, รหัส/HN, ป้ายสถานะ Badge, จำนวนนับ, ปุ่ม Action (โดย `th` และ `td` ต้องมี alignment ตรงกัน 100% ไม่เอียงริมซ้ายริมขวาสะเปะสะปะ) |
| **การแสดงวันที่** | ใช้ **ปี พ.ศ. ไทย** เสมอ (เช่น "12 ต.ค. 2569") |
| **การปกป้องข้อมูล (PHI)** | Mask เลขบัตรประชาชนและ HN แสดงเฉพาะ 4 หลักท้าย |
| **สถานะว่าง (Empty)** | แสดงข้อความอธิบายอบอุ่น พร้อมปุ่มเริ่มต้นใช้งาน |
| **ไอคอนนำสายตา** | ใช้ไอคอนมาตรฐาน (เช่น ปฏิทิน, นาฬิกา, เบอร์โทร) ชี้แนะข้อมูล |

---

## 5. โทนสีและสถานะที่ใช้งาน (Semantic Colors)
| สถานะ / ข้อมูล | CSS Variable | ค่าสีพื้น / ตัวอักษร | วัตถุประสงค์การใช้ |
|---|---|---|---|
| สีหลัก | `var(--primary)` | `#0D7446` / ขาว | ปุ่มหลักของหน้า, แท็บที่เลือก |
| รออนุมัติ / รอตรวจ | `var(--warning-*)` | `#FEF3C7` / `#B45309` | รายการที่ต้องรอเจ้าหน้าที่ตรวจสอบ |
| ยกเลิก / ปฏิเสธ | `var(--danger-*)` | `#FEE2E2` / `#B91C1C` | รายการที่ไม่ผ่านการอนุมัติ |
| เสร็จสิ้น / สำเร็จ | `var(--success-*)` | `#DCFCE7` / `#15803D` | งานที่ให้บริการเรียบร้อยแล้ว |

---

## 6. การตอบสนองบนอุปกรณ์ (Responsive Design)
| ขนาดหน้าจอ | พฤติกรรมการแสดงผล |
|---|---|
| **หน้าจอคอมพิวเตอร์ (≥ 1024px)** | แสดงตารางข้อมูลแบบโปร่งสบายตา คอลัมน์กว้างขวาง |
| **แท็บเล็ต / จอขนาดกลาง (768px - 1023px)** | ตารางมี `overflow-x: auto` มีเงาระบุขอบเขตเลื่อน |
| **มือถือ (< 768px)** | แปลงตารางเป็นการ์ดรายการโปร่งๆ (Card View), ปุ่มสูง ≥ 48px |

---

## 7. ข้อมูลที่ต้องใช้จาก API Gateway
| ฟิลด์ข้อมูล | แหล่งที่มา / วิธีใช้ |
|---|---|
| `id` | รหัสอ้างอิงของรายการ |
| `status` | รหัสสถานะสำหรับกำหนดสีป้าย Badge |
| `thaiDate` | วันที่จัดรูปแบบ พ.ศ. มาจากระบบ |

---

## 8. สิ่งที่ตัดออกจากหน้าเดิม (Smart Subtraction)
| สิ่งที่ตัดออก | เหตุผลที่ตัด |
|---|---|
| <เช่น ไอคอนตกแต่งลอยๆ ไร้ความหมาย> | <ตัดสิ่งรบกวนสายตา ช่วยให้คนทั่วไปโฟกัสเนื้องาน> |
| <เช่น การบีบอัดข้อมูลจนตารางเตี้ย> | <ขยายระยะห่างเพื่อให้สายตาผู้สูงอายุอ่านง่าย> |

---

## 9. หมายเหตุเกี่ยวกับต้นแบบ (Prototype Notes)
| เรื่อง | รายละเอียด |
|---|---|
| **ข้อมูลจำลอง (Placeholders)** | <ระบุข้อมูลที่ยังไม่ใช่ข้อมูลจริงจากฐานข้อมูล> |
| **ฟังก์ชันที่ยังไม่ได้เชื่อมต่อจริง** | <ระบุปุ่มหรือฟังก์ชันที่ยังเป็น Mockup หน้าบ้าน> |
```
