# เช็กลิสต์ตรวจสอบ UI ก่อนส่งมอบ (Review Checklist)

ใช้ตรวจสอบก่อนส่งมอบผลงานทั้ง 3 โหมด (ต้นแบบ, Brief, และการ Refactor โค้ดจริง)

---

## 1. ดักจับ AI Slop (ต้องไม่มี ❌)

| สิ่งที่ต้องตรวจ | เกณฑ์ผ่าน |
|---|---|
| **Emoji ใน UI** | ไม่มี Emoji ปนในหัวข้อ, เมนู หรือข้อความระบบ (เช่น "ยินดีต้อนรับ 👋") |
| **ไอคอนตกแต่ง** | ไม่มีไอคอนใส่ประดับหน้าการ์ดหรือทุกแถวโดยไม่มีฟังก์ชันคลิก |
| **สไตล์ลอยตัว / Gradient แฟนซี** | ไม่มี Gradient ม่วง-น้ำเงิน, Glassmorphism ฟุ้งๆ, หรือแสง Glow แปลกปลอม |
| **ขอบสีด้านซ้ายของการ์ด** | ไม่ใช้แถบสีขอบซ้ายของการ์ดเพื่อบอกสถานะ (ให้ใช้ป้าย Badge ภายในที่ชัดเจนแทน) |
| **การ์ดสถิติแยกกระจัดกระจาย** | ข้อมูลสรุปต้องรวมเป็นแถบสถิติเดียวอย่างเป็นระเบียบ ไม่แยกเป็นการ์ดเล็กๆ 4-5 ใบโดยไม่จำเป็น |
| **ป้ายสีซ้ำซ้อนทุกแถว** | ไม่แสดงป้ายสถานะเดิมซ้ำทุกบรรทัดในตาราง (ให้กรองที่หัวตารางแทน) |
| **ข้อความหลอก (Lorem Ipsum)** | ข้อมูลตัวอย่างต้องมีโครงสร้างเสมือนจริงและติดป้าย Placeholder ชัดเจน |

## 2. มาตรฐานระบบโรงพยาบาล (Hospital Standards ✔)

| ข้อกำหนด | เกณฑ์ผ่าน |
|---|---|
| **ปี พ.ศ. ไทย** | วันที่ทุกจุดต้องแสดงเป็นปีพุทธศักราช (พ.ศ.) เช่น "24 ต.ค. 2569" ห้ามปน ค.ศ. ในหน้าบุคลากร/คนไข้ |
| **การปกป้องข้อมูลสุขภาพ (PHI Masking)** | เลขประจำตัวประชาชน และ HN ต้องแสดงเฉพาะ **4 ตัวท้าย** (เช่น `x-xxxx-xxxxx-xx-1` หรือ `•••1234`) |
| **ความคมชัดและอ่านง่าย (Accessibility)** | คอนทราสต์ตัวอักษรทุกคู่สี ≥ **4.5:1** (รวมถึงตัวอักษรบนป้ายสถานะพื้นอ่อน) |
| **ขนาดตัวอักษร** | ไม่มีตัวอักษรขนาดต่ำกว่า 12px (ข้อความทั่วไป ≥ 14-16px, ป้ายกำกับ ≥ 13px) |
| **เป้าสัมผัสบนมือถือ** | ปุ่มและตัวเลือกแบบฟอร์มต้องมีพื้นที่กด ≥ **44px** |
| **ตัวเลขในตาราง** | ใช้ `font-variant-numeric: tabular-nums` เพื่อให้หลักเลขตรงกันเสมอ |

## 3. ความสมบูรณ์ของการใช้งาน (Usability & Edge Cases ✔)

| กรณีทดสอบ | เกณฑ์ผ่าน |
|---|---|
| **One Primary Action** | ในแต่ละแถวหรือหน้าจอ มีปุ่มหลัก (Primary Button) เด่นชัดเพียง 1 ปุ่ม |
| **รองรับข้อความยาว** | ชื่อ-นามสกุล หรือชื่อหน่วยงานยาว ไม่ถูกตัดหายหรือล้นทะลุกล่อง (ใช้ `overflow-wrap: break-word`) |
| **สถานะว่าง (Empty State)** | มีหน้าจอ/ข้อความอธิบายเมื่อไม่มีข้อมูล พร้อมแนะนำขั้นตอนถัดไป |
| **สถานะกำลังโหลด (Loading State)** | ใช้ Skeleton โครงสร้างเทาขนาดเท่าของจริง ไม่ใช้ Spinner ขนาดใหญ่หมุนค้าง |
| **สถานะข้อผิดพลาด (Error State)** | มีข้อความแจ้งปัญหาที่ผู้ใช้เข้าใจได้ และมีปุ่ม "ลองใหม่อีกครั้ง" |
| **ตารางบนมือถือ** | ตารางกว้างมีกล่อง `overflow-x: auto` เลื่อนได้อิสระ โดยไม่ทำให้โครงสร้างหน้าหลักแตก |
| **การกระทำที่มีความเสี่ยง** | การยกเลิก/ลบ/ถอนสิทธิ์ มี Modal หรือการยืนยันผลกระทบชัดเจน และพร้อมรองรับ Audit Log |

## 4. ความซื่อสัตย์ของการส่งมอบ (Honesty)

| หัวข้อ | เกณฑ์ผ่าน |
|---|---|
| **ระบุ Placeholder ชัดเจน** | จุดไหนที่ยังไม่มีข้อมูลจริงให้แจ้งผู้ใช้อย่างตรงไปตรงมา |
| **ระบุขอบเขตของต้นแบบ** | สิ่งที่ทำงานเฉพาะหน้าบ้าน (Local state) กับสิ่งที่ต้องต่อ API Gateway จริง ระบุแยกกันชัดเจน |
