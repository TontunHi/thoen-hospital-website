# เช็กลิสต์ตรวจสอบ UI ก่อนส่งมอบ (Review Checklist)

ใช้ตรวจสอบก่อนส่งมอบผลงานทั้ง 3 โหมด (ต้นแบบ, Brief, และการ Refactor โค้ดจริง)
เพื่อให้มั่นใจว่าทันสมัย สบายตา เป็นมิตรกับผู้ใช้ทั่วไป และไม่บีบอัดพื้นที่

---

## 1. ดักจับ AI Slop (ต้องไม่มี ❌)

| สิ่งที่ต้องตรวจ | เกณฑ์ผ่าน |
|---|---|
| **Emoji ใน UI** | ไม่มี Emoji ปนในหัวข้อ, เมนู หรือข้อความระบบทางการ (เช่น "ยินดีต้อนรับ 👋") |
| **ไอคอนประดับลอยๆ** | ไม่มีไอคอนใส่เป็นเครื่องประดับเปล่าๆ ทุกไอคอนต้องมีหน้าที่นำสายตาหรือมีฟังก์ชันคลิก |
| **สไตล์ลอยตัว / แฟนซี** | ไม่มี Gradient ม่วง-น้ำเงิน, Glassmorphism ฟุ้งๆ, หรือแสง Glow แปลกปลอม |
| **ขอบสีซ้ายการ์ดแข็งทื่อ** | ไม่ใช้แถบขอบสีหนาเตอะทางซ้ายของการ์ดเพื่อบอกสถานะ (ใช้ Badge แคปซูลมนภายในแทน) |
| **ความบีบอัดจนอึดอัด** | **ไม่มีการอัดข้อมูลจนเบียดเสียด** แถวตารางเตี้ยแคบ หรือ Padding ชิดขอบกล่องจนล้นตา |
| **ตารางเอียงสะเปะสะปะ (Ragged Alignment)** | **ไม่มีตารางที่หัวข้อกับข้อมูลจัดแนวไม่ตรงกัน** (เช่น `<th>` จัดกึ่งกลางแต่ `<td>` ชิดซ้าย, หรือ `<th>` ชิดซ้ายแต่ `<td>` ลอยไปริมขวา, หรือข้อมูลในคอลัมน์เดียวกันเอียงซ้ายขวาสลับไปมา) |
| **Eyebrow / Title Badge ลอยเหนือหัวข้อ** | **ไม่มี Badge แคปซูลมนๆ หรือ Chip ลอยแปะไว้เหนือ `<h1>`** (เช่น `[ Activity กองทุน 14 • บริการ... ]`) ส่วนหัวต้องสะอาดตา ขึ้น `<h1>` ชัดเจน หรือใช้ Breadcrumb ข้อความเรียบง่าย |
| **ตัวเลขลำดับข้อนำหน้าชื่อเมนูหรือชื่อเรื่อง** | **ไม่มีตัวเลขลำดับ `1.`, `2.`, `3.` นำหน้าชื่อเมนูใน Sidebar, หัวเรื่อง `<h1>`, Title, หรือ Breadcrumb** (เช่น "2. รายชื่อผู้รับบริการ") ให้ใช้ชื่อรายงานตรงไปตรงมา และใช้ Badge ชิปแยกหากต้องแสดงรหัสข้อ |
| **เลขลำดับหน้าแท็บเลือกช่วงเวลา** | **ไม่มีตัวเลขลำดับ `1. 2. 3.` นำหน้าชื่อโหมดแท็บ** (เช่น "1. กำหนดเอง", "2. เดือน") ให้ใช้ชื่อโหมดตรงไปตรงมา |
| **ช่วงวันที่รกในดรอปดาวน์ปีงบประมาณ** | **ไม่มีช่วงวันที่ในวงเล็บ `(1 ต.ค. ... - 30 ก.ย. ...)`** ต่อท้ายชื่อปีงบประมาณ แสดงเฉพาะ "ปีงบประมาณ [พ.ศ.]" |
| **แถบเลือกวันที่ตัดขึ้นบรรทัดใหม่** | **ไม่แยกแท็บสลับโหมดกับตัวเลือกวันที่เป็น 2 แถวบนจอเดสก์ท็อป** ต้องจัดอยู่ในแถวเดียวกันบรรทัดเดียว |
| **การ์ดสรุปสถิติแถวแหว่งหรือไม่เท่ากัน** | **ไม่ปล่อยให้แถวบนและแถวล่างมีจำนวนการ์ดไม่เท่ากัน** (เช่น บน 5 ล่าง 3) ต้องจัดแถวละเท่ากันอย่างสมมาตร |
| **ปุ่มคัดลอกในเซลล์ตาราง** | **ไม่มีปุ่มไอคอน Copy วางซ้ำๆ ทุกแถว** ข้าง HN หรือเลขบัตรในตาราง ให้คลิกดูใน Modal หรือไฮไลต์ข้อความเอง |
| **ดรอปดาวน์เลือกฟิลด์ค้นหาที่ซ้ำซ้อน** | **ไม่มีดรอปดาวน์เลือกฟิลด์ค้นหา** (เช่น "ค้นหาทุกฟิลด์", "ค้นหาด้วย HN") ช่องค้นหาต้องรองรับการพิมพ์ค้นหาทุกมิติได้พร้อมกันในช่องเดียว |
| **ชื่อ-สกุลถูกตัดพยางค์กลางคำ** | **ไม่มีชื่อหรือนามสกุลที่ถูกเบราว์เซอร์ตัดแบ่งพยางค์กลางคำ** ต้องแสดงในบรรทัดเดียวกันเป็นหลัก และหากพื้นที่ไม่พอต้องยกไปทั้งนามสกุล |
| **คำว่า "ปี" หล่นไปอยู่อีกบรรทัด** | **ไม่มีตัวเลขอายุที่แยกบรรทัดกับคำว่า "ปี"** ต้องแสดงในบรรทัดเดียวกันเสมอ (เช่น `18 ปี`) |
| **ข้อมูลชดเชยเอียงไม่ตรงกลางหัวข้อ** | **ไม่มีคอลัมน์ "ชดเชย (บาท)" ที่จัดแนวเอียงซ้ายหรือขวา** ต้องจัดตรงกลางหัวข้อ (`col-center` ทั้ง `<th>` และ `<td>`) |
| **ไอคอน Sort หล่นไปอยู่อีกบรรทัด** | **ไม่มีไอคอน Sort หัวตารางที่หล่นไปอยู่อีกบรรทัดใต้ชื่อหัวข้อ** ต้องแสดงเคียงข้างกันในบรรทัดเดียวเสมอ (`inline-flex` + `white-space: nowrap;`) |
| **ข้อความหลอก (Lorem Ipsum)** | ข้อมูลตัวอย่างต้องมีโครงสร้างเสมือนจริงในบริบทโรงพยาบาลและติดป้าย Placeholder ชัดเจน |

## 2. ความโปร่งสบายและระยะหายใจ (Breathing Room & Anti-Cramping ✔)

| หัวข้อตรวจสอบ | เกณฑ์ผ่าน |
|---|---|
| **ระยะห่างภายในการ์ด (Card Padding)** | ไม่ต่ำกว่า **20px - 24px** บนคอมฯ และไม่ต่ำกว่า **16px** บนมือถือ |
| **ความสูงแถวตาราง (Table Row Height)** | สูงอย่างน้อย **52px - 56px** เซลล์มี padding ซ้าย-ขวา ≥ 16px ตัวหนังสือไม่ชนขอบ |
| **แถบเลือกช่วงเวลาในแถวเดียว (Single-Row Date Selector)** | กลุ่มแท็บสลับโหมดและตัวเลือกวันที่จัดวางใน**แถวเดียวกันในบรรทัดเดียว** มีเส้นคั่นบางแนวตั้งคั่นกลาง ไม่ตัดขึ้นบรรทัดใหม่ |
| **การ์ดสรุป KPI สมมาตรแถวละเท่ากัน (Equal KPI Grid)** | แสดงการ์ดแถวละเท่าๆ กันเสมอ เช่น **4 คอลัมน์ x 2 แถว (`repeat(4, 1fr)`)** ทุกใบกว้างและสูงสมดุลเท่ากัน |
| **กดดูข้อมูลผ่าน Record โดยตรง (Row-Clickable Records)** | แถวตาราง (`<tr>`) สามารถคลิกเปิดดูรายละเอียดได้โดยตรง (`cursor: pointer`, hover feedback ชัดเจน) ไม่ต้องเพิ่มคอลัมน์ปุ่มเปิดดูซ้ำซ้อน |
| **การจัดแนวตาราง (Table Alignment Harmony)** | **ข้อมูลในเซลล์ (`<td>`) ต้องแสดงตรงกลางของหัวข้อ (`<th>`)** สำหรับคอลัมน์ลำดับ, วันที่, เวลา, รหัส/HN, เลขบัตรประชาชน, ชื่อ-สกุลผู้ป่วย (จัดตรงกลางในแนวนอนแกน X), ป้ายสถานะ Badge, จำนวนนับ, ข้อมูลชดเชย (บาท), และปุ่ม Action โดย `<th>` และ `<td>` มี alignment สอดคล้องกัน 100% |
| **ชื่อ-สกุลผู้ป่วยจัดตรงกลางในแนวนอนแกน X และยกไปทั้งนามสกุล (Centered Patient Name & Wrap)** | ข้อมูลชื่อ-สกุลผู้ป่วยจัด**ตรงกลางในแนวนอนแกน X (`col-center`, `text-align: center`)** ทั้งหัวตารางและเซลล์ข้อมูล โดยแสดงใน**บรรทัดเดียวกันเป็นหลัก** และหากพื้นที่ไม่พอจะ**ยกไปทั้งนามสกุล** (`inline-block` + `white-space: nowrap`) ไม่ตัดคำกลางพยางค์ |
| **ข้อมูลอายุและหน่วย (Age Cohesion)** | ข้อมูลอายุและหน่วย "ปี" แสดงใน**บรรทัดเดียวกันเสมอ** (เช่น `18 ปี`) ไม่ตัดคำว่า "ปี" ตกไปอีกบรรทัด |
| **ไอคอน Sort หัวตารางในบรรทัดเดียว (Sort Icon Inline Cohesion)** | ข้อความชื่อหัวข้อและไอคอน Sort แสดงเคียงคู่กันใน**บรรทัดเดียวกันเสมอ** ไม่แตกแถวตกไปอีกบรรทัด (`display: inline-flex; align-items: center; gap: 4px; white-space: nowrap;`) พร้อมความกว้างคอลัมน์ที่รองรับพอเหมาะ |
| **ระยะห่างระหว่างหมวด (Section Gap)** | มีช่องว่างระหว่างบล็อกเนื้อหาอย่างน้อย **24px - 32px** ให้สายตาได้พัก |
| **การจัดกลุ่มข้อมูล (Chunking)** | ข้อมูลเยอะถูกแบ่งเป็นสัดส่วน มี Hierarchy ชัดเจน ไม่เทรวมเป็นก้อนทึบ |
| **ระยะบรรทัดภาษาไทย** | `line-height` อยู่ในช่วง **1.6 - 1.7** สระบน-ล่างไม่เบียดชนกัน |

## 3. ความเป็นมิตรต่อผู้ใช้ทั่วไปและผู้สูงอายุ (Non-Tech & Elderly Friendly ✔)

| หัวข้อตรวจสอบ | เกณฑ์ผ่าน |
|---|---|
| **Affordance ชัดเจน** | ปุ่มดูออกทันทีว่าเป็นปุ่ม (มีมิติ ขอบเขต หรือพื้นหลังชัดเจน) อะไรกดได้ต้องสื่อชัด |
| **ภาษาเข้าใจง่าย (No Jargon)** | ไม่ใช้ศัพท์เทคนิคไอที ใช้ภาษาไทยสุภาพ เป็นมิตร อธิบายเข้าใจทันที |
| **ขนาดตัวอักษรและเป้าสัมผัส** | ตัวอักษรทั่วไป ≥ **16px**, คำอธิบายย่อย ≥ **13px**, ปุ่มและพื้นที่กด ≥ **44-48px** |
| **ลดความวิตกกังวล (Reassurance)** | มีหน้าต่างยืนยันก่อนลบ/ยกเลิก พร้อมข้อความอธิบายผลกระทบชัดเจน ไม่ใช้คำขู่ |
| **สถานะว่างและโหลดที่อบอุ่น** | Empty State และ Skeleton ให้ความรู้สึกเป็นมิตร มีทางไปต่อชัดเจน |

## 4. มาตรฐานระบบโรงพยาบาล (Hospital Standards ✔)

| ข้อกำหนด | เกณฑ์ผ่าน |
|---|---|
| **ปี พ.ศ. ไทย** | วันที่ทุกจุดต้องแสดงเป็นปีพุทธศักราช (พ.ศ.) เช่น "24 ต.ค. 2569" ห้ามปน ค.ศ. |
| **การปกป้องข้อมูลสุขภาพ (PHI Masking)** | เลขประจำตัวประชาชน และ HN ต้องแสดงเฉพาะ **4 ตัวท้าย** (เช่น `x-xxxx-xxxxx-xx-1` หรือ `•••1234`) |
| **ความคมชัดและอ่านง่าย (Accessibility)** | คอนทราสต์ตัวอักษรทุกคู่สี ≥ **4.5:1** (ระดับ AA) |
| **ตัวเลขในตาราง** | ใช้ `font-variant-numeric: tabular-nums` เพื่อให้หลักเลขตรงกันเสมอ |
| **การบันทึก Audit Log** | การกระทำสำคัญ (เปลี่ยนสถานะ, แก้ไขข้อมูล) พร้อมเชื่อมโยงกับ Audit Log |

## 5. ความซื่อสัตย์ของการส่งมอบ (Honesty)

| หัวข้อ | เกณฑ์ผ่าน |
|---|---|
| **ระบุ Placeholder ชัดเจน** | แจ้งอย่างโปร่งใสว่าจุดไหนเป็นข้อมูลตัวอย่าง |
| **ระบุขอบเขตของต้นแบบ** | แยกชัดเจนระหว่างการทำงานหน้าบ้าน (Local state) กับการต่อ API Gateway จริง |
