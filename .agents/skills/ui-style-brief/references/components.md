# โครงสร้างและรูปแบบคอมโพเนนต์ (Component Guidelines)

สำหรับระบบโรงพยาบาลเถิน (Next.js 16 + CSS Modules / `page.css`)
เน้นความทันสมัย โปร่งสบายตา (Breathing Room) และใช้งานง่ายสำหรับผู้ใช้ทั่วไป (Non-Tech & Elderly Friendly)

---

## 1. ลำดับโครงสร้างหน้ามาตรฐาน (Spacious Page Layout)

| ลำดับ | ส่วนประกอบ | รายละเอียดและการจัดวางที่โปร่งสบาย |
|---|---|---|
| **1** | ลิงก์ย้อนกลับ | ข้อความ `← กลับสู่หน้ารายการ` พร้อมไอคอนลูกศร ตัวอักษรสี `var(--gray-700)` สูง ≥ 44px มีระยะห่างด้านล่าง `var(--space-3)` |
| **2** | ส่วนหัว (Header Bar) | `<h1>` ชื่อหน้าระบบชัดเจน + คำอธิบายบทบาทสั้น 1 บรรทัด (ช่วยให้ผู้ใช้ทั่วไปเข้าใจหน้าที่ของหน้า) + **ปุ่มหลักของหน้า (ชิดขวา)** |
| **3** | บล็อกสรุปสถิติ (Overview Metrics) | แสดงสรุปภาพรวมที่เข้าใจง่าย (เช่น รอดำเนินการ, เสร็จสิ้น) ในรูปแบบ Stat Pill Bar หรือการ์ดสรุปโปร่งๆ (`gap: 16px`, padding 16-20px) **ไม่บีบอัดตัวเลขติดกัน** |
| **4** | แถบเครื่องมือ (Spacious Toolbar) | ซ้าย: แท็บกรองสถานะแบบมนสบายตา \| ขวา: ช่องค้นหาแบบ Live พร้อมไอคอนแว่นขยาย + ดรอปดาวน์คัดกรอง เว้นระยะห่าง `gap: 16px` |
| **5** | เนื้อหาหลัก (Main Content) | ตารางข้อมูล (Table) หรือการ์ดรายการกลุ่ม (Grouped Cards) ที่มีพื้นที่ขอบสบายตา |

## 2. กติกาคอมโพเนนต์หลักเพื่อ UX ที่เป็นมิตร

| คอมโพเนนต์ | แนวทางปฏิบัติ & การจัดระยะไม่ให้บีบอัด |
|---|---|
| **ปุ่มหลัก (Primary Button)** | พื้นหลัง `var(--primary)`, ตัวอักษรขาว, สูง **44px - 48px**, รัศมีมุม `8px`, มีเงา `--shadow-card` นุ่มนวล, **มี 1 ปุ่มต่อมุมมองหลัก** พร้อมไอคอนฟังก์ชันนำสายตา (เช่น `+ สร้างนัดหมายใหม่`) |
| **ปุ่มรอง (Secondary Button)** | พื้นขาว ขอบ `var(--gray-200)` หรือพื้น `var(--primary-light)` ข้อความสีเขียวเข้ม ชัดเจนว่าคลิกได้ ไม่กลืนหายไปกับพื้นหลัง |
| **ปุ่มอันตราย (Destructive Button)** | พื้นหลัง `var(--danger-bg)` ตัวอักษร `var(--danger)` ใช้เฉพาะปุ่มลบหรือถอนสิทธิ์ และต้องเปิดโมดอลยืนยันผลเสมอ |
| **ช่องค้นหา (Search Input)** | ความสูง 44-48px มีไอคอนแว่นขยายชิดซ้าย Placeholder ภาษาไทยชัดเจน มีตัวอย่างคำค้น เช่น *"ค้นหาด้วยชื่อผู้ป่วย, HN หรือเลขบัตร..."* |
| **ตารางข้อมูล (Data Table)** | **ห้ามบีบแถวเตี้ยเด็ดขาด**: ความสูงแถวอย่างน้อย **52px - 56px**, เซลล์มี padding ซ้าย-ขวา 16-20px, ตัวเลขใช้ `font-variant-numeric: tabular-nums` ชิดขวา, บนมือถือ (< 768px) ให้แปลงเป็นการ์ดรายบุคคลที่อ่านง่าย |
| **ป้ายสถานะ (Status Badge)** | รูปทรงแคปซูลมน (Pill shape), ตัวอักษรหนาพอเหมาะ, สีพื้นอ่อน + ตัวอักษรเข้ม, มีไอคอนจุดสถานะ (Dot) ช่วยนำสายตา |
| **ฟอร์มกรอกข้อมูล (Friendly Forms)** | ระยะห่างระหว่างช่อง (Row Gap) **20px - 24px**, Label อยู่เหนือช่องเสมอพร้อมดอกจันสีแดงหากจำเป็น, มี Helper Text แนะนำตัวอย่างกำกับใต้ช่อง |
| **โมดอลยืนยัน (Confirmation Modal)** | ไม่ใช้ภาษาโปรแกรมมิ่ง ระบุผลลัพธ์ที่จะเกิดขึ้นให้ผู้ใช้มั่นใจ พร้อมปุ่ม "ยกเลิก" ที่กดง่ายและไม่ทำให้ตกใจ |

## 3. สถานะที่ต้องมีในทุกหน้า (Reassuring States)

1. **ว่าง (Friendly Empty State):**
   - เมื่อยังไม่มีข้อมูล แสดงพื้นที่โปร่งสบาย พร้อมไอคอนขนาด 48px โทนเทา-เขียวอ่อน
   - ข้อความชี้แจงสาเหตุอย่างสุภาพ ("ยังไม่มีประวัติการนัดหมายในระบบ")
   - มีปุ่มนำทางเริ่มต้นที่ชัดเจน เช่น "สร้างการนัดหมายครั้งแรก"
2. **ไม่พบผลการค้นหา (No Search Results):**
   - แจ้งคำค้นอย่างสุภาพ ("ไม่พบข้อมูลที่ตรงกับคำว่า '[คำค้น]'") พร้อมปุ่ม "ล้างคำค้นหาทั้งหมด"
3. **กำลังโหลด (Spacious Skeleton):**
   - ใช้ Skeleton Box สีเทาอ่อนกะพริบเบาๆ ขนาดและระยะห่างเท่าของจริง (ห้ามยุบพื้นที่จนกระตุกเมื่อโหลดเสร็จ)
4. **ข้อผิดพลาด (Empathetic Error State):**
   - อธิบายด้วยภาษาที่เข้าใจง่าย ไม่แสดง Raw Error พร้อมปุ่ม "ลองโหลดใหม่อีกครั้ง" และช่องทางติดต่อเจ้าหน้าที่

## 4. ป้องกันการแสดงผลบีบอัดบนมือถือ (Anti-Cramping on Mobile & PWA)

- **Card Layout over Squished Table:** เมื่อหน้าจอแคบกว่า 768px เปลี่ยนแถวตารางเป็น Card รูปทรงโปร่ง มี Padding ภายใน 16px - 20px
- **Touch Targets:** ทุกปุ่มและทุกจุดกดสูงอย่างน้อย `44px - 48px` มีช่องว่างระหว่างปุ่มอย่างน้อย `8px - 12px` ป้องกันการกดชน
- **Sticky Bottom Action Bar:** หากมีปุ่มบันทึกหรือยืนยันที่ติดขอบล่าง ต้องมีพื้นหลังทึบกันเนื้อหาซ้อน และมี `padding-bottom: calc(16px + env(safe-area-inset-bottom))`
- **Vertical Rhythm:** ระยะห่างแนวตั้งระหว่างการ์ดอย่างน้อย `16px` เพื่อให้สายตาผู้ใช้แยกแยะแต่ละรายการได้สบาย ไม่ตาล้า
