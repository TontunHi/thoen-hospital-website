# โครงสร้างและรูปแบบคอมโพเนนต์ (Component Guidelines)

สำหรับระบบโรงพยาบาลเถิน (Next.js 16 + CSS Modules / `page.css`)
เน้นความทันสมัย โปร่งสบายตา (Breathing Room) และใช้งานง่ายสำหรับผู้ใช้ทั่วไป (Non-Tech & Elderly Friendly)

## 1. ลำดับโครงสร้างหน้ามาตรฐาน (Spacious Page Layout)

| ลำดับ | ส่วนประกอบ | รายละเอียดและการจัดวางที่โปร่งสบาย |
|---|---|---|
| **1** | ลิงก์ย้อนกลับ | ข้อความ `← กลับสู่หน้ารายการ` พร้อมไอคอนลูกศร ตัวอักษรสี `var(--gray-700)` สูง ≥ 44px มีระยะห่างด้านล่าง `var(--space-3)` |
| **2** | ส่วนหัว (Header Bar) | `<h1>` ชื่อหน้าระบบชัดเจน + คำอธิบายบทบาทสั้น 1 บรรทัด (ช่วยให้ผู้ใช้ทั่วไปเข้าใจหน้าที่ของหน้า) + **ปุ่มหลักของหน้า (ชิดขวา)** *(ห้ามใส่ Eyebrow Badge / Pill Badge หมวดหมู่ลอยเหนือ `<h1>` เด็ดขาด หากมีลำดับชั้นให้ใช้ Breadcrumb ข้อความเรียบง่ายด้านบน)* |
| **3** | บล็อกสรุปสถิติ (Overview Metrics) | แสดงสรุปภาพรวมที่เข้าใจง่าย (เช่น รอดำเนินการ, เสร็จสิ้น) ในรูปแบบ Stat Pill Bar หรือการ์ดสรุปโปร่งๆ (`gap: 16px`, padding 16-20px) **ไม่บีบอัดตัวเลขติดกัน** |
| **4** | แถบเครื่องมือ (Spacious Toolbar) | ซ้าย: แท็บกรองสถานะแบบมนสบายตา \| ขวา: ช่องค้นหาแบบ Live พร้อมไอคอนแว่นขยาย + ดรอปดาวน์คัดกรอง เว้นระยะห่าง `gap: 16px` |
| **5** | เนื้อหาหลัก (Main Content) | ตารางข้อมูล (Table) หรือการ์ดรายการกลุ่ม (Grouped Cards) ที่มีพื้นที่ขอบสบายตา |

## 2. กติกาคอมโพเนนต์หลักเพื่อ UX ที่เป็นมิตร

| คอมโพเนนต์ | แนวทางปฏิบัติ & การจัดระยะไม่ให้บีบอัด |
|---|---|
| **ปุ่มหลัก (Primary Button)** | พื้นหลัง `var(--primary)`, ตัวอักษรขาว, สูง **44px - 48px**, รัศมีมุม `8px`, มีเงา `--shadow-card` นุ่มนวล, **มี 1 ปุ่มต่อมุมมองหลัก** พร้อมไอคอนฟังก์ชันนำสายตา (เช่น `+ สร้างนัดหมายใหม่`) |
| **ปุ่มรอง (Secondary Button)** | พื้นขาว ขอบ `var(--gray-200)` หรือพื้น `var(--primary-light)` ข้อความสีเขียวเข้ม ชัดเจนว่าคลิกได้ ไม่กลืนหายไปกับพื้นหลัง |
| **ปุ่มอันตราย (Destructive Button)** | พื้นหลัง `var(--danger-bg)` ตัวอักษร `var(--danger)` ใช้เฉพาะปุ่มลบหรือถอนสิทธิ์ และต้องเปิดโมดอลยืนยันผลเสมอ |
| **ช่องค้นหา (Unified Global Search)** | ความสูง 44-48px มีไอคอนแว่นขยายชิดซ้าย Placeholder ภาษาไทยชัดเจน เช่น *"พิมพ์คำค้นหา (ค้นหาได้ทั้ง HN, CID, ชื่อผู้ป่วย, VN, รหัสโรค, สิทธิ)..."* **ไม่ต้องมีดรอปดาวน์เลือกฟิลด์ค้นหา** (เช่น "ค้นหาด้วย HN", "ค้นหาทุกฟิลด์") เพราะระบบค้นหาครอบคลุมทุกมิติได้พร้อมกันอยู่แล้ว การตัดดรอปดาวน์ออกช่วยให้ Toolbar สะอาดโปร่งตาและพิมพ์ค้นหาได้ทันทีโดยไม่ต้องคลิกเลือกหมวดก่อน |
| **แถบเลือกช่วงเวลา (Single-Row Date Selector)** | **จัดวางในแถวเดียวกันในบรรทัดเดียว (Single Horizontal Line)** บนเดสก์ท็อป โดยมีเส้นคั่นบางแนวตั้ง (`border-right` หรือ `.as-date-divider`) คั่นระหว่างแท็บสลับโหมดกับกลุ่มเลือกวันที่ ไม่ตัดขึ้นบรรทัดใหม่ให้กล่องวันที่ตกไปอยู่อีกแถว<br>• **แท็บสลับโหมด:** ใช้ชื่อโหมดตรงไปตรงมา **"กำหนดเอง" \| "เดือน" \| "ปีงบประมาณ"** โดย**ห้ามใส่เลขลำดับ `1. 2. 3.` นำหน้า** เด็ดขาด<br>• **ดรอปดาวน์ปีงบประมาณ:** แสดงเฉพาะ **"ปีงบประมาณ [พ.ศ.]"** เช่น "ปีงบประมาณ 2568" **ห้ามแสดงช่วงวันที่ในวงเล็บ `(1 ต.ค. ... - 30 ก.ย. ...)`** ให้รกสายตา |
| **การ์ดสรุปสถิติ (Equal & Balanced KPI Grid)** | จัดการ์ดสรุปสถิติให้แสดง**แถวละเท่าๆ กันเสมอ** อย่างสมมาตร เช่น หากมี 8 ใบ ให้จัดเป็น **4 คอลัมน์ x 2 แถว (`repeat(4, 1fr)`)** หรือบนแท็บเล็ตเป็น 2 คอลัมน์ x 4 แถว (`repeat(2, 1fr)`) **ห้ามใช้ `auto-fill` ที่ทำให้แถวบนและล่างมีจำนวนไม่เท่ากันจนแหว่ง** (เช่น บน 5 ล่าง 3) การ์ดทุกใบต้องมีความกว้างและความสูงสมดุลเท่ากัน |
| **ตารางข้อมูล (Data Table)** | **ห้ามบีบแถวเตี้ยเด็ดขาด**: ความสูงแถวอย่างน้อย **52px - 56px**, เซลล์มี padding ซ้าย-ขวา 16-20px, **จัดข้อมูลให้อยู่ตรงกลางของหัวข้อคอลัมน์ (`center`) เป็นมาตรฐานหลัก** (ลำดับ, วันที่/เวลา, รหัส/HN, เลขบัตรประชาชน, ชื่อ-สกุลผู้ป่วย, สถานะ Badge, จำนวนนับ, ปุ่ม Action) เพื่อความสมดุลสายตา ไม่เอียงริมซ้ายริมขวาสะเปะสะปะ โดยหัวคอลัมน์ `<th>` และเซลล์ `<td>` ต้องมี alignment ตรงกัน 100% เสมอ (ดูรายละเอียดข้อ 3)<br>• **ไอคอน Sort อยู่บรรทัดเดียวกับชื่อหัวข้อเสมอ (Sort Icon Inline Cohesion):** ไอคอนเรียงลำดับ (`ArrowUpDown`, `ArrowUp`, `ArrowDown`) ต้องแสดงเคียงข้างกับข้อความชื่อหัวข้อในบรรทัดเดียวกันเสมอ (`display: inline-flex; align-items: center; gap: 4px; white-space: nowrap;`) **ห้ามปล่อยให้ไอคอนตกไปอยู่อีกบรรทัดเด็ดขาด** (ระวัง `svg { display: block; }` ใน CSS Reset)<br>• **กดดูข้อมูลผ่านแถวโดยตรง (Row-Clickable Records):** ทั้งแถว (`<tr>`) สามารถคลิกเปิดดู Modal รายละเอียดได้โดยตรง (`cursor: pointer`, hover feedback ชัดเจน) ไม่ต้องสร้างคอลัมน์ปุ่ม "ดูข้อมูล/รายละเอียด" ซ้ำซ้อน<br>• **ไม่มีปุ่มคัดลอกในเซลล์ (No In-Cell Copy Clutter):** ไม่ใส่ไอคอนปุ่ม Copy ข้าง HN หรือเลขบัตรทุกบรรทัด แสดงตัวเลขเรียบง่ายด้วย `tabular-nums` เพื่อความสะอาดตา บนมือถือ (< 768px) ให้แปลงเป็นการ์ดรายบุคคลที่อ่านง่าย |
| **ป้ายสถานะ (Status Badge)** | รูปทรงแคปซูลมน (Pill shape), ตัวอักษรหนาพอเหมาะ, สีพื้นอ่อน + ตัวอักษรเข้ม, มีไอคอนจุดสถานะ (Dot) ช่วยนำสายตา เมื่ออยู่ในตารางต้องจัดอยู่กึ่งกลางเซลล์ (`display: inline-flex; margin: 0 auto;`) *(ใช้สำหรับแสดงสถานะข้อมูลในตาราง/การ์ดเท่านั้น **ห้ามนำมาทำเป็น Eyebrow Badge แปะลอยเหนือ `<h1>`**)* |
| **ฟอร์มกรอกข้อมูล (Friendly Forms)** | ระยะห่างระหว่างช่อง (Row Gap) **20px - 24px**, Label อยู่เหนือช่องเสมอพร้อมดอกจันสีแดงหากจำเป็น, มี Helper Text แนะนำตัวอย่างกำกับใต้ช่อง |
| **โมดอลยืนยัน (Confirmation Modal)** | ไม่ใช้ภาษาโปรแกรมมิ่ง ระบุผลลัพธ์ที่จะเกิดขึ้นให้ผู้ใช้มั่นใจ พร้อมปุ่ม "ยกเลิก" ที่กดง่ายและไม่ทำให้ตกใจ |

## 3. มาตรฐานการจัดแนวข้อมูลในตารางให้ตรงกลางหัวข้อ (Table Alignment Standard)

แก้ปัญหาข้อมูลตารางเอียงสะเปะสะปะ เดี๋ยวริมซ้ายเดี๋ยวริมขวาไม่ตรงกับหัวข้อ โดยยึดหลักเกณฑ์ดังนี้:

### 3.1 หัวคอลัมน์ (`<th>`) และเซลล์ข้อมูล (`<td>`) ต้องตรงกัน 100% (Alignment Harmony)
- **ห้ามเด็ดขาด**: `<th>` จัดกึ่งกลางแต่ `<td>` ชิดซ้าย หรือ `<th>` ชิดซ้ายแต่ `<td>` ชิดขวา
- คอลัมน์ใดกำหนดแนวการจัดวางแบบใด ทั้งหัวตารางและเนื้อหาทุกแถวต้องใช้การจัดวางแนวนั้นเหมือนกันทุกแถว

### 3.2 กฎการจัดกึ่งกลาง (`text-align: center`) — มาตรฐานหลักสำหรับข้อมูลส่วนใหญ่
เพื่อให้ตารางมีความสมดุล สบายตา อ่านง่าย และข้อมูลอยู่ตรงกลางของหัวข้ออย่างแท้จริง คอลัมน์ต่อไปนี้ **ต้องจัดตรงกลาง (`center`) ทั้ง `<th>` และ `<td>`**:
1. **ลำดับที่ (#, ลำดับ)**: `text-align: center;`
2. **วันที่และเวลา (Date & Time)**: เช่น "12 ต.ค. 2569", "08:30 น." → `text-align: center;`
3. **รหัส, หมายเลขเอกสาร, HN, Masked CID**: เช่น "HN 123456", "•••1234" → `text-align: center; font-variant-numeric: tabular-nums;`
4. **ป้ายสถานะ (Status Badges / Tags / Pills)**: จัดกึ่งกลางทั้งหัวตารางและเซลล์ ภายในเซลล์ให้ Badge อยู่กึ่งกลางเสมอด้วย `display: inline-flex; justify-content: center; align-items: center;`
5. **ตัวเลขจำนวนนับ / สถิติทั่วไป / จำนวนเคส (Counts & General Numbers)**: เช่น "5 ราย", "10 ชิ้น" → `text-align: center; font-variant-numeric: tabular-nums;`
6. **ปุ่มการกระทำและไอคอน (Actions / Buttons / Menu)**: กลุ่มปุ่มดูรายละเอียด, แก้ไข, ลบ → `text-align: center;` พร้อม `display: inline-flex; justify-content: center; gap: 8px;`
7. **ช่องทำเครื่องหมาย (Checkbox / Selection)**: `text-align: center;`
8. **ข้อมูลชดเชย (บาท) ในตารางกองทุน/เวชระเบียน (Reimbursement Amount)**: จัดแสดงตรงกลางของหัวข้อ (`text-align: center; font-variant-numeric: tabular-nums;`) เพื่อความสมดุลสายตาและสอดคล้องกับหัวตาราง
9. **ข้อมูลอายุและหน่วย (Age & Unit Cohesion)**: `text-align: center;` และต้องแสดงหน่วย "ปี" ในบรรทัดเดียวกันเสมอ (`white-space: nowrap;`) เช่น `18 ปี`
10. **ชื่อ-สกุลผู้ป่วย (Patient Name)**: จัดแสดงตรงกลางในแนวนอนแกน X เสมอ (`text-align: center;` หรือ `.col-center` ทั้ง `<th>` และ `<td>`) สอดรับกลมกลืนกับคอลัมน์ HN, CID, เพศ, อายุ ที่ขนาบข้าง ไม่ให้ข้อมูลชื่อเอียงริมซ้ายขัดสายตา และหัวตาราง `<th>` ที่มีปุ่ม Sort ให้จัด `justify-content: center` เพื่อให้ข้อมูลชื่อ-สกุลตรงกลางสมดุลอย่างแท้จริง

### 3.3 ข้อยกเว้นเฉพาะสำหรับการจัดชิดซ้ายหรือชิดขวา (โดย `<th>` ต้องตรงกับ `<td>`)
- **จัดชิดซ้าย (`text-align: left` ทั้ง `<th>` และ `<td>`)**:
  - ใช้เฉพาะคอลัมน์ที่เป็น **ข้อความบรรยายยาว** เช่น "รายการตรวจ/การวินิจฉัย", "หัวข้อข่าว/เรื่อง", "บันทึกหมายเหตุ", "ชื่อยาและวิธีใช้ยาวๆ" เพื่อให้อ่านตามธรรมชาติของการขึ้นบรรทัดใหม่จากซ้ายไปขวา (หมายเหตุ: คอลัมน์ **ชื่อ-สกุลผู้ป่วย ไม่จัดชิดซ้าย** แต่จัดแสดงตรงกลางในแนวนอนแกน X ตามข้อ 3.2 ข้อ 10 เพื่อความสมดุลสายตา)
  - **สำหรับชื่อ-สกุลผู้ป่วย (Centered Patient Name & Intact Wrap):** จัดกึ่งกลางแนวนอนแกน X และแสดงชื่อและนามสกุลใน**บรรทัดเดียวกันเป็นหลัก** (`minWidth: 160-180px`) หากพื้นที่ไม่พอจนจำเป็นต้องตัดบรรทัดใหม่ **ให้ยกไปทั้งนามสกุล (Keep Surname Intact on New Line)** โดยครอบชื่อและนามสกุลด้วย `display: inline-block; white-space: nowrap;` ป้องกันเบราว์เซอร์ตัดคำกลางพยางค์
- **จัดชิดขวา (`text-align: right` ทั้ง `<th>` และ `<td>`)**:
  - ใช้เฉพาะ **รายงานสรุปงบประมาณ/บัญชีการเงินที่เน้นการเทียบหลักทศนิยมโดยตรง (Financial Ledgers)** โดยหัวคอลัมน์ `<th>` ต้องจัดชิดขวาตรงกับข้อมูล `<td>` เสมอ

### 3.4 โครงสร้าง CSS และ Classes แนะนำสำหรับตาราง

```css
/* คลาสจัดแนวคอลัมน์ที่ต้องใช้คู่กันทั้ง th และ td */
.thTable th,
.thTable td {
  padding: 14px 16px;
  vertical-align: middle;
}

/* 1. จัดกึ่งกลางตรงกับหัวข้อ (มาตรฐานหลัก) */
.thTable th.col-center,
.thTable td.col-center {
  text-align: center;
}

/* จัดให้ Badge หรือ Action Group อยู่ตรงกลางช่องพอดี */
.thTable td.col-center .statusBadge {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  margin: 0 auto;
}

.thTable td.col-center .actionGroup {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: 8px;
}

/* 2. จัดชิดซ้าย (ข้อความยาว/ชื่อคน) */
.thTable th.col-left,
.thTable td.col-left {
  text-align: left;
}

/* 3. จัดชิดขวา (เฉพาะยอดเงินทางการเงิน) */
.thTable th.col-right,
.thTable td.col-right {
  text-align: right;
  font-variant-numeric: tabular-nums;
}
```

### 3.5 โครงสร้างไอคอน Sort หัวตารางให้อยู่บรรทัดเดียวกับชื่อหัวข้อ (Sort Icon Inline Pattern)

```tsx
/* โครงสร้าง JSX ใน <th> ที่มี Sort */
<th
  className="sortable text-center"
  style={{ width: '130px' }}
  onClick={() => handleSort('vstdate')}
>
  <span className="th-sort-inner">
    <span>วันที่รับบริการ</span>
    {renderSortIndicator('vstdate')}
  </span>
</th>
```

```css
/* สไตล์ CSS สำหรับหัวข้อและไอคอน Sort ให้อยู่บรรทัดเดียว ไม่แตกแถว */
.thTable thead th.sortable {
  cursor: pointer;
  white-space: nowrap;
  user-select: none;
}

.th-sort-inner {
  display: inline-flex;
  align-items: center;
  gap: 4px;
  white-space: nowrap;
  vertical-align: middle;
}
```

## 4. สถานะที่ต้องมีในทุกหน้า (Reassuring States)

1. **ว่าง (Friendly Empty State):**
   - เมื่อยังไม่มีข้อมูล แสดงพื้นที่โปร่งสบาย พร้อมไอคอนขนาด 48px โทนเทา-เขียวอ่อน
   - ข้อความชี้แจงสาเหตุอย่างสุภาพ ("ยังไม่มีประวัติการนัดหมายในระบบ")
   - มีปุ่มนำทางเริ่มต้นที่ชัดเจน เช่น "สร้างการนัดหมายครั้งแรก"
2. **ไม่พบผลการค้นหา (No Search Results):**
   - แจ้งคำค้นอย่างสุภาพ ("ไม่พบข้อมูลที่ตรงกับคำว่า '[คำค้น]'") พร้อมปุ่ม "ล้างคำค้นหาทั้งหมด"
3. **กำลังโหลด (Spacious Skeleton):**
   - ใช้ Skeleton Box สีเทาอ่อนกะพริบเบาๆ ขนาดและระยะห่างเท่าของจริง (ห้ามยุบพื้นที่จนกระตุกเมื่อโหลดเสร็จ)
4. **ข้อผิดพลาด (Empathetic Error State):**
   - อธิบายด้วยภาษาที่เข้าใจง่าย ไม่แสดง Raw Error พร้อมปุ่ม "ลองโหลดใหม่อีกครั้ง" และช่องทางติดต่อเจ้าหน้าที่

## 5. ป้องกันการแสดงผลบีบอัดบนมือถือ (Anti-Cramping on Mobile & PWA)

- **Card Layout over Squished Table:** เมื่อหน้าจอแคบกว่า 768px เปลี่ยนแถวตารางเป็น Card รูปทรงโปร่ง มี Padding ภายใน 16px - 20px
- **Touch Targets:** ทุกปุ่มและทุกจุดกดสูงอย่างน้อย `44px - 48px` มีช่องว่างระหว่างปุ่มอย่างน้อย `8px - 12px` ป้องกันการกดชน
- **Sticky Bottom Action Bar:** หากมีปุ่มบันทึกหรือยืนยันที่ติดขอบล่าง ต้องมีพื้นหลังทึบกันเนื้อหาซ้อน และมี `padding-bottom: calc(16px + env(safe-area-inset-bottom))`
- **Vertical Rhythm:** ระยะห่างแนวตั้งระหว่างการ์ดอย่างน้อย `16px` เพื่อให้สายตาผู้ใช้แยกแยะแต่ละรายการได้สบาย ไม่ตาล้า
