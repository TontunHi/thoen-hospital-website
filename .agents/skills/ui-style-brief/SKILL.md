# สไตล์ดีไซน์ UI โรงพยาบาลเถิน และคู่มือปฏิบัติงาน (UI Style Brief)

ระบบเว็บและพอร์ทัลโรงพยาบาลเถิน (Next.js 16 App Router, React 19, CSS Modules / `page.css`, API Gateway Backend)
ตอบเป็นภาษาไทยเสมอ เว้นแต่ผู้ใช้ใช้ภาษาอื่น ข้อมูลทางเทคนิคให้สรุปเป็นตารางเพื่อความกระชับ

| โหมด | ใช้เมื่อ | สิ่งที่ทำ |

## เสาหลักการออกแบบ 8 ข้อ (Core Design Pillars)

1. **ชัดเจน เป็นมิตร เข้าใจง่ายต่อทุกคน (Human-Centered & Non-Tech Friendly):**
   - ผู้ใช้คือบุคลากรทางการแพทย์ที่ทำงานแข่งกับเวลา, ผู้ป่วย, และประชาชนทุกช่วงวัยรวมถึงผู้สูงอายุ
   - ออกแบบให้ **Affordance ชัดเจนโดยไม่ต้องเดา**: ปุ่มต้องดูเป็นปุ่ม, ฟิลด์กรอกมีขอบเขตชัดเจน, ตัวหนังสืออ่านง่ายตาไม่ล้า
   - ลดความกลัวในการกดผิด (Forgiving UI) มีข้อความอธิบายเป็นภาษาไทยสุภาพ ไร้ศัพท์เทคนิค (No jargon)
2. **โปร่ง โล่ง สบายตา มีระยะหายใจ (Breathing Room & Anti-Cramping):**
   - **ห้ามบีบอัดข้อมูลจนแน่นอึดอัดเด็ดขาด**: Whitespace คือเครื่องมือจัดกลุ่มความคิด ไม่ใช่ที่ว่างที่ต้องรีบยัดของลงไป
   - ใช้ระยะห่างสบายตา (Comfortable Density): Card padding 20-24px, ช่องว่างระหว่างส่วน (Section Gap) 24-32px, แถวตารางสูงอย่างน้อย 52-56px
   - หากข้อมูลมีจำนวนมาก ให้ใช้วิธีจัดกลุ่มแบบก้อนข้อมูล (Chunking) หรือเปิดดูเพิ่มเติม (Progressive Disclosure) แทนการอัดทุกอย่างในแถวเดียว
3. **ทันสมัย เรียบหรู แต่ดูอบอุ่น (Modern, Polished & Welcoming):**
   - ดีไซน์ร่วมสมัยด้วยพื้นผิวที่สะอาดสะอ้าน มนละมุน (`border-radius: 12-16px`), เส้นขอบบางเบาเป็นระเบียบ (`var(--gray-200)`), และเงานุ่มลึกเป็นธรรมชาติ (`var(--shadow-card)`, `var(--shadow-hover)`)
   - ไม่แบนราบแข็งทื่อเหมือนแบบฟอร์มราชการยุคเก่า และไม่เยอะฟุ้งแบบ AI slop (ไม่มี Gradient แฟนซีม่วง-น้ำเงิน หรือ Glassmorphism เลอะเทอะ)
4. **ไอคอนนำสายตาที่มีหน้าที่ชัดเจน (Purposeful Visual Anchors):**
   - ไม่ใช้ไอคอนตกแต่งลอยๆ ไร้ความหมาย (No decorative clutter)
   - **แต่สนับสนุนการใช้ไอคอนนำสายตาและเพิ่มความเข้าใจ (Visual Anchors)** จาก `material-symbols-outlined` หรือ `lucide-react` เพื่อช่วยผู้ใช้ที่ไม่ชอบอ่านข้อความยาวๆ สแกนหน้าจอได้ทันที เช่น ไอคอนปฏิทินหน้าระบุวันที่, ไอคอนโทรศัพท์หน้าเบอร์ติดต่อ, ไอคอนแว่นขยายในช่องค้นหา, ไอคอนเตือนหน้าข้อความสำคัญ
   - **ห้ามใส่ Emoji** ในหัวข้อ เมนู หรือข้อความทางการของระบบ
5. **สีสื่อความหมายและสร้างความมั่นใจ (Semantic & Calming Colors):**
   - 1 สี = 1 ความหมาย: สีเขียวแบรนด์ (`var(--primary): #0D7446`) สื่อถึงความน่าเชื่อถือ สุขภาพ และการกระทำหลัก
   - สีสถานะอื่นใช้พื้นสีอ่อน + ตัวอักษรเข้มคอนทราสต์ ≥ 4.5:1 ตาม `references/tokens.md` พร้อมข้อความกำกับเสมอ
   - ให้ความรู้สึกสงบ ปลอดภัย ไม่ใช้สีเตือนจัดจ้านเกินความจำเป็นจนทำให้ผู้ใช้ตกใจ
6. **หนึ่งหน้า หนึ่งการกระทำหลัก (Clear Action Hierarchy):**
   - ในแต่ละมุมมองหรือการ์ด ต้องมี **ปุ่มหลัก (Primary Button) เด่นชัดเพียง 1 ปุ่ม** เพื่อให้ผู้ใช้รู้ทันทีว่าต้องกดอะไรต่อ
   - ปุ่มรองและลิงก์ช่วยเสริมอย่างกลมกลืน ไม่แย่งความเด่น
7. **ลดความซ้ำซ้อน จัดระเบียบสายตา และจัดกึ่งกลางตาราง (Smart Subtraction & Table Alignment):**
   - ข้อมูลหรือป้ายสถานะที่ซ้ำกันทุกบรรทัด ให้ย้ายขึ้นไปสรุปหรือกรองที่หัวตาราง
   - ตัดสิ่งรบกวนสายตาออก เพื่อเหลือเฉพาะข้อมูลที่ช่วยให้ตัดสินใจได้เร็วที่สุด
   - **กดดูข้อมูลผ่านแถว/Record โดยตรง (Row-Clickable Records):** ไม่ต้องสร้างคอลัมน์ "รายละเอียด/เปิดดู" หรือยัดปุ่ม Action ซ้ำๆ ทุกแถว ให้ทั้งแถว (`<tr>`) สามารถคลิกเปิดดู Modal หรือรายละเอียดเชิงลึกได้โดยตรง (`cursor: pointer`, hover feedback ชัดเจน) ช่วยประหยัดพื้นที่คอลัมน์และลดความรกของ UI
   - **ไม่ต้องมีปุ่มคัดลอกในเซลล์ตาราง (No In-Cell Copy Clutter):** ไม่ต้องใส่ปุ่มไอคอน Copy ข้าง HN หรือเลขบัตรประชาชนทุกบรรทัด ให้แสดงตัวเลขชัดเจนด้วย `tabular-nums` หากต้องการคัดลอก ผู้ใช้สามารถคลิกดูในหน้าต่างรายละเอียด (Detail Modal) หรือไฮไลต์ข้อความได้เอง ลด Visual Clutter ในตาราง
    - **ห้ามใส่ Eyebrow Badge / Pill Badge ลอยเหนือหัวข้อเรื่อง (No Eyebrow/Overline Pill Badges above Titles):** ห้ามสร้างป้ายแคปซูลมนๆ มีไอคอนพร้อมข้อความหมวดหมู่หรือกองทุน (เช่น `[ Activity กองทุน 14 • บริการคัดกรอง... ]`) แปะลอยไว้เหนือ `<h1>` เด็ดขาด ดีไซน์แบบนี้รกสายตา ดูเป็นเทมเพลตสำเร็จรูป/SaaS marketing page ที่ไม่เข้ากับระบบงานโรงพยาบาล ให้ส่วนหัว (Header) สะอาดตา ขึ้น `<h1>` ได้ทันที หากต้องการระบุลำดับชั้นหรือหมวดหมู่แม่ ให้ใช้ Breadcrumb ลิงก์ข้อความเรียบง่าย หรือระบุใน Subtitle ข้อความปกติ
    - **แถบเลือกช่วงเวลาในแถวเดียวและไร้ตัวเลขนำหน้า (Unified Single-Row Date Selector & No Tab Numbers):**
      - ปุ่ม Segmented แท็บสลับช่วงเวลาให้ใช้ข้อความชื่อโหมดตรงไปตรงมา: **"กำหนดเอง" | "เดือน" | "ปีงบประมาณ"** โดย**ห้ามใส่เลขลำดับ `1. 2. 3.` นำหน้า** เพราะเป็นตัวสลับโหมด (Mode Switcher) ไม่ใช่แบบสอบถามหรือขั้นตอน Wizard
      - ในตัวเลือกปีงบประมาณ (Dropdown) ให้แสดงเฉพาะ **"ปีงบประมาณ [พ.ศ.]"** (เช่น "ปีงบประมาณ 2568") โดย**ห้ามแสดงช่วงวันที่ในวงเล็บ `(1 ต.ค. ... – 30 ก.ย. ...)`** ให้รกสายตา ผู้ใช้ในโรงพยาบาลทราบรอบปีงบประมาณดีอยู่แล้ว การตัดออกช่วยลดความยาวและกวาดสายตาหาปีได้เร็วขึ้น (Smart Subtraction)
      - จัดวางแท็บสลับโหมดและตัวเลือกวันที่ให้อยู่ใน**แถวเดียวกันในบรรทัดเดียว (Single Unified Row)** บนหน้าจอเดสก์ท็อป โดยมีเส้นคั่นบางแนวตั้ง (`as-date-divider` / `hs-date-divider`) คั่นระหว่างกลุ่มแท็บกับกลุ่มตัวเลือกวันที่ ไม่ตัดขึ้นบรรทัดใหม่ให้กล่องวันที่ตกไปอยู่อีกแถว
    - **การ์ดสรุปสถิติแถวละเท่ากันอย่างสมมาตร (Equal & Balanced KPI Grid Layout):**
      - จัดการ์ดสรุปสถิติ (KPI Summary Cards) ให้แสดงแถวละเท่าๆ กันเสมอ เช่น หากมีการ์ด 8 ใบ ให้จัดเป็น **4 คอลัมน์ x 2 แถวสมมาตร (`grid-template-columns: repeat(4, 1fr)`)** หรือบนแท็บเล็ตเป็น 2 คอลัมน์ x 4 แถว (`repeat(2, 1fr)`)
      - **ห้าม** ใช้ `auto-fill` ที่ทำให้การ์ดแถวบนและแถวล่างมีจำนวนไม่เท่ากัน (เช่น แถวบน 5 ใบ แถวล่าง 3 ใบ) จนเกิดช่องโหว่แหว่งหรือไม่สมดุล การ์ดทุกใบต้องมีความกว้างและความสูงเท่ากัน
    - **ช่องค้นหาแบบครอบคลุมในช่องเดียว ไม่ต้องมีดรอปดาวน์เลือกฟิลด์ (Unified Global Search & No Field Dropdown Clutter):**
      - **ไม่ต้องมีดรอปดาวน์เลือกฟิลด์ค้นหา** (เช่น ไม่ต้องมีตัวเลือกว่า "ค้นหาด้วย HN", "ค้นหาด้วย CID", หรือ "ค้นหาทุกฟิลด์") เพราะช่องค้นหา (Search Input) สามารถค้นหาครอบคลุมทุกมิติได้พร้อมกันอยู่แล้ว (HN, CID, ชื่อผู้ป่วย, VN, รหัสโรค, สิทธิการรักษา)
      - การตัดดรอปดาวน์เลือกฟิลด์ออกช่วยลดขั้นตอน (Frictionless UX) ผู้ใช้พิมพ์คำค้นได้ทันทีโดยไม่ต้องคลิกเลือกหมวดก่อน และทำให้แถบเครื่องมือ (Toolbar) โปร่งสบายตาขึ้นอย่างมาก
    - **จัดข้อมูลในตารางให้ตรงกลางหัวข้อเสมอ (Table Column Harmony):** ข้อมูลในเซลล์ (`<td>`) ต้องจัดแสดงตรงกลางของหัวข้อ (`<th>`) เป็นมาตรฐานหลักสำหรับข้อมูลส่วนใหญ่ (ลำดับ, วันที่, เวลา, รหัส/HN, เลขบัตรประชาชน, ชื่อ-สกุลผู้ป่วย, ป้ายสถานะ Badge, จำนวนนับ) ป้องกันปัญหาข้อมูลเอียงริมซ้ายริมขวาสะเปะสะปะ โดยหัวข้อ `<th>` และเซลล์ `<td>` ในคอลัมน์เดียวกันต้องมี Alignment ตรงกัน 100% เสมอ
    - **การแสดงผลชื่อ-สกุลผู้ป่วยจัดตรงกลางในแนวนอนแกน X และยกไปทั้งนามสกุล (Centered Patient Name on X-Axis & Intact Wrap):**
      - **จัดชื่อ-สกุลให้อยู่ตรงกลางในแนวนอนแกน X เสมอ (`col-center` ทั้ง `<th>` และ `<td>`, `text-align: center`)**: ข้อมูลชื่อ-สกุลผู้ป่วยต้องจัดแสดงกึ่งกลางคอลัมน์ ไม่เอียงริมซ้ายริมขวา เพื่อให้สอดรับกลมกลืนกับคอลัมน์ HN, CID, เพศ, อายุ ที่อยู่ขนาบข้าง และหัวตาราง `<th>` ที่มีปุ่ม Sort ต้องจัด `justify-content: center` ให้อยู่กึ่งกลางเช่นเดียวกัน
      - แสดงชื่อและนามสกุลใน**บรรทัดเดียวกันเป็นหลัก** กำหนดพื้นที่คอลัมน์ให้เหมาะสม (`minWidth: 160-180px`)
      - หากพื้นที่จอแคบจนจำเป็นต้องตัดบรรทัดใหม่ **ให้ยกไปทั้งนามสกุล (Keep Surname Intact on New Line)** ห้ามให้เบราว์เซอร์ตัดแบ่งพยางค์กลางชื่อหรือตัดกลางนามสกุลเด็ดขาด
      - **วิธีปฏิบัติ:** กำหนด `text-align: center;` (หรือคลาส `col-center`) บน `<th>` และ `<td>` พร้อมแยกส่วนคำนำหน้า+ชื่อ (`firstName`) และนามสกุล (`lastName`) ครอบแต่ละส่วนด้วยกล่องที่ไม่แตกคำ (`display: inline-block; white-space: nowrap;`) คั่นด้วยเว้นวรรคปกติ ทำให้หากพื้นที่พอจะแสดงต่อกันในบรรทัดเดียวตรงกลาง แต่หากพื้นที่แคบ ก้อนนามสกุลจะถูกยกไปขึ้นบรรทัดใหม่อย่างสมบูรณ์ทั้งก้อนโดยยังคงกึ่งกลางแนวนอนแกน X
    - **ข้อมูลอายุและหน่วยต้องอยู่บรรทัดเดียวกันเสมอ (Age & Unit Cohesion):**
      - ข้อมูลอายุและหน่วย "ปี" ต้องแสดงใน**บรรทัดเดียวกันเสมอ** เช่น `18 ปี`, `26 ปี` ห้ามปล่อยให้คำว่า "ปี" ตกไปอยู่อีกบรรทัดเด็ดขาด (`white-space: nowrap` หรือ `{item.age}&nbsp;ปี`)
    - **ข้อมูลชดเชยจัดแสดงตรงกลางของหัวข้อ (Centered Reimbursement Column):**
      - ในตารางรายงานเวชระเบียน/กองทุน RCM ข้อมูลคอลัมน์ "ชดเชย (บาท)" ให้จัดแสดง**ตรงกลางของหัวข้อ (`text-align: center` ทั้ง `<th>` และ `<td>`)** เพื่อความสมดุลสายตาและสอดคล้องกลมกลืนกับคอลัมน์สถานะและรหัสส่วนใหญ่ในตาราง
    - **ไอคอน Sort หัวตารางต้องอยู่บรรทัดเดียวกับชื่อหัวข้อเสมอ (Table Header Sort Icon Inline Cohesion):**
      - ไอคอน Sort (`ArrowUpDown`, `ArrowUp`, `ArrowDown`) ต้องแสดงใน**บรรทัดเดียวกับข้อความชื่อหัวข้อตารางเสมอ** (`display: inline-flex; align-items: center; gap: 4px; white-space: nowrap;`)
      - **ห้ามปล่อยให้ไอคอน Sort หล่นไปอยู่อีกบรรทัด** ด้านล่างชื่อหัวข้อโดยเด็ดขาด เนื่องจากใน `globals.css` มีการรีเซ็ต `svg { display: block; }` ทำให้หากไม่มีการครอบด้วย inline-flex container หรือกำหนด `display: inline-block; vertical-align: middle;` ตัวไอคอน SVG จะกลายเป็นบล็อกและตัดขึ้นบรรทัดใหม่ทันที
      - กำหนดความกว้างคอลัมน์ (`width` หรือ `minWidth`) ให้เพียงพอสำหรับทั้งข้อความหัวข้อ + ช่องว่าง + ไอคอน (เช่น "วันที่รับบริการ" ควรใช้ `width: 120-130px`) พร้อม `white-space: nowrap;`
      - หากหัวข้อจัดตรงกลาง (`text-center`) ให้ inner flex จัดกึ่งกลางด้วย (`justify-content: center;`) เพื่อให้ทั้งข้อความและไอคอนสมดุลอยู่กลางคอลัมน์อย่างแท้จริง
    - **ห้ามใส่ป้ายแคปซูล/Pill Tag ตกแต่งประกบข้อมูลปกติ (No Gratuitous/AI-Looking Pill Tags on Standard Data):**
      - เช่น การใส่ป้ายแคปซูลมนๆ สีเขียวหรือสีพาสเทลแปะประกบตัวเลขอายุ `[ 13-45 ]` หรือ `[ กลุ่มเป้าหมาย 13-45 ปี ]` ข้างตัวเลขอายุในตารางหรือในหัวข้อหน้าต่าง Modal
      - ดีไซน์ลักษณะนี้เป็นหนึ่งในสัญญาณของ AI slop (พยายามสร้าง tag/pill ใส่ทุกสิ่งทุกอย่างที่คำนวณได้จนรกสายตา)
      - ข้อมูลอายุควรแสดงเพียงตัวเลขอายุปกติ เช่น `26 ปี` อย่างสะอาดตาและเป็นระเบียบ ไม่ต้องมี tag ประกบซ้ำซ้อน หากต้องการคัดกรองหรือเน้นกลุ่มเป้าหมาย ให้ใช้ตัวกรองที่แถบเครื่องมือหรือดูภาพรวมจากการ์ดสรุป KPI แทน
    - **ห้ามใส่ตัวเลขลำดับหัวข้อนำหน้าชื่อเมนูและชื่อเรื่อง (No Leading Item Numbers in Fund/Report Titles and Menu Labels):**
      - **ห้ามใส่ตัวเลขลำดับข้อ เช่น `1.`, `2.`, `3.` นำหน้าชื่อเมนูใน Sidebar/Submenu หรือชื่อหน้ารายงาน (`<h1>`, Page Title, Breadcrumb)** เช่น ห้ามใช้ `"2. รายชื่อผู้รับบริการ"`, `"3. รายชื่อผู้รับบริการแพทย์แผนไทยรวม"`
      - ให้ใช้ชื่อบริการหรือชื่อรายงานที่สื่อความหมายโดยตรง เช่น **"รายชื่อผู้รับบริการ"**, **"รายชื่อผู้รับบริการแพทย์แผนไทยรวม"**
      - หากระบบจำเป็นต้องระบุรหัสหัวข้อหรือตัวเลขลำดับกองทุน ให้แยกแสดงในรูปของป้าย Badge ชิปกำกับ (เช่น `badge: '2'`, `badge: '3'`) หรือระบุใน Subtitle/Breadcrumb แทนการใส่ตัวเลขจุดนำหน้าชื่อ ช่วยให้แถบนำทางและหัวเรื่องดูโปร่ง สะอาดตา ทันสมัย และไม่ดูเหมือนเอกสารราชการหรือข้อสอบยุคเก่า
8. **เคารพมาตรฐานโรงพยาบาลและความปลอดภัย (Hospital Standards & Safety):**
   - วันที่ต้องเป็น **พ.ศ. ไทย** เสมอ (เช่น "1 พ.ย. 2569")
   - ข้อมูลสุขภาพและตัวบุคคล (PHI) ต้อง Masking แสดงเฉพาะ 4 ตัวท้าย (เช่น `x-xxxx-xxxxx-xx-1` หรือ `•••1234`)
   - ขนาดเป้าสัมผัส (Touch Target) ทุกจุดบนมือถือและจอสัมผัสต้องกว้างและสูงอย่างน้อย **44-48px**
   - คอนทราสต์ตัวอักษรทุกจุด ≥ 4.5:1 (ระดับ AA)

## ขั้นตอนโหมด A (ออกแบบต้นแบบ: Prototype)

1. **ทำความเข้าใจผู้ใช้และบริบท:** ผู้ใช้เป็นใคร (ผู้ป่วย/ผู้สูงอายุ/พยาบาล/จนท.), เข้ามาทำอะไร, อุปกรณ์หลักคืออะไร (มือถือ/แท็บเล็ต/คอมพิวเตอร์หน้างาน)
2. **วินิจฉัยจุดบกพร่องเดิม:** ระบุจุดที่อึดอัด บีบแน่น สีสับสน ข้อมูลตารางเอียงริมซ้ายริมขวา หรือยากต่อคนไม่เก่งเทคโนโลยี
3. **กำหนดการจัดวางแบบโปร่งสบาย (Breathing Room Layout):**
   - กำหนด Spacing, Card padding, Table row height ให้โปร่งตา สบายใจ
   - กำหนด Alignment ตารางให้ข้อมูลอยู่ตรงกลางหัวข้อ (Center-aligned standard)
   - วาง Visual hierarchy: Header โปร่งชัดเจน → สรุปสถานะที่เข้าใจง่าย → ตัวกรอง/ค้นหา → เนื้อหาหลัก
4. **ใส่ Affordance & Visual Anchors:**
   - ใช้ปุ่มที่เห็นขอบเขตชัดเจน กดง่าย
   - ใส่ไอคอนนำสายตาประกอบข้อความสำคัญเพื่อช่วยการสแกนเร็ว
5. **สร้างความพร้อมรองรับทุกสถานะ (States):**
   - ว่าง (Empty State): อธิบายอย่างเป็นมิตรพร้อมปุ่มเริ่มต้นที่ชัดเจน
   - กำลังโหลด: Skeleton โทนเทาอ่อนขนาดเท่ากล่องจริง ไม่กระตุกตา
   - ข้อผิดพลาด: ภาษาเข้าใจง่าย ปลอบประโลม ไม่โทษผู้ใช้ พร้อมปุ่มลองใหม่
6. **ตรวจทาน:** ตรวจสอบตาม `references/review-checklist.md` และส่งมอบไฟล์ Interactive Prototype + Spec `.md`

## ขั้นตอนโหมด C (ตรวจสอบ & Refactor โค้ดจริง)

1. **สำรวจโค้ดและวัดความอึดอัด:** เปิดดู `page.tsx` และ CSS เช็คดูว่า padding/gap แคบเกินไปหรือไม่, ตัวหนังสือติดกันเป็นพืดหรือไม่
2. **ปรับ Spacing & Padding:** ขยายพื้นที่หายใจ ใช้ตัวแปร `--space-*`, ปรับความสูงแถวตารางเป็น ≥ 52px, ปรับ padding การ์ดเป็น 20-24px
3. **จัดระเบียบตารางและ Alignment (Fix Ragged Table Alignment & Reduce Row Clutter):**
   - ตรวจสอบ `<th>` และ `<td>` ในแต่ละคอลัมน์ให้มี `text-align` สอดคล้องตรงกันเสมอ
   - ปรับคอลัมน์ลำดับ, วันที่, เวลา, รหัส/HN, เลขบัตรประชาชน, ชื่อ-สกุลผู้ป่วย, ป้ายสถานะ Badge, จำนวนนับ ให้จัดแสดงตรงกลางหัวข้อ (`text-align: center`)
   - แก้ไขปัญหาข้อมูลเอียงริมซ้ายริมขวาไม่ตรงกับหัวข้อ จัด Badge ให้อยู่กึ่งกลางเซลล์ (`justify-content: center; margin: 0 auto;`)
   - ปรับการเปิดดูข้อมูลให้กดผ่าน Record/แถวโดยตรง (`cursor: pointer`) แทนการเพิ่มคอลัมน์ปุ่มเปิดดูซ้ำซ้อน
   - ตัดปุ่มไอคอนคัดลอก (Copy button) ที่รกสายตาในเซลล์ตารางออก แสดงตัวเลขด้วย `tabular-nums` อย่างเป็นระเบียบตา เลขบัตรประชาชน (CID) ไม่ต้องใส่ตัวคั่นขีด (Hyphen) ให้แสดงตัวเลขติดกันตามจริง เพื่อความสะดวกในการคัดลอกหรือค้นหาต่อ
   - **ปรับแถบเลือกช่วงเวลาในแถวเดียว (Single-Row Date Selector):** รวมปุ่มแท็บสลับโหมด (`กำหนดเอง` | `เดือน` | `ปีงบประมาณ` โดยไม่มีเลข `1. 2. 3.` นำหน้า) และตัวเลือกวันที่ให้อยู่ในแถวเดียวกันในบรรทัดเดียว มีเส้นคั่นบางแนวตั้ง ไม่ตัดขึ้นบรรทัดใหม่ และตัดวงเล็บวันที่ในตัวเลือกปีงบประมาณออกให้เหลือเฉพาะ "ปีงบประมาณ [พ.ศ.]"
   - **ปรับ Grid การ์ดสรุป KPI ให้สมมาตรแถวละเท่ากัน (Equal KPI Grid):** จัดให้การ์ดแสดงแถวละเท่าๆ กัน เช่น 4 คอลัมน์ x 2 แถว (`repeat(4, 1fr)`) ไม่ปล่อยให้แถวบนและล่างมีจำนวนไม่เท่ากันจนแหว่ง
   - **จัดระเบียบชื่อ-สกุลผู้ป่วยให้อยู่ตรงกลางในแนวนอนแกน X (Centered Patient Name on X-Axis):** จัดชื่อ-สกุลให้อยู่ตรงกลางคอลัมน์แนวนอนแกน X เสมอ (`col-center` ทั้ง `<th>` และ `<td>`, `text-align: center`, หัวตารางปุ่ม Sort ใช้ `justify-content: center`) แสดงในบรรทัดเดียวกันเป็นหลัก (`minWidth: 160-180px`) และหากจำเป็นต้องตัดบรรทัดใหม่ ให้ยกไปทั้งนามสกุล (`display: inline-block; white-space: nowrap;` บนชื่อและนามสกุล) โดยไม่ตัดคำกลางพยางค์
   - **แสดงอายุและหน่วยในบรรทัดเดียว (Age Cohesion):** ตัวเลขอายุและหน่วยปีต้องอยู่บรรทัดเดียวกันเสมอ (`18 ปี`) ด้วย `white-space: nowrap` หรือ non-breaking space
   - **จัดคอลัมน์ชดเชยไว้ตรงกลางหัวข้อ (Centered Reimbursement Column):** คอลัมน์ชดเชย (บาท) ในตารางกองทุน/เวชระเบียน ให้จัดแสดงตรงกลางของหัวข้อ (`col-center` ทั้ง `<th>` และ `<td>`) สอดคล้องกับคอลัมน์ส่วนใหญ่
   - **จัดไอคอน Sort หัวตารางให้อยู่บรรทัดเดียวกับชื่อหัวข้อ (Sort Icon Inline Cohesion):** ตรวจสอบ `<th>` ที่มีฟังก์ชัน Sort ทุกคอลัมน์ ต้องครอบข้อความและไอคอนด้วยคอนเทนเนอร์ `inline-flex` (เช่น `.hs-th-sort`) หรือปุ่ม sort ที่มี `display: inline-flex; align-items: center; gap: 4px; white-space: nowrap;` และตั้งค่าไอคอนให้ `flex-shrink: 0; display: inline-block;` ป้องกันผลกระทบจาก `svg { display: block; }` ใน `globals.css` ที่ทำให้ไอคอนหล่นไปอยู่อีกบรรทัด
4. **ยกระดับ Affordance & Accessibility:**
   - เช็คขนาดปุ่ม (Touch Target ≥ 44-48px)
   - เพิ่ม Focus ring และ Hover transitions ที่นุ่มนวล
   - แทนที่ข้อความห้วนหรือศัพท์เทคนิคด้วย Microcopy ภาษาไทยที่สุภาพ เป็นมิตร
5. **ล้าง AI Slop และควบคุมโทนสี:**
   - ตรวจจับและถอด Eyebrow Badge / Title Badge ลอยเหนือหัวข้อออก (เช่น คลาส `.hs-title-badge` หรือ Badge กองทุนแคปซูล) ปรับเป็น Breadcrumb ข้อความธรรมดาหรือย้ายข้อมูลไปอยู่ใน Subtitle ให้ส่วนหัวสะอาดตา
   - ตรวจจับและถอดป้ายแคปซูลตกแต่งที่ไม่จำเป็น (Gratuitous Pill Tags) เช่น Tag ช่วงอายุ `[ 13-45 ]` หรือป้ายกลุ่มเป้าหมายที่แปะข้างตัวเลขอายุในตารางและใน Modal ออก แสดงเฉพาะตัวเลขอายุและหน่วยปีตามจริง
   - ตรวจจับและตัดตัวเลขลำดับข้อ เช่น `1.`, `2.`, `3.` ที่นำหน้าชื่อเมนูนำทาง (Sidebar/Submenu labels), ชื่อหัวข้อหน้า (`<h1>`), Page metadata title, และ Breadcrumb ออก ให้แสดงเฉพาะชื่อบริการ/รายงานที่สื่อความหมายชัดเจน และใช้ Badge ชิปแยกต่างหากหากต้องแสดงรหัสข้อ
   - ใช้ตัวแปรมาตรฐานใน `src/app/globals.css` วันที่ พ.ศ. ไทย และ Mask PHI
6. **สรุปผลการปรับปรุง:** รายงานสิ่งที่ปรับปรุงทั้งมิติ UX, Table Alignment, Spacing, และ Tokens ที่ใช้

## ข้อความในระบบ (Microcopy) & แนวทางสื่อสาร

- **สุภาพ เป็นมิตร ปลอดภัย:** ใช้ภาษาที่ให้ความรู้สึกสบายใจ เช่น "ไม่พบข้อมูลนัดหมายในระบบ หากมีข้อสงสัยกรุณาติดต่อเคาน์เตอร์เวชระเบียน" แทนที่จะขึ้นตัวหนังสือสีแดงแข็งๆ
- **ปุ่มระบุผลลัพธ์ตรงไปตรงมา:** ใช้คำกริยาที่เห็นภาพชัดเจน เช่น "ยืนยันการลงทะเบียน", "พิมพ์ใบนัดหมาย", "ย้อนกลับไปแก้ไข"
- **ตัวเลขและรหัส:** ใช้ `font-variant-numeric: tabular-nums` เสมอ เพื่อให้อ่านตัวเลขจำนวนเงิน, วันที่, และเวลาได้เป็นระเบียบตา
- **การกระทำสำคัญ:** มีหน้าต่างยืนยันที่ระบุผลกระทบเป็นภาษาคนทั่วไป และบันทึก Audit Log เสมอ
