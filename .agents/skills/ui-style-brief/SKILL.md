# สไตล์ดีไซน์ UI โรงพยาบาลเถิน และคู่มือปฏิบัติงาน (UI Style Brief)

ระบบเว็บและพอร์ทัลโรงพยาบาลเถิน (Next.js 16 App Router, React 19, CSS Modules / `page.css`, API Gateway Backend)
ตอบเป็นภาษาไทยเสมอ เว้นแต่ผู้ใช้ใช้ภาษาอื่น ข้อมูลทางเทคนิคให้สรุปเป็นตารางเพื่อความกระชับ

## เสาหลักการออกแบบ 8 ข้อ (Core Design Pillars)

1. **ชัดเจน เป็นมิตร เข้าใจง่ายต่อทุกคน (Human-Centered & Non-Tech Friendly):**
   - ผู้ใช้คือบุคลากรทางการแพทย์ที่ทำงานแข่งกับเวลา, ผู้ป่วย, และประชาชนทุกช่วงวัยรวมถึงผู้สูงอายุ
   - ออกแบบให้ **Affordance ชัดเจนโดยไม่ต้องเดา**: ปุ่มต้องดูเป็นปุ่ม, ฟิลด์กรอกมีขอบเขตชัดเจน, ตัวหนังสืออ่านง่ายตาไม่ล้า
   - ลดความกลัวในการกดผิด (Forgiving UI) มีข้อความอธิบายเป็นภาษาไทยสุภาพ ไร้ศัพท์เทคนิค (No jargon)
2. **โปร่ง โล่ง สบายตา มีระยะหายใจ (Breathing Room & Anti-Cramping):**
   - **ห้ามบีบอัดข้อมูลจนแน่นอึดอัดเด็ดขาด**: Whitespace คือเครื่องมือจัดกลุ่มความคิด ไม่ใช่ที่ว่างที่ต้องรีบยัดของลงไป
   - ใช้ระยะห่างสบายตา (Comfortable Density): Card padding 20-24px, ช่องว่างระหว่างส่วน (Section Gap) 24-32px, แถวตารางสูงอย่างน้อย 52-56px
   - หากข้อมูลมีจำนวนมาก ให้ใช้วิธีจัดกลุ่มแบบก้อนข้อมูล (Chunking) หรือเปิดดูเพิ่มเติม (Progressive Disclosure) แทนการอัดทุกอย่างในแถวเดียว
3. **ทันสมัย เรียบหรู แต่ดูอบอุ่น (Modern, Polished & Welcoming):**
   - ดีไซน์ร่วมสมัยด้วยพื้นผิวที่สะอาดสะอ้าน มนละมุน (`border-radius: 12-16px`), เส้นขอบบางเบาเป็นระเบียบ (`var(--gray-200)`), และเงานุ่มลึกเป็นธรรมชาติ (`var(--shadow-card)`, `var(--shadow-hover)`)
   - ไม่แบนราบแข็งทื่อเหมือนแบบฟอร์มราชการยุคเก่า และไม่เยอะฟุ้งแบบ AI slop (ไม่มี Gradient แฟนซีม่วง-น้ำเงิน หรือ Glassmorphism เลอะเทอะ)
4. **ไอคอนนำสายตาที่มีหน้าที่ชัดเจน (Purposeful Visual Anchors):**
   - ไม่ใช้ไอคอนตกแต่งลอยๆ ไร้ความหมาย (No decorative clutter)
   - **แต่สนับสนุนการใช้ไอคอนนำสายตาและเพิ่มความเข้าใจ (Visual Anchors)** จาก `material-symbols-outlined` หรือ `lucide-react` เพื่อช่วยผู้ใช้ที่ไม่ชอบอ่านข้อความยาวๆ สแกนหน้าจอได้ทันที เช่น ไอคอนปฏิทินหน้าระบุวันที่, ไอคอนโทรศัพท์หน้าเบอร์ติดต่อ, ไอคอนแว่นขยายในช่องค้นหา, ไอคอนเตือนหน้าข้อความสำคัญ
   - **ห้ามใส่ Emoji** ในหัวข้อ เมนู หรือข้อความทางการของระบบ
5. **สีสื่อความหมายและสร้างความมั่นใจ (Semantic & Calming Colors):**
   - 1 สี = 1 ความหมาย: สีเขียวแบรนด์ (`var(--primary): #0D7446`) สื่อถึงความน่าเชื่อถือ สุขภาพ และการกระทำหลัก
   - สีสถานะอื่นใช้พื้นสีอ่อน + ตัวอักษรเข้มคอนทราสต์ ≥ 4.5:1 ตาม `references/tokens.md` พร้อมข้อความกำกับเสมอ
   - ให้ความรู้สึกสงบ ปลอดภัย ไม่ใช้สีเตือนจัดจ้านเกินความจำเป็นจนทำให้ผู้ใช้ตกใจ
6. **หนึ่งหน้า หนึ่งการกระทำหลัก (Clear Action Hierarchy):**
   - ในแต่ละมุมมองหรือการ์ด ต้องมี **ปุ่มหลัก (Primary Button) เด่นชัดเพียง 1 ปุ่ม** เพื่อให้ผู้ใช้รู้ทันทีว่าต้องกดอะไรต่อ
   - ปุ่มรองและลิงก์ช่วยเสริมอย่างกลมกลืน ไม่แย่งความเด่น
7. **ลดความซ้ำซ้อน จัดระเบียบสายตา และจัดกึ่งกลางตาราง (Smart Subtraction & Table Alignment):**
   - ข้อมูลหรือป้ายสถานะที่ซ้ำกันทุกบรรทัด ให้ย้ายขึ้นไปสรุปหรือกรองที่หัวตาราง
   - ตัดสิ่งรบกวนสายตาออก เพื่อเหลือเฉพาะข้อมูลที่ช่วยให้ตัดสินใจได้เร็วที่สุด
   - **กดดูข้อมูลผ่านแถว/Record โดยตรง (Row-Clickable Records):** ไม่ต้องสร้างคอลัมน์ "รายละเอียด/เปิดดู" หรือยัดปุ่ม Action ซ้ำๆ ทุกแถว ให้ทั้งแถว (`<tr>`) สามารถคลิกเปิดดู Modal หรือรายละเอียดเชิงลึกได้โดยตรง (`cursor: pointer`, hover feedback ชัดเจน) ช่วยประหยัดพื้นที่คอลัมน์และลดความรกของ UI
   - **ไม่ต้องมีปุ่มคัดลอกในเซลล์ตาราง (No In-Cell Copy Clutter):** ไม่ต้องใส่ปุ่มไอคอน Copy ข้าง HN หรือเลขบัตรประชาชนทุกบรรทัด ให้แสดงตัวเลขชัดเจนด้วย `tabular-nums` หากต้องการคัดลอก ผู้ใช้สามารถคลิกดูในหน้าต่างรายละเอียด (Detail Modal) หรือไฮไลต์ข้อความได้เอง ลด Visual Clutter ในตาราง
   - **จัดข้อมูลในตารางให้ตรงกลางหัวข้อเสมอ (Table Column Harmony):** ข้อมูลในเซลล์ (`<td>`) ต้องจัดแสดงตรงกลางของหัวข้อ (`<th>`) เป็นมาตรฐานหลักสำหรับข้อมูลส่วนใหญ่ (ลำดับ, วันที่, เวลา, รหัส/HN, เลขบัตรประชาชน, ป้ายสถานะ Badge, จำนวนนับ) ป้องกันปัญหาข้อมูลเอียงริมซ้ายริมขวาสะเปะสะปะ โดยหัวข้อ `<th>` และเซลล์ `<td>` ในคอลัมน์เดียวกันต้องมี Alignment ตรงกัน 100% เสมอ
8. **เคารพมาตรฐานโรงพยาบาลและความปลอดภัย (Hospital Standards & Safety):**
   - วันที่ต้องเป็น **พ.ศ. ไทย** เสมอ (เช่น "1 พ.ย. 2569")
   - ข้อมูลสุขภาพและตัวบุคคล (PHI) ต้อง Masking แสดงเฉพาะ 4 ตัวท้าย (เช่น `x-xxxx-xxxxx-xx-1` หรือ `•••1234`)
   - ขนาดเป้าสัมผัส (Touch Target) ทุกจุดบนมือถือและจอสัมผัสต้องกว้างและสูงอย่างน้อย **44-48px**
   - คอนทราสต์ตัวอักษรทุกจุด ≥ 4.5:1 (ระดับ AA)

## ขั้นตอนโหมด A (ออกแบบต้นแบบ: Prototype)

1. **ทำความเข้าใจผู้ใช้และบริบท:** ผู้ใช้เป็นใคร (ผู้ป่วย/ผู้สูงอายุ/พยาบาล/จนท.), เข้ามาทำอะไร, อุปกรณ์หลักคืออะไร (มือถือ/แท็บเล็ต/คอมพิวเตอร์หน้างาน)
2. **วินิจฉัยจุดบกพร่องเดิม:** ระบุจุดที่อึดอัด บีบแน่น สีสับสน ข้อมูลตารางเอียงริมซ้ายริมขวา หรือยากต่อคนไม่เก่งเทคโนโลยี
3. **กำหนดการจัดวางแบบโปร่งสบาย (Breathing Room Layout):**
   - กำหนด Spacing, Card padding, Table row height ให้โปร่งตา สบายใจ
   - กำหนด Alignment ตารางให้ข้อมูลอยู่ตรงกลางหัวข้อ (Center-aligned standard)
   - วาง Visual hierarchy: Header โปร่งชัดเจน → สรุปสถานะที่เข้าใจง่าย → ตัวกรอง/ค้นหา → เนื้อหาหลัก
4. **ใส่ Affordance & Visual Anchors:**
   - ใช้ปุ่มที่เห็นขอบเขตชัดเจน กดง่าย
   - ใส่ไอคอนนำสายตาประกอบข้อความสำคัญเพื่อช่วยการสแกนเร็ว
5. **สร้างความพร้อมรองรับทุกสถานะ (States):**
   - ว่าง (Empty State): อธิบายอย่างเป็นมิตรพร้อมปุ่มเริ่มต้นที่ชัดเจน
   - กำลังโหลด: Skeleton โทนเทาอ่อนขนาดเท่ากล่องจริง ไม่กระตุกตา
   - ข้อผิดพลาด: ภาษาเข้าใจง่าย ปลอบประโลม ไม่โทษผู้ใช้ พร้อมปุ่มลองใหม่
6. **ตรวจทาน:** ตรวจสอบตาม `references/review-checklist.md` และส่งมอบไฟล์ Interactive Prototype + Spec `.md`

## ขั้นตอนโหมด B (เขียน Brief สั่ง AI)

1. ดึงโครงจาก `references/brief-template.md`
2. เติมบริบทระบบโรงพยาบาลเถิน: กลุ่มผู้ใช้ (เน้นย้ำหากมีผู้ใช้ที่ไม่คุ้นเคยกับเทคโนโลยีหรือผู้สูงอายุ)
3. กำชับกฎ: Modern & Welcoming, มีระยะหายใจ (ห้ามบีบอัดข้อมูล), จัดข้อมูลในตารางให้ตรงกลางหัวข้อเสมอ (ห้ามเอียงริมซ้ายริมขวาสะเปะสะปะ), Affordance ชัดเจน, ห้าม AI Slop/Emoji, วันที่ พ.ศ. ไทย, PHI Masking
4. กำหนดผลลัพธ์: Interactive Prototype พร้อม Design Spec

## ขั้นตอนโหมด C (ตรวจสอบ & Refactor โค้ดจริง)

1. **สำรวจโค้ดและวัดความอึดอัด:** เปิดดู `page.tsx` และ CSS เช็คดูว่า padding/gap แคบเกินไปหรือไม่, ตัวหนังสือติดกันเป็นพืดหรือไม่
2. **ปรับ Spacing & Padding:** ขยายพื้นที่หายใจ ใช้ตัวแปร `--space-*`, ปรับความสูงแถวตารางเป็น ≥ 52px, ปรับ padding การ์ดเป็น 20-24px
3. **จัดระเบียบตารางและ Alignment (Fix Ragged Table Alignment & Reduce Row Clutter):**
   - ตรวจสอบ `<th>` และ `<td>` ในแต่ละคอลัมน์ให้มี `text-align` สอดคล้องตรงกันเสมอ
   - ปรับคอลัมน์ลำดับ, วันที่, เวลา, รหัส/HN, เลขบัตรประชาชน, ป้ายสถานะ Badge, จำนวนนับ ให้จัดแสดงตรงกลางหัวข้อ (`text-align: center`)
   - แก้ไขปัญหาข้อมูลเอียงริมซ้ายริมขวาไม่ตรงกับหัวข้อ จัด Badge ให้อยู่กึ่งกลางเซลล์ (`justify-content: center; margin: 0 auto;`)
   - ปรับการเปิดดูข้อมูลให้กดผ่าน Record/แถวโดยตรง (`cursor: pointer`) แทนการเพิ่มคอลัมน์ปุ่มเปิดดูซ้ำซ้อน
   - ตัดปุ่มไอคอนคัดลอก (Copy button) ที่รกสายตาในเซลล์ตารางออก แสดงตัวเลขด้วย `tabular-nums` อย่างเป็นระเบียบตา เลขบัตรประชาชน (CID) ไม่ต้องใส่ตัวคั่นขีด (Hyphen) ให้แสดงตัวเลขติดกันตามจริง เพื่อความสะดวกในการคัดลอกหรือค้นหาต่อ
4. **ยกระดับ Affordance & Accessibility:**
   - เช็คขนาดปุ่ม (Touch Target ≥ 44-48px)
   - เพิ่ม Focus ring และ Hover transitions ที่นุ่มนวล
   - แทนที่ข้อความห้วนหรือศัพท์เทคนิคด้วย Microcopy ภาษาไทยที่สุภาพ เป็นมิตร
5. **ล้าง AI Slop และควบคุมโทนสี:** ใช้ตัวแปรมาตรฐานใน `src/app/globals.css` วันที่ พ.ศ. ไทย และ Mask PHI
6. **สรุปผลการปรับปรุง:** รายงานสิ่งที่ปรับปรุงทั้งมิติ UX, Table Alignment, Spacing, และ Tokens ที่ใช้

## ข้อความในระบบ (Microcopy) & แนวทางสื่อสาร

- **สุภาพ เป็นมิตร ปลอดภัย:** ใช้ภาษาที่ให้ความรู้สึกสบายใจ เช่น "ไม่พบข้อมูลนัดหมายในระบบ หากมีข้อสงสัยกรุณาติดต่อเคาน์เตอร์เวชระเบียน" แทนที่จะขึ้นตัวหนังสือสีแดงแข็งๆ
- **ปุ่มระบุผลลัพธ์ตรงไปตรงมา:** ใช้คำกริยาที่เห็นภาพชัดเจน เช่น "ยืนยันการลงทะเบียน", "พิมพ์ใบนัดหมาย", "ย้อนกลับไปแก้ไข"
- **ตัวเลขและรหัส:** ใช้ `font-variant-numeric: tabular-nums` เสมอ เพื่อให้อ่านตัวเลขจำนวนเงิน, วันที่, และเวลาได้เป็นระเบียบตา
- **การกระทำสำคัญ:** มีหน้าต่างยืนยันที่ระบุผลกระทบเป็นภาษาคนทั่วไป และบันทึก Audit Log เสมอ
