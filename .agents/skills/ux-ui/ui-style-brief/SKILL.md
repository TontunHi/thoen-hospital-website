# สไตล์ดีไซน์ UI โรงพยาบาลเถิน และคู่มือปฏิบัติงาน (UI Style Brief)

ระบบเว็บและพอร์ทัลโรงพยาบาลเถิน (Next.js 16 App Router, React 19, CSS Modules / `page.css`, API Gateway Backend)
ตอบเป็นภาษาไทยเสมอ เว้นแต่ผู้ใช้ใช้ภาษาอื่น ข้อมูลทางเทคนิคให้สรุปเป็นตารางเพื่อความกระชับ

---

## 3 โหมดการทำงาน

| โหมด | ใช้เมื่อ | สิ่งที่ทำ |
|---|---|---|
| **A. ออกแบบต้นแบบ** | ผู้ใช้ส่งภาพหน้าเดิม หรือสั่งให้ออกแบบหน้าใหม่ / ปรับ mockup | ส่งต้นแบบ UI ที่กดได้ (interactive prototype) + ไฟล์ spec `.md` |
| **B. เขียน Brief สั่ง AI** | ผู้ใช้ขอ prompt / brief / instructions สำหรับส่งต่อให้ AI ออกแบบ | กรอก `references/brief-template.md` ด้วยบริบทจริงของระบบโรงพยาบาล |
| **C. ตรวจสอบ & Refactor โค้ดจริง** | ผู้ใช้ให้ตรวจหรือปรับปรุงหน้าเว็บที่มีโค้ดอยู่แล้วในโปรเจกต์ (`src/app/**`) | ตรวจจับ AI slop, ลบส่วนเกิน, ปรับ CSS variables และ microcopy ให้ตรงสไตล์ในโค้ดจริง |

---

## หลักการ 7 ข้อ (ห้ามละเมิดโดยไม่บอกเหตุผล)

1. **ข้อมูลมาก่อนการตกแต่ง (Information Over Decoration):** ผู้ใช้ (แพทย์, พยาบาล, เจ้าหน้าที่) เข้ามาเพื่อทำงาน จัดลำดับความสำคัญของข้อมูลตามลำดับการตัดสินใจ ไม่ใช่ความสวยงาม
2. **ไม่มีไอคอนตกแต่ง (No Decorative Icons):** ค่าเริ่มต้นคือไม่ใส่ไอคอนเลย อนุญาตเฉพาะไอคอนเชิงฟังก์ชันที่มีความหมายสากลชัดเจน (เช่น ปุ่มค้นหา, ปุ่มปิด, สลับมุมมอง) จาก `lucide-react` หรือ `material-symbols-outlined` ห้ามใส่ไอคอนหน้าการ์ดทุกใบ และ**ห้ามใส่ Emoji** ในหัวข้อหรือข้อความ UI เด็ดขาด
3. **สีสื่อความหมาย 1 สี = 1 ความหมาย:** สีแบรนด์หลัก (`var(--primary): #0D7446`) ใช้กับปุ่มหลักและสถานะ Active เท่านั้น สีสถานะอื่นใช้พื้นอ่อน + ตัวอักษรเข้มคอนทราสต์ ≥ 4.5:1 ตาม `references/tokens.md` และต้องมีข้อความบอกความหมายเสมอ ห้ามใช้สีตกแต่งสุ่ม
4. **หนึ่งหน้า หนึ่งการกระทำหลัก (One Primary Action):** ในแต่ละแถวหรือการ์ด มีปุ่มหลักไม่เกิน 1 ปุ่ม + ลิงก์ข้อความรองไม่เกิน 1 จุด ส่วนที่เหลือเปิดดูในหน้ารายละเอียดหรือคลิกที่ชื่อ
5. **ตัดของซ้ำ (Subtraction Pass):** ข้อมูลที่ซ้ำกันทุกแถว (เช่น ป้ายสถานะเหมือนกันหมด, ปีงบประมาณ, ชื่อหน่วยงาน) ให้ย้ายไปไว้ที่ตัวกรองหรือหัวตาราง ห้ามแสดงซ้ำทุกบรรทัด
6. **แก้ปัญหาโครงสร้างจริง รองรับ Edge Cases:** ออกแบบรองรับกรณีขอบเสมอ (ข้อมูลว่าง 0 รายการ, ข้อมูลยาวล้น, คะแนน/ลำดับเท่ากัน, ข้อมูล 100+ แถว) และมีสถานะ ว่าง/กำลังโหลด (Skeleton)/เกิดข้อผิดพลาด ครบถ้วน
7. **ไม่ดู AI slop และเคารพมาตรฐานโรงพยาบาล:** ตรวจสอบตาม `references/review-checklist.md` ทุกครั้ง:
   - วันที่ต้องเป็น **พ.ศ. ไทย** เสมอ (เช่น "1 พ.ย. 2569")
   - ข้อมูลระบุตัวตนผู้ป่วย/บุคลากร (PHI) ต้อง Masking แสดงเฉพาะ 4 ตัวท้าย (เช่น เลขบัตร `x-xxxx-xxxxx-xx-1`)
   - ขนาดเป้าสัมผัส (Touch Target) บนมือถือ ≥ 44px
   - คอนทราสต์ตัวอักษรทุกจุด ≥ 4.5:1

## ขั้นตอนโหมด A (ออกแบบต้นแบบ)

1. **ทำความเข้าใจงาน:** ผู้ใช้คือใคร (คนไข้ / จนท. / แอดมิน), เข้ามาทำอะไร, อุปกรณ์หลัก (คอมฯ / มือถือ PWA), ข้อมูลที่ต้องคงไว้ ดึงจากบริบทให้มากที่สุด ถามเพิ่มเท่าที่จำเป็น (ไม่เกิน 1 คำถาม)
2. **ระบุปัญหาหน้าเดิม:** ชี้ชัดเป็นข้อๆ ที่ตรวจสอบได้ ("ตารางล้นจอแนวนอนบนมือถือ", "ปุ่มกดยืนยันกับยกเลิกสีเขียวเหมือนกัน")
3. **รอบตัด (Subtraction Pass):** ระบุสิ่งที่ตัดออกพร้อมเหตุผล ก่อนเริ่มเพิ่มสิ่งใหม่
4. **จัดลำดับชั้นข้อมูล:** ข้อมูลระดับ 1 (เห็นทันที 3 วินาทีแรก), ระดับ 2 (เห็นเมื่อสนใจ/คลิกขยาย), ระดับ 3 (ย้ายไปหน้ารายละเอียด)
5. **ดึง Token & Component:** ใช้ตัวแปร CSS จาก `references/tokens.md` และโครงสร้างจาก `references/components.md`
6. **สร้างต้นแบบ:** จัดการ Tab, Search, Filter ให้กดทดสอบได้จริง ส่วนที่ไม่มีข้อมูลสดให้ใส่ placeholder ที่ติดป้ายชัดเจน
7. **เขียน Spec `.md`:** ตามโครงใน `references/spec-template.md` (ตารางสรุปการเปลี่ยนแปลง, ฟิลด์ API, ข้อยกเว้น)
8. **ตรวจทาน:** ตรวจด้วย `references/review-checklist.md` ก่อนส่งมอบ

---

## ขั้นตอนโหมด B (เขียน Brief สั่ง AI)

1. ดึงโครงจาก `references/brief-template.md`
2. เติมบริบทจริงของระบบโรงพยาบาลเถิน: Stack (Next.js 16 + React 19 + CSS Modules), ผู้ใช้งาน, ข้อจำกัดทางสิทธิ์
3. กำชับกฎเหล็ก: ห้ามใส่ Emoji, ห้ามไอคอนตกแต่ง, ห้าม Gradient ม่วง-น้ำเงิน, 1 สี = 1 ความหมาย, วันที่ พ.ศ. ไทย
4. ระบุผลลัพธ์ที่ต้องการ (Interactive Prototype + Design Spec Markdown)

---

## ขั้นตอนโหมด C (ตรวจสอบ & Refactor โค้ดจริง)

1. **สำรวจโค้ดเดิม:** อ่านไฟล์ `page.tsx` และไฟล์สไตล์ (`page.css` หรือ `.module.css`) ของหน้านั้นๆ
2. **วินิจฉัยจุดที่หลุดสไตล์:**
   - มีไอคอนตกแต่งที่ไม่จำเป็นหรือไม่? ถ้ามี ให้ตัดออก
   - มี Emoji หรือสีสุ่มที่ไม่มีความหมายหรือไม่?
   - วันที่แสดงเป็น ค.ศ. หรือ พ.ศ.? มีการ Mask PHI หรือไม่?
   - ใช้ Hardcoded color หรือใช้ CSS variables (`var(--primary)`, `var(--gray-*)`)?
3. **Subtraction & Refactor:**
   - ปรับโค้ดให้สั้น ตรงไปตรงมา (Ponytail style) ไม่เพิ่ม Abstraction เกินจำเป็น
   - แทนที่ inline style หรือสีแปลกปลอมด้วยตัวแปรมาตรฐานใน `src/app/globals.css`
   - ปรับปุ่มให้มีการกระทำหลักเด่นชัด (Primary 1 ปุ่ม) และเพิ่มสถานะ Empty/Loading/Error
4. **สรุปผล:** รายงานผลเป็นตารางสั้นๆ: "สิ่งที่ตัดออก / สิ่งที่ปรับปรุง / Token CSS ที่ใช้"

## ข้อความในระบบ (Microcopy) & มาตรฐานโรงพยาบาล

- **ภาษาไทยเป็นหลัก:** ใช้ศัพท์ที่บุคลากรทางการแพทย์และโรงพยาบาลเข้าใจตรงกัน (เช่น "นัดหมาย", "ส่งตรวจ", "จำหน่าย", "เวชระเบียน")
- **ปุ่มระบุการกระทำชัดเจน:** ขึ้นต้นด้วยกริยา เช่น "บันทึกข้อมูล", "ยืนยันการรับงาน", "ยกเลิกคำขอ" (ไม่ใช้ "ตกลง" หรือ "คลิกที่นี่" ลอยๆ)
- **ตัวเลขสถิติและตาราง:** ใช้ `font-variant-numeric: tabular-nums` เสมอ เพื่อให้ตัวเลขตรงหลัก อ่านง่าย
- **การกระทำที่มีความเสี่ยง (Destructive/State Transitions):** ปรับสถานะสำคัญหรือลบข้อมูล ต้องมีข้อความยืนยันผลกระทบชัดเจน และเชื่อมโยงกับการบันทึก Audit Log เสมอ
