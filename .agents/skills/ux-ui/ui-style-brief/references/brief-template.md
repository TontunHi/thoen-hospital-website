# เทมเพลต brief สำหรับสั่ง AI ออกแบบ (โหมด B)

กรอกให้ครบด้วยบริบทจริง อย่าส่งเทมเพลตเปล่าให้ผู้ใช้ ถ้าขาดข้อมูลส่วนไหนให้ใส่ [วงเล็บ] เฉพาะส่วนที่ผู้ใช้ต้องเติมเอง

## เทมเพลตหลัก

```
ช่วยออกแบบหน้า [ชื่อหน้า] ใหม่ (แนบภาพหน้าเดิม)

บริบท
- หน้านี้ใช้ทำ: [หน้าที่]
- ผู้ใช้: [ใคร] ใช้ผ่าน [มือถือ/คอม] (PWA)
- ระบบ: [stack หน้าบ้าน] + NestJS

ปัญหาของหน้าเดิม (ระบุที่ตรวจสอบได้)
- [ข้อ 1]
- [ข้อ 2]

ต้องการ
- โทน: modern, ใช้งานง่าย, สบายตา
- สี: [สี accent หลัก] พื้นขาว/เทาอ่อน สีอื่นใช้เมื่อสื่อความหมายเท่านั้น 1 สี = 1 ความหมาย
- ต้องคงไว้: [ฟีเจอร์/ข้อมูลที่ห้ามหาย]

ห้าม
- ไอคอนที่ไม่จำเป็น, emoji
- gradient, glow, เงาหนา, ขอบสีด้านซ้ายของการ์ด
- ป้ายสีซ้ำทุกแถว, การ์ดสถิติแยกหลายใบโดยไม่จำเป็น
- ตัดชื่อด้วย "..."
- หน้าตาแบบเทมเพลตสำเร็จรูป

ให้ทำด้วย
- รองรับกรณีขอบ: [คะแนนเท่ากัน / ว่าง / ชื่อยาว / ข้อมูลเยอะ]
- ออกแบบสถานะ ว่าง/โหลด/ผิดพลาด
- ข้อมูลในต้นแบบใช้ของจริงจากภาพ ส่วนที่ไม่มีให้ใส่ placeholder ติดป้ายชัด
- ปุ่มหลักต่อแถวไม่เกิน 1

ผลลัพธ์ที่ต้องการ
- ต้นแบบที่กดได้ (แท็บ ค้นหา ตัวกรองทำงานจริง)
- ไฟล์ spec .md แบบตาราง: ปัญหาเดิม/วิธีแก้, โครงสร้าง, กติกา, สี, responsive, accessibility, ฟิลด์ API ที่ต้องใช้, สิ่งที่ตัดออกพร้อมเหตุผล, หมายเหตุต้นแบบ
- บอกตรง ๆ ว่าอะไรเป็น placeholder และอะไรยังไม่ได้ทำ
```

## ส่วนเสริม: ขอเพิ่มสีสัน

```
ตอนนี้หน้านี้ดูเป็นตัวหนังสือล้วน เข้าใจยาก ช่วยเพิ่มสีสัน

เป้าหมาย: ให้ผู้ใช้แยกประเภทข้อมูลได้ในแวบเดียว ไม่ต้องอ่านทุกบรรทัด

ข้อมูลที่ต้องแยกด้วยสี
- [ประเภท 1]
- [ประเภท 2]
- [สถานะเสี่ยงที่ต้องเตือน]

กติกา
- 1 สี = 1 ความหมาย ห้ามสีตกแต่ง
- สี accent หลักใช้กับสิ่งที่เลือกอยู่และปุ่มหลักเท่านั้น
- สีอื่นเป็นพื้นอ่อน + ตัวอักษรเข้มโทนเดียวกัน คอนทราสต์ ≥ 4.5:1 มีตัวอักษรกำกับทุกครั้ง
- สีชมพู/แดงเฉพาะความเสี่ยง
- ถ้ามีเกิน 2 ความหมายให้ใส่แถบ legend

ให้เพิ่ม: ตัวเลขสรุปเป็นช่องสี, หัวข้อย่อยตัวหนา, ปรับต้นแบบเดิมไม่ออกแบบใหม่ทั้งหน้า
ผลลัพธ์: ตารางสีทุกตัว (ความหมาย/พื้น/ตัวอักษร/ใช้ที่) และอัปเดต spec .md
```

## ตารางอธิบาย (แนบท้าย brief เมื่อผู้ใช้อยากรู้เหตุผล)

| ข้อความใน brief | ป้องกันปัญหา |
|---|---|
| ปัญหาที่ตรวจสอบได้ | AI แก้โครงสร้างจริง ไม่ใช่แค่ทาสี |
| รายการห้ามชัดเจน | ตัดของที่ AI ชอบใส่เองได้ตรงที่สุด |
| 1 สี = 1 ความหมาย | ไม่ให้สีสุ่มแล้วต้องเดา |
| รองรับกรณีขอบ | หน้าไม่พังเมื่อข้อมูลไม่เป็นไปตามตัวอย่าง |
| placeholder ติดป้าย | ไม่ให้ข้อมูลที่แต่งขึ้นดูเหมือนจริง |
| ขอ spec .md คู่ต้นแบบ | เอาไปให้ทีมต่อยอดหรือแปลงเป็นโค้ดได้ |
| ปรับต้นแบบเดิม | กันไม่ให้โครงสร้างที่ชอบแล้วถูกเปลี่ยน |

## เทคนิคแก้ทีละรอบ

| สถานการณ์ | ควรพูด |
|---|---|
| ไม่ชอบบางอย่าง | บอกชื่อสิ่งนั้นและเหตุผล ("สีม่วงกับชมพูใกล้เกินไป แยกยาก") ไม่ใช่ "ไม่สวย" |
| อยากเรียบขึ้น | "ใช้สีให้น้อยที่สุด เฉพาะส่วนที่ผู้ใช้ต้องตัดสินใจ" |
| อยากสดขึ้น | "เพิ่มความอิ่มตัวของพื้นอ่อน แต่ตัวอักษรยังคอนทราสต์ ≥ 4.5:1" |
| อยากมีโหมดมืด | "ทำชุดสีโหมดมืดคู่กัน คงความหมายสีเดิมทุกตัว" |
| อยากได้โค้ด | ระบุ stack หน้าบ้านและให้ใช้ข้อมูลโครงสร้างเดียวกับ API จริง |
