# รูปแบบคอมโพเนนต์

## โครงหน้ามาตรฐาน

| ลำดับ | ส่วน |
|---|---|
| 1 | ลิงก์กลับ (ข้อความ "← กลับ...") |
| 2 | h1 + คำอธิบาย 1-2 บรรทัด + ปุ่มหลักของหน้า (ชิดขวา) |
| 3 | แถบสรุป (ถ้ามี): ตัวเลขเด่นเป็นช่อง ไม่ใช่การ์ดแยกหลายใบ |
| 4 | แถบเครื่องมือ: แท็บ (ซ้าย) + ค้นหา + ตัวกรอง (ขวา) |
| 5 | เนื้อหาหลัก (ตาราง/รายการ) จัดกลุ่มตามความหมาย |

## คอมโพเนนต์

| คอมโพเนนต์ | กติกา |
|---|---|
| ปุ่มหลัก | พื้น accent ตัวอักษรขาว สูง 44px 1 ปุ่ม/พื้นที่ |
| ปุ่มรอง | พื้นขาว ขอบ border-input หรือพื้น accent-tint |
| ลิงก์ข้อความ | สี accent สูง 44px (พื้นที่กด) ใช้กับการกระทำรอง |
| แท็บ | แบบ segmented (พื้น track `#eef1ee`) หรือขีดเส้นใต้ 2px accent ใช้ `<button aria-pressed>` ใส่จำนวนหลังชื่อ |
| ช่องค้นหา | `input[type=search]` placeholder บอกว่าค้นอะไรได้ กรอง live ไม่ต้องกด Enter ไม่มีไอคอนแว่นขยาย |
| ตาราง | หัวตาราง 13px muted พื้น surface-alt ตัวเลขชิดขวา tabular-nums แถวสูง ≥ 48px ห่อด้วย `overflow-x:auto` เพื่อมือถือ แถวเด่นใช้พื้น accent-row ไม่ใช้ป้ายสีซ้ำทุกแถว |
| รายการจัดกลุ่ม | หัวกลุ่มเล็กสีเทา (หรือป้ายพื้นอ่อน) การ์ดขาว 1 ใบต่อกลุ่ม |
| ชิป (แท็ก) | มุม 8px พื้นอ่อนตามประเภท มีปุ่ม × ถ้าลบได้ (`aria-label` ระบุชื่อ) |
| ป้ายสถานะ | แสดงเฉพาะสถานะที่ต่างจากส่วนใหญ่ ("กำลังจัดงาน") ไม่แสดงสถานะที่เหมือนกันทุกแถว |
| ช่องสรุป | ตัวเลข 26-28px + หน่วยเล็ก + ป้ายกำกับ รวมในแถบเดียวคั่นด้วยเส้น หรือเป็นช่องสีตามประเภท |
| ฟอร์ม | ป้ายกำกับอยู่เหนือช่องเสมอ (ไม่ใช้ placeholder แทนป้าย) ข้อผิดพลาดเป็นข้อความใต้ช่องสีชมพูเข้ม บอกวิธีแก้ ปุ่มส่งอยู่ท้ายฟอร์มชิดซ้าย |
| Select | native `<select>` สูง 44px เว้นแต่ต้องการตัวเลือกซับซ้อน |
| Modal/ยืนยัน | ใช้เมื่อเป็นการกระทำที่ย้อนไม่ได้เท่านั้น ปุ่มระบุการกระทำ ("ลบกิจกรรม") ไม่ใช้ "ตกลง/ยกเลิก" |

## สถานะที่ต้องออกแบบทุกครั้ง

| สถานะ | สิ่งที่ต้องมี |
|---|---|
| ว่าง (empty) | ข้อความบอกสาเหตุ + ทางไปต่อ |
| ไม่พบผลค้นหา | ข้อความ "ไม่พบ..." ที่ตรงกับเงื่อนไข |
| กำลังโหลด | โครงเทา (skeleton) ขนาดเท่าของจริง ไม่ใช้ spinner ใหญ่ |
| ผิดพลาด | ข้อความบอกว่าเกิดอะไร + ปุ่มลองใหม่ |
| ข้อมูลยาว | ชื่อยาวขึ้นบรรทัดใหม่ ไม่ตัด |
| กรณีขอบ | คะแนนเท่ากัน, 0 รายการ, 1 รายการ, 100+ รายการ (pagination/โหลดเพิ่ม) |
| ปิดใช้งาน | จางลง + บอกเหตุผลถ้าเป็นเรื่องสิทธิ์ (หรือซ่อนทั้งปุ่ม ถ้าผู้ใช้ไม่มีสิทธิ์เลย) |

## การกระทำที่เสี่ยง (ถอนสิทธิ์ ลบ ปิดระบบ)

- แสดงผลกระทบเป็นภาษาคน ("จะถอนสิทธิ์ของ นาย ... ทันที")
- มีขั้นตอนยืนยัน หรือปุ่ม "เลิกทำ" ชั่วคราว
- ฝั่งระบบควรบันทึก audit log (ใครเปลี่ยนอะไรของใคร เมื่อไหร่)
- สีชมพูเข้มใช้เฉพาะจุดนี้

## มือถือ / PWA

| ข้อ | กติกา |
|---|---|
| ออกแบบจากมือถือก่อน | ใช้ flex-wrap / grid auto-fill ไม่ใช้ breakpoint เยอะ |
| เป้าสัมผัส | ≥ 44px |
| safe area | เว้น `env(safe-area-inset-*)` สำหรับแถบติดขอบจอ |
| ตารางกว้าง | เลื่อนแนวนอนในกล่องของตัวเอง หรือเปลี่ยนเป็นรายการการ์ดบนมือถือ |
| น้ำหนัก | ไม่ใช้รูปใหญ่/ฟอนต์เพิ่มโดยไม่จำเป็น มี fallback ฟอนต์ |
| offline | ถ้าหน้าเป็นข้อมูลสด ให้บอกสถานะเมื่อออฟไลน์ |

## ความหนาแน่น

| ประเภทหน้า | แนวทาง |
|---|---|
| หน้าบุคลากรทั่วไป (member) | โปร่ง อ่านง่าย แถว ≥ 56px |
| หน้าแอดมิน (settings, สิทธิ์) | แน่นขึ้นได้ แต่ต้องมีหัวข้อย่อยชัด แยกกลุ่มด้วยสี/ช่องว่าง และมี legend |
