# 🏥 Thoen Hospital Web Application (ระบบเว็บไซต์โรงพยาบาลเถิน)

ยินดีต้อนรับสู่ระบบสารสนเทศและเว็บไซต์หลักของ **โรงพยาบาลเถิน อำเภอเถิน จังหวัดลำปาง** 
ระบบนี้พัฒนาขึ้นเพื่อให้บริการประชาชนและบุคลากรภายในโรงพยาบาลด้วยเทคโนโลยีที่ทันสมัย ปลอดภัย และมีประสิทธิภาพสูง

---

## 🚀 คุณลักษณะสำคัญของระบบ (Key Features)

### 👥 บริการสำหรับประชาชน (Public Services)
* **ข่าวสารและประชาสัมพันธ์ (CMS):** ติดตามข่าวสาร กิจกรรมสุขภาพ และประกาศรับสมัครงาน พร้อมแบนเนอร์ภาพสไลด์ที่หน้าแรก
* **ระบบตรวจสอบวันนัดหมายแพทย์ (/check-date):** ตรวจสอบวันนัดแพทย์ล่วงหน้าได้ด้วยตนเองโดยใช้เลขบัตรประจำตัวประชาชน 13 หลัก
  * *ความปลอดภัยด้านข้อมูล (Data Privacy):* ระบบจะปกปิดข้อมูลอ่อนไหว (เช่น บดบังตัวอักษรบางส่วนของชื่อและนามสกุล) และจำกัดการเข้าถึงเพื่อป้องกันความเป็นส่วนตัวของคนไข้

### 🔐 บริการสำหรับบุคลากร (Staff Portal)
* **ระบบล็อกอินแบบไร้รหัสผ่าน (OTP-Based Authentication):** เข้าสู่ระบบผ่านเลขบัตรประชาชน โดยรหัส OTP (6 หลัก) จะถูกส่งตรงไปยังอีเมลส่วนตัวของบุคลากรที่ลงทะเบียนไว้ในระบบอย่างปลอดภัย
* **ระบบใบขอสั่งผลิตสื่อและงานประชาสัมพันธ์ (PR Order Workflow):** บุคลากรสามารถส่งคำขอผลิตสื่อ เลือกขนาด รูปแบบงาน และช่องทางเผยแพร่ผ่านฟอร์มออนไลน์
* **ระบบอนุมัติเอกสารและลงนามดิจิทัล (Digital Signature):** หัวหน้ากลุ่มงานและผู้อำนวยการสามารถตรวจสอบใบขอสั่งผลิตสื่อ ลงลายเซ็นดิจิทัลผ่านหน้าจอ และแปลงเป็นใบอนุมัติสั่งงานขนาด A4 สำหรับพิมพ์ได้ทันที
* **สลิปเงินเดือนออนไลน์ (Salary Slip SSO):** เชื่อมโยงระบบบุคลากรเข้ากับฐานข้อมูลบัญชีเงินเดือนภายนอก ช่วยให้บุคลากรตรวจสอบสลิปเงินเดือนและค่าตอบแทนการปฏิบัติงานนอกเวลา (OT) ย้อนหลังได้อย่างสะดวกและปลอดภัย
* **ระบบแสดงผลห้องฉุกเฉินเรียลไทม์ (ER Live Status):** แสดงสถานะผู้ป่วยฉุกเฉินปัจจุบัน จำแนกตามระดับความเร่งด่วน (Triage Colors)
  * *โหมดแสดงผลบนหน้าจอทีวี (TV Mode):* หน้าจอพิเศษสำหรับเปิดจอทีวีแสดงผลค้างไว้ในแผนก โดยจะซ่อนเมนูที่ไม่จำเป็นและดึงข้อมูลอัปเดตแบบเรียลไทม์โดยอัตโนมัติ
* **การจัดการโปรไฟล์ส่วนตัว (Profile Avatar Management):** รองรับการอัปโหลดและเปลี่ยนรูปโปรไฟล์ของตนเองผ่าน Dashboard พร้อมระบบย่อขนาดและบันทึกภาพลงพื้นที่จัดเก็บส่วนตัว
* **ระบบแจ้งเตือนงานอนุมัติอัจฉริยะ (Smart Approvals Notification):**
  * **Navbar Bell (`🔔`):** กระดิ่งแจ้งเตือนพร้อมตัวเลขแสดงรายการงานค้างอนุมัติสีแดงสั่นเตือนเป็นจังหวะ ทั้งบน Desktop และ Mobile
  * **In-App Toast:** กล่องข้อความสไลด์แจ้งเตือนแบบ Glassmorphism ด้านมุมขวาบนเมื่อมีงานใหม่เข้ามาขณะใช้งาน
  * **Browser Native Push:** ส่งการแจ้งเตือนไปยัง Notification System ของ OS โดยตรงแม้จะสลับไปทำงานที่แท็บหรือแอปพลิเคชันอื่น
  * **Dynamic Document Title:** เปลี่ยนข้อความแท็บบราวเซอร์อัตโนมัติเพื่อสะท้อนจำนวนงานค้าง (เช่น `(3) งานรออนุมัติ | โรงพยาบาลเถิน`) เมื่อผู้ใช้เปิดหน้าจออื่นค้างไว้

## 🛠️ เทคโนโลยีหลักที่ใช้พัฒนา (Tech Stack)

* **Framework:** [Next.js (App Router)](https://nextjs.org/) + TypeScript
* **Styling:** Vanilla CSS (ใช้สถาปัตยกรรม CSS ดั้งเดิมเพื่อประสิทธิภาพสูงสุด ความคล่องตัวในการควบคุม และขนาด Bundle ที่เล็กที่สุด)
* **Database ORM:** [Prisma Client](https://www.prisma.io/)
* **Database Systems:**
  * **Primary DB (MySQL/MariaDB):** เก็บข้อมูลโครงสร้างระบบ CMS, ข่าวสาร, สไลด์โชว์ และระบบสารสนเทศบุคลากร
  * **External DB (Read-Only Integration):** เชื่อมโยงกับฐานข้อมูลสลิปเงินเดือน (Salary) และฐานข้อมูลคนไข้/นัดหมายของโรงพยาบาล
* **Data Validation:** [Zod](https://zod.dev/) (สำหรับตรวจทาน Payload ป้อนเข้าทุกรูปแบบ)
* **Security Middleware:** HMAC-SHA256 Signatures & Next.js Middlewares สำหรับป้องกันการเปลี่ยนแปลงข้อมูล Session

## 🔒 มาตรฐานความปลอดภัยและการปกป้องข้อมูล (Security & Privacy)

> [!IMPORTANT]
> ระบบนี้ผ่านการทดสอบและวางโครงสร้างความปลอดภัยเพื่อป้องกันช่องโหว่ด้านเว็บแอปพลิเคชันในระดับสูงสุด

1. **การป้องกันเส้นทางที่ฝั่งเซิร์ฟเวอร์ (Defensive Server-side Protection):** ทุกเพจและ API ภายในระบบสมาชิก (Member Dashboard) และหน้าผู้ดูแลระบบ (Admin Panel) จะถูกตรวจสอบสิทธิ์และเซสชันที่ฝั่งเซิร์ฟเวอร์ก่อนแสดงผล (Server-side Session Validation) หากผู้ใช้อ้างอิง URL โดยตรงโดยไม่มีสิทธิ์ ระบบจะทำการ Redirect ทันทีที่ระดับเซิร์ฟเวอร์
2. **การป้องกัน SQL Injection:** การติดต่อฐานข้อมูลหลักผ่าน Prisma ORM และคำสั่ง Query ภายนอกทั้งหมด ใช้กลไก Prepared Statements และ Parameterized Queries 100% ทำให้ไม่สามารถแทรกคำสั่ง SQL แปลกปลอมได้
3. **การเก็บรักษาและแยกแยะพื้นที่ส่วนตัว (Data Isolation):** ข้อมูลอ่อนไหว เช่น ลายเซ็นอิเล็กทรอนิกส์และภาพถ่ายโปรไฟล์ จะถูกแยกจัดเก็บภายใต้โครงสร้างไดเรกทอรีส่วนบุคคลแยกตามรหัสผู้ใช้งาน (`storage/[username]/`) และจำกัดสิทธิ์การเข้าถึงผ่าน API ยืนยันตัวตนเท่านั้น
4. **ความปลอดภัยของ Session Cookie:** คุกกี้เซสชันได้รับการปกป้องด้วยการลงลายมือชื่อดิจิทัล (HMAC-SHA256) ป้องกันการสวมรอยหรือแก้ไขเนื้อหาภายในคุกกี้โดยเด็ดขาด
5. **การปิดบังข้อผิดพลาดเชิงลึก (Security Logging):** ความผิดพลาดของระบบ (Internal Errors) และ Stack Trace จะถูกบันทึกในรูปแบบไฟล์บันทึกประวัติ (Log Files) ที่ฝั่งเซิร์ฟเวอร์เท่านั้น แอปพลิเคชันจะไม่เปิดเผยรายละเอียดฐานข้อมูลหรือไฟล์ใดๆ ให้กับหน้าจอบราวเซอร์ผู้ใช้งานเพื่อป้องกันการหาช่องโหว่

## 📂 โครงสร้างโฟลเดอร์โครงการ (Directory Structure)

```text
├── prisma/                    # สคีมาและฐานข้อมูลหลัก (Prisma Database Schema)
├── public/                    # ไฟล์ Static ทั่วไปของแอป (รูปภาพ โลโก้ เอกสารสาธารณะ)
├── storage/                   # พื้นที่จัดเก็บไฟล์ส่วนบุคคล (ลายเซ็น, รูปโปรไฟล์) แยกโฟลเดอร์รายบุคคล
├── src/
│   ├── app/                   # Next.js App Router (Pages & API Routes)
│   │   ├── admin-news/        # หน้าระบบแอดมินจัดการข่าวสารและสไลด์ประชาสัมพันธ์
│   │   ├── api/               # API Endpoints (การตรวจสอบนัดหมาย, สมาชิก, เงินเดือน, โปรไฟล์)
│   │   ├── check-date/        # หน้าบริการประชาชนสำหรับเช็คตารางนัดแพทย์
│   │   ├── member/            # หน้าระบบสมาชิกบุคลากร, ส่งแบบฟอร์ม, ลงนามอนุมัติ
│   │   ├── news/              # หน้าแสดงข่าวสารและรายละเอียดข่าวสารสำหรับประชาชนทั่วไป
│   │   └── service/           # บริการพิเศษ เช่น ER Live Status (รวมทีวีโหมด)
│   ├── components/            # ส่วนประกอบ UI ส่วนกลาง (Navbar, Footer, Slideshow)
│   ├── config/                # ไฟล์ตั้งค่าที่อยู่เว็บและข้อมูลระบบภายในโรงพยาบาล
│   ├── features/              # คุณสมบัติและวิดเจ็ตเสริมย่อย
│   ├── lib/                   # โมดูลตัวช่วยส่วนกลาง (Database Connections, Session, Rate Limiter)
│   └── types/                 # การระบุประเภทข้อมูลและโครงสร้างข้อมูล (TypeScript Types)
├── middleware.ts              # Next.js Middleware คัดกรองสิทธิ์การเข้าถึงข้อมูลระบบเบื้องต้น
├── next.config.ts             # การตั้งค่า Next.js และ Security Headers
└── tsconfig.json              # กำหนดค่าการคอมไพล์ภาษา TypeScript
```

## ⚙️ ขั้นตอนการติดตั้งและทดสอบ (Getting Started)

### 1. ติดตั้ง Package และ Dependencies
รันคำสั่งต่อไปนี้ที่ไดเรกทอรีหลักของโปรเจกต์:
```bash
npm install
```

### 2. ตั้งค่าไฟล์ Environment (.env)
คัดลอกไฟล์ต้นแบบ `.env.example` ไปสร้างเป็นไฟล์ใหม่ในชื่อ `.env` และกำหนดค่าต่าง ๆ ให้ถูกต้อง:
```bash
cp .env.example .env
```
*กรุณาระบุที่อยู่ฐานข้อมูลหลัก (`DATABASE_URL`), ข้อมูลการเชื่อมต่อฐานข้อมูลภายนอก (Salary, HOSxP), ข้อมูลโฮสต์อีเมลสำหรับการส่งรหัสผ่านใช้ครั้งเดียว (OTP SMTP), และรหัสความปลอดภัยสำหรับการเข้ารหัสเซสชัน*

### 3. เตรียมฐานข้อมูลและสร้าง Prisma Client
ซิงค์โครงสร้างตารางข้อมูลเข้าสู่ฐานข้อมูลหลักของคุณ และสร้าง Client เชื่อมต่อฐานข้อมูล:
```bash
npx prisma generate
```

### 4. สตาร์ทระบบในโหมดพัฒนา (Development Mode)
```bash
npm run dev
```
เปิดใช้งานระบบและเข้าทดสอบผ่านทางบราวเซอร์ได้ที่ [http://localhost:3000](http://localhost:3000)

### 5. ทำการ Build และเปิดบริการจริง (Production Mode)
```bash
npm run build
npm run start
```
