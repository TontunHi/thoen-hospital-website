# 2. ระบบจัดการเอกสารชมรมจริยธรรม (Hospital Ethics Document Management System)

Date: 2026-09-28

## สถานะ (Status)
ยอมรับแล้ว (Accepted)

## บริบท (Context)
หน้าเว็บไซต์ `/ethics?year=xxxx` ทำหน้าที่เป็นศูนย์รวมเอกสาร แผนการดำเนินงาน และคำสั่งคณะทำงานขับเคลื่อนชมรมจริยธรรมของโรงพยาบาลเถิน เพื่อเปิดให้ประชาชนและบุคลากรเข้าถึงข้อมูลด้านคุณธรรมและความโปร่งใสได้อย่างเปิดเผย

เดิมทีระบบทำการ Hardcode รายชื่อเอกสารและโครงสร้างปี (2567, 2568, 2569) ไว้ใน React Client Component (`src/app/ethics/page.tsx`) ทำให้เมื่อมีเอกสารใหม่ในระหว่างปีงบประมาณ (เช่น แผนปฏิบัติการ, รายงานผลรอบ 6 เดือน, 12 เดือน) หรือเมื่อขึ้นปีงบประมาณใหม่ เจ้าหน้าที่ไม่สามารถอัปโหลดหรือแก้ไขได้ด้วยตนเอง

นอกจากนี้ โรงพยาบาลต้องการให้ทุกคน (รวมถึงประชาชนภายนอก) สามารถเปิดอ่านและดาวน์โหลดไฟล์ PDF ได้อย่างอิสระ แต่จำกัดสิทธิ์ในการเพิ่มปีงบประมาณ, สร้างหัวข้อเอกสาร, อัปโหลดไฟล์ PDF หรือลบเอกสาร ให้เฉพาะตำแหน่งงานที่ได้รับมอบหมายเท่านั้น โดยควบคุมผ่านหน้า `/member/settings`

## การตัดสินใจ (Decision)

1. **การควบคุมสิทธิ์ตามตำแหน่งงาน (RBAC via Position Permissions):**
   - **การเปิดดูสาธารณะ (Public Read Access):** หน้า `/ethics` เป็น Public Page ประชาชนทั่วไปและเจ้าหน้าที่สามารถเข้าดูเอกสารและดาวน์โหลดไฟล์ PDF ได้โดยไม่ต้องเข้าสู่ระบบ
   - **การจัดการเอกสาร (Write/Manage Access):** เพิ่ม Permission Key ใหม่ `manage_ethics` (จัดการเอกสารชมรมจริยธรรม) ในตาราง `position_permissions`
   - กำหนดให้ผู้ดูแลระบบ (`role = 'admin'`) หรือบุคลากรในตำแหน่งงานที่ได้รับสิทธิ์ `manage_ethics` สามารถเข้าถึงหน้าจัดการ `/member/ethics` และจัดการเอกสารได้
   - เพิ่มปุ่มทางลัด `จัดการเอกสารจริยธรรม ⚙️` ในหน้า `/ethics` สำหรับเจ้าหน้าที่ที่มีสิทธิ์เมื่อล็อกอินอยู่

2. **โครงสร้างฐานข้อมูล (Two-Tier Data Model Hierarchy):**
   เพิ่มโมเดลใน Prisma Schema:
   - **`EthicsYear` (ตาราง `ethics_years`):**
     - `id`: Int (Primary Key)
     - `year`: String (เช่น "2569", "2568")
     - `displayOrder`: Int (ลำดับความสำคัญในการจัดเรียง)
     - `isActive`: Boolean (สถานะเปิด/ปิดการเผยแพร่)
     - `createdAt`, `updatedAt`: DateTime
     - ความสัมพันธ์: HasMany `EthicsDocument`
   - **`EthicsDocument` (ตาราง `ethics_documents`):**
     - `id`: Int (Primary Key)
     - `yearId`: Int (Foreign Key เชื่อมกับ `ethics_years`)
     - `parentId`: Int? (Foreign Key ชี้หาตัวมันเอง สำหรับรองรับข้อย่อย เช่น รอบ 6 เดือน, 12 เดือน)
     - `title`: String (ชื่อเอกสาร เช่น "1. คำสั่งคณะทำงาน...")
     - `filePath`: String? (เส้นทางไฟล์ PDF เช่น "/documents/ethics/2569/command.pdf")
     - `fileSize`: BigInt? (ขนาดไฟล์)
     - `displayOrder`: Int (ลำดับข้อ)
     - `isActive`: Boolean
     - `createdAt`, `updatedAt`: DateTime
     - ความสัมพันธ์: `year` (EthicsYear), `parent` (EthicsDocument?), `children` (EthicsDocument[]) กับพฤติกรรม `onDelete: Cascade`

3. **การจัดเก็บไฟล์และการย้ายข้อมูลเดิม (File Storage & Data Migration):**
   - ไฟล์ PDF ถูกจัดเก็บใน `public/documents/ethics/[year]/` และรองรับการอัปโหลดไฟล์ใหม่แบบ Sanitized Safe File Name
   - จัดทำ Seed Script นำเข้าโครงสร้างเอกสารเดิมของปี 2567, 2568, 2569 (รวมทั้งข้อย่อยรอบ 6 เดือน, 12 เดือน) พร้อมเชื่อมโยงกับไฟล์ PDF เดิมที่มีอยู่จริงครบถ้วน 100%

4. **การเรียงลำดับการแสดงผล (Display Ordering Rules):**
   - **หน้าสาธารณะ (`/ethics`):** แสดงปีงบประมาณล่าสุดเป็นอันดับแรก (เช่น 2569 -> 2568 -> 2567) และหากไม่มี `?year=...` จะเลือกปีล่าสุดที่เปิดใช้งานเป็นค่าเริ่มต้นอัตโนมัติ
   - **หน้าจัดการ (`/member/ethics`):** เรียงลำดับปีล่าสุดไว้ด้านบนเพื่อให้จัดการปีปัจจุบันได้สะดวกรวดเร็ว

5. **ระบบการตรวจสอบย้อนกลับ (Audit Logging):**
   - บันทึก `logAudit()` ทุกการกระทำ: สร้างปี, แก้ไขปี, ลบปี, อัปโหลดเอกสาร, แก้ไขชื่อเอกสาร และลบเอกสาร

## ผลกระทบ (Consequences)

### ผลเชิงบวก (Positive):
- คณะทำงานชมรมจริยธรรมสามารถอัปเดตคำสั่ง แผนงาน และรายงานผลการดำเนินงานได้ด้วยตนเองทันที
- รองรับทั้งเอกสารเดี่ยวและเอกสารที่มีการแตกหัวข้อย่อยได้อย่างสมบูรณ์แบบ
- ข้อมูลเดิมและไฟล์ PDF ในอดีตทั้งหมดยังคงใช้งานได้ตามปกติ ไร้รอยต่อ

### สิ่งที่ต้องระวัง / ข้อจำกัด (Trade-offs):
- เมื่อลบหัวข้อแม่ที่มีข้อย่อย ระบบจะใช้ `Cascade Delete` ลบเอกสารลูกทั้งหมดตามที่ตกลงกันไว้ จึงต้องมี Modal ยืนยันการลบอย่างรัดกุม
- ต้องตรวจสอบ MIME Type (เฉพาะ application/pdf) และขนาดไฟล์ไม่เกิน 20MB ฝั่งเซิร์ฟเวอร์
