# 1. ระบบจัดการทะเบียนหนังสือส่งออกทางราชการ (Outgoing Document Management System)

Date: 2026-09-28

## สถานะ (Status)
ยอมรับแล้ว (Accepted)

## บริบท (Context)
เดิมระบบทะเบียนหนังสือส่งออกทางราชการที่หน้า `/service/outgoing-document` มีการเก็บลิงก์ Google Sheets ประจำปีงบประมาณ 2561 - 2569 แบบ Hardcoded ในโค้ด React ทำให้เมื่อขึ้นปีงบประมาณใหม่ หรือมีการเปลี่ยนแปลง URL / หมายเหตุ ผู้ดูแลระบบต้องแก้ไขโค้ดและ Build ระบบใหม่ทุกครั้ง

นอกจากนี้ โรงพยาบาลต้องการจำกัดสิทธิ์เฉพาะบุคลากรในตำแหน่งงานสารบรรณ/ธุรการที่ได้รับมอบหมายเท่านั้น ที่สามารถเพิ่ม แก้ไข หรือลบลิงก์ Google Sheets ได้ โดยเชื่อมโยงกับการตั้งค่าสิทธิ์ตามตำแหน่งในหน้า `/member/settings` ในขณะที่บุคลากรทั่วไปของโรงพยาบาลที่เข้าสู่ระบบสมาชิกแล้วสามารถเข้าถึงและเปิดดู Google Sheets ได้ตามปกติ

## การตัดสินใจ (Decision)

1. **สถาปัตยกรรมการควบคุมสิทธิ์ (RBAC via Position Permissions):**
   - **การเปิดดู (Read Access):** บุคลากรของโรงพยาบาลทุกคนที่ผ่านการตรวจสอบเซสชัน (`verifyMemberSession()`) มีสิทธิ์เข้าดูหน้า `/service/outgoing-document` และเปิดดูลิงก์ Google Sheets ได้ทั้งหมด
   - **การจัดการข้อมูล (Write/Manage Access):** เพิ่ม Permission Key ใหม่ชื่อ `manage_outgoing_doc` ในระบบสิทธิ์ตามตำแหน่งงาน (`position_permissions`) โดยผู้ดูแลระบบระดับ `admin` หรือบุคลากรที่มีตำแหน่งงานที่ได้รับสิทธิ์ `manage_outgoing_doc` เท่านั้น จึงจะมีสิทธิ์เข้าถึงหน้าบริหารจัดการ `/member/outgoing-document` และเรียกใช้ API สำหรับ Create/Update/Delete
   
2. **การจัดเก็บข้อมูลและการย้ายข้อมูลเดิม (Data Storage & Migration):**
   - เพิ่มโมเดล `OutgoingDocument` ในฐานข้อมูลหลัก (Prisma ORM - MariaDB/MySQL) ฟิลด์ประกอบด้วย:
     - `id`: Int (Primary Key)
     - `year`: String (ปีงบประมาณ เช่น "2569")
     - `label`: String (ชื่อแสดงผล เช่น "ปีงบประมาณ 2569")
     - `note`: String? (หมายเหตุ เช่น "เริ่มใช้วันที่ 1 ตุลาคม 2568")
     - `url`: String (ลิงก์ Google Sheets)
     - `status`: String (สถานะ เช่น "ล่าสุด", "เสร็จสิ้น")
     - `displayOrder`: Int (ลำดับการแสดงผล เรียงจากปีล่าสุดก่อน)
     - `isActive`: Boolean (สถานะเปิด/ปิดการเผยแพร่)
     - `createdBy`, `updatedBy`: String? (Audit tracking)
     - `createdAt`, `updatedAt`: DateTime
   - จัดทำ Seed Migration นำเข้าข้อมูลประวัติเดิม 9 ปีงบประมาณ (2561 - 2569) เข้าสู่ฐานข้อมูลทันที

3. **ส่วนติดต่อผู้ใช้งาน (UI Presentation & Navigation):**
   - **หน้าบริการ (`/service/outgoing-document`):** ปรับให้ดึงข้อมูลแบบไดนามิกจากฐานข้อมูลผ่าน API หากผู้ใช้ล็อกอินด้วยตำแหน่งที่มีสิทธิ์ `manage_outgoing_doc` หรือ `admin` จะแสดงปุ่มลัด `จัดการลิงก์ Sheet ⚙️` นำทางไปยังหน้าจัดการ
   - **หน้าจัดการหลังบ้าน (`/member/outgoing-document`):** หน้าบริหารจัดการสำหรับเพิ่ม แก้ไข ลบ จัดลำดับ และสลับสถานะลิงก์
   - **หน้าแดชบอร์ดบุคลากร (`/member`):** เพิ่มการ์ดเมนู "จัดการระบบหนังสือส่งออก Online" แสดงเฉพาะผู้ใช้ที่มีสิทธิ์

4. **การตรวจสอบและบันทึกประวัติ (Audit Trail):**
   - ทุกคำสั่งเพิ่ม แก้ไข หรือลบลิงก์ Google Sheets จะถูกบันทึก Audit Log ผ่าน `logAudit()` ลงตาราง `audit_logs` ระบุผู้ดำเนินการ วันเวลา และรายละเอียดที่เปลี่ยนแปลง

## ผลกระทบ (Consequences)

### ผลเชิงบวก (Positive):
- งานสารบรรณ/ธุรการสามารถจัดการลิงก์ เพิ่มปีงบประมาณใหม่ หรือแก้ไข URL ได้เองผ่านหน้าเว็บทันที ไม่ต้องพึ่งพาทีมพัฒนาโปรแกรม
- การกำหนดสิทธิ์สอดคล้องกับมาตรฐาน RBAC เดิมของโรงพยาบาล สามารถเลือกตำแหน่งที่ได้รับอนุญาตผ่านหน้า `/member/settings` ได้ยืดหยุ่น
- ข้อมูลประวัติเดิม 9 ปีไม่สูญหาย และพร้อมใช้งานต่อเนื่องทันที

### สิ่งที่ต้องระวัง / ข้อจำกัด (Trade-offs):
- ต้องตรวจสอบความถูกต้องของ URL Google Sheets ที่ผู้ใช้ป้อนเข้ามา (Server-side validation) เพื่อป้องกันการใส่ลิงก์ที่ไม่ถูกต้อง
- ต้องเพิ่ม Permission Key `manage_outgoing_doc` ลงในระบบตั้งค่าสิทธิ์ของหน้า `/member/settings`
