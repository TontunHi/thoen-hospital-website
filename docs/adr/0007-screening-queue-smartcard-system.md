# 7. สถาปัตยกรรมระบบคิวคัดกรองและลงทะเบียนตรวจนอกพื้นที่ด้วยเครื่องอ่านบัตรประชาชน (Screening Queue and Smart Card Integration)

Date: 2026-10-14

## สถานะ (Status)
ยอมรับแล้ว (Accepted)

## บริบท (Context)
โรงพยาบาลเถินมีภารกิจออกหน่วยตรวจคัดกรองสุขภาพเชิงรุกและบริการตรวจนอกสถานที่ (Field Screening / Outreach Services) เป็นประจำ ซึ่งมีผู้มารับบริการเป็นจำนวนมากในแต่ละรอบ 

ปัญหาและข้อจำกัดในปัจจุบัน:
1. **ความรวดเร็วในการลงทะเบียนหน้างาน:** การกรอกข้อมูลด้วยมือหรือค้นหาทีละคนทำให้คิวสะสมหนาแน่น เจ้าหน้าที่ต้องการเพียง "เสียบบัตรประชาชนเข้าเครื่องอ่านที่ต่อกับโน้ตบุ๊ก" แล้วให้ระบบดึงข้อมูลอัตโนมัติ
2. **ความต่อเนื่องในการรับคิว (Rapid Batch Flow):** เจ้าหน้าที่จุดอ่านบัตรต้องการหน้าจอที่เมื่อกดบันทึกแล้ว จะเคลียร์หน้าจอและค้างสถานะพร้อมรับคนต่อไปทันที โดยไม่ต้องถูก Redirect ออกไปหน้าอื่น
3. **การแสดงผลคิวแยกหน้าจอ (Display Screen Separation):** จุดคัดกรองหรือเจ้าหน้าที่ห้องบัตรอีกฝั่งต้องการหน้าจอติดตามรายชื่อแบบ Real-time (Auto-refresh ทุก 3 วินาที) เพื่อเตรียมตัวเปิด Visit ในระบบโรงพยาบาล
4. **ความยืดหยุ่นของโครงสร้างข้อมูลบัตร:** ในระยะเริ่มต้น ยังไม่ทราบแน่ชัดว่าเครื่องอ่านบัตรแต่ละรุ่นจะส่งฟิลด์ใดมาบ้าง จึงต้องการให้บันทึกทั้งฟิลด์สำคัญและเก็บ `rawPayload` (JSON ดิบทั้งหมด) ไว้ตรวจสอบ
5. **การจัดการข้อมูลย้อนหลังและการล้างข้อมูล (Retention Policy):** หน้าจอปกติให้แสดงเฉพาะรายชื่อของ "วันนี้" เพื่อความกระชับ แต่ให้มีปุ่มกดเปิดดูประวัติย้อนหลังได้ และเมื่อข้อมูลมีอายุเกิน 1 เดือน (30 วัน) ให้ระบบล้างข้อมูลเก่าออกอัตโนมัติ

## การตัดสินใจ (Decision)

### 1. สถาปัตยกรรม URL และการแยกส่วนการทำงาน (`/service/screening`)
- **หน้าแสดงรายการคิวผู้รับบริการ (`/service/screening`):**
  - แสดงผลรายชื่อผู้ที่ถูกอ่านบัตรเข้ามาใน "วันนี้ (Today)" เป็นค่าเริ่มต้น
  - อัปเดตข้อมูลอัตโนมัติทุก 3 วินาที (Polling)
  - มีแถบค้นหาชื่อ-สกุล หรือเลขบัตรประชาชน 13 หลัก
  - มีปุ่มเปิดดู *"ข้อมูลย้อนหลัง"* พร้อมตัวเลือกวันที่
  - แสดงสถานะของแต่ละรายชื่อ: `WAITING` (รอเปิด Visit), `VISIT_OPENED` (เปิด Visit แล้ว), `CANCELLED` (ยกเลิก)
  - มีปุ่มกดดูข้อมูลดิบจากบัตรประชาชน (Raw Payload Modal)
- **หน้าจุดอ่านบัตรประชาชน (`/service/screening/scan`):**
  - หน้าจอสำหรับเจ้าหน้าที่จุดเสียบบัตรโดยเฉพาะ
  - เชื่อมต่อเครื่องอ่านบัตรผ่าน WebHID API ในเบราว์เซอร์ Chrome / Edge โดยตรง ไม่ต้องติดตั้งโปรแกรม Local Agent เพิ่มเติม
  - มีโหมดทดสอบอ่านข้อมูล (Mock / Simulation) สำหรับกรณีทดสอบระบบหรือเครื่องอ่านยังไม่ได้เชื่อมต่อ
  - เมื่อกด "เพิ่มเข้าระบบ" บันทึกข้อมูลสำเร็จ จะแสดงสัญญาณเตือนและรีเซ็ตหน้าจอพร้อมรับบัตรคนถัดไปทันที

### 2. โครงสร้างฐานข้อมูล (Database Schema in Prisma)
สร้างโมเดล `ScreeningQueue` ในตาราง `screening_queues`:
```prisma
model ScreeningQueue {
  id          Int      @id @default(autoincrement())
  cid         String   @db.VarChar(13)
  title       String?  @db.VarChar(50)
  firstName   String?  @map("first_name") @db.VarChar(100)
  lastName    String?  @map("last_name") @db.VarChar(100)
  fullName    String   @map("full_name") @db.VarChar(255)
  gender      String?  @db.VarChar(10)
  birthDate   String?  @map("birth_date") @db.VarChar(20)
  address     String?  @db.Text
  photoBase64 String?  @map("photo_base64") @db.LongText
  rawPayload  String?  @map("raw_payload") @db.LongText
  status      String   @default("WAITING") @db.VarChar(30)
  vn          String?  @db.VarChar(50)
  recordedBy  Int?     @map("recorded_by")
  createdAt   DateTime @default(now()) @map("created_at")
  updatedAt   DateTime @default(now()) @updatedAt @map("updated_at")

  @@index([createdAt], map: "idx_screening_created")
  @@index([cid], map: "idx_screening_cid")
  @@index([status], map: "idx_screening_status")
  @@map("screening_queues")
}
```

### 3. การเชื่อมต่อ WebHID กับ Smart Card APDU
- ใช้ WebHID API (`navigator.hid`) ส่งคำสั่งมาตรฐาน CCID / APDU ตามข้อกำหนดบัตรประชาชนไทย (ISO-7816):
  - อ่านเลขประจำตัวประชาชน 13 หลัก
  - อ่านคำนำหน้า ชื่อ นามสกุล ภาษาไทยและภาษาอังกฤษ
  - อ่านวันเดือนปีเกิด เพศ
  - อ่านที่อยู่ตามทะเบียนบ้าน
  - อ่านรูปถ่ายหน้าบัตร (เมื่อต้องการ)
- รองรับการถอดรหัส TIS-620 เป็น UTF-8 ภายในตัว
- บันทึก JSON ก้อนเต็มลงในฟิลด์ `rawPayload` เพื่อให้เจ้าหน้าที่สามารถเปิดดูฟิลด์ทั้งหมดที่เครื่องอ่านส่งมาได้

### 4. นโยบายการจัดเก็บและล้างข้อมูล (Retention & Auto Cleanup)
- ข้อมูลในตาราง `screening_queues` ที่มีอายุมากกว่า 30 วัน จะถูกล้างออกโดยอัตโนมัติผ่าน Service logic เมื่อมีการเรียกใช้งานหน้าคัดกรอง หรือผ่าน Cleanup Job เพื่อรักษาประสิทธิภาพและสุขอนามัยของฐานข้อมูล

## ผลที่ตามมา (Consequences)
- **ข้อดี:**
  - ใช้งานสะดวกสูงสุด เจ้าหน้าที่เปิดเพียงเบราว์เซอร์ Chrome เสียบเครื่องอ่าน USB สามารถอ่านบัตรได้ทันทีโดยไม่ต้องลงโปรแกรมหรือ driver เสริม
  - ตอบโจทย์งานตรวจนอกพื้นที่ที่มีผู้รับบริการจำนวนมาก ค้างหน้าจอไว้รันคิวต่อเนื่องได้รวดเร็ว
  - การแยกจอแสดงผลช่วยให้ทีมคัดกรองและทีมห้องบัตรมองเห็นคิวตรงกันแบบ Real-time
  - โครงสร้าง `rawPayload` ช่วยให้ทีมพัฒนามองเห็นข้อมูลดิบทั้งหมดจากบัตรจริงก่อนนำไปพัฒนาต่อยอดในขั้นตอนเชื่อม HOSxP Visit
- **ข้อพึงระวัง:**
  - WebHID API ทำงานได้บน Chromium-based browsers (Google Chrome, Microsoft Edge, Brave) และต้องใช้งานผ่าน HTTPS หรือ `localhost`
