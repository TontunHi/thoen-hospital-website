# 6. สถาปัตยกรรมระบบกิจกรรมโรงพยาบาลเถินและการเช็คอินผ่าน ThaID (Hospital Event Management and ThaID Attendance System)

Date: 2026-10-12

## สถานะ (Status)
ยอมรับแล้ว (Accepted)

## บริบท (Context)
โรงพยาบาลเถินมีกิจกรรมภายในหลากหลายประเภทอย่างต่อเนื่อง เช่น การอบรมพัฒนาศักยภาพบุคลากร, งานจิตอาสา, ประชุมวิชาการ, กิจกรรมส่งเสริมสุขภาพ และกิจกรรมชมรมคุณธรรม/จริยธรรม 

ปัจจุบันยังมีปัญหาและข้อจำกัดในการบริหารจัดการกิจกรรมดังนี้:
1. **การติดตามการมีส่วนร่วมและคะแนนกิจกรรม (Participation Points):** ยังไม่มีระบบรวมศูนย์ที่บันทึกว่าบุคลากรแต่ละคนหรือแต่ละกลุ่มงาน/แผนก เข้าร่วมกิจกรรมมากน้อยเพียงใด เพื่อนำไปใช้เป็นตัวชี้วัดหรือกระตุ้นการมีส่วนร่วมในองค์กร
2. **ความยุ่งยากและความถูกต้องของการเช็คอินหน้างาน (Event Check-in):** การลงชื่อในกระดาษหรือกรอก Google Form เกิดความล่าช้า ตัวสะกดผิด หรือมีการลงชื่อแทนกัน องค์กรต้องการใช้ระบบยืนยันตัวตนดิจิทัลภาครัฐ **ThaID (DOPA)** สแกนผ่านโทรศัพท์มือถือ เพื่อยืนยันว่าเป็นตัวบุคคลจริง 1 คน ต่อ 1 สิทธิ์ ต่อ 1 กิจกรรม โดยไม่ต้องบังคับให้ผู้ใช้ต้องล็อกอินบัญชีเว็บไซต์โรงพยาบาลไว้ล่วงหน้า
3. **การควบคุมช่วงเวลาเช็คอิน (Time Window Restriction):** ต้องสามารถควบคุมให้สแกนได้เฉพาะช่วงเวลาจัดงานจริงเท่านั้น ไม่ให้สแกนล่วงหน้าก่อนเวลาเปิดรับ หรือสแกนหลังจากจบกิจกรรมไปแล้ว
4. **การเตรียมวัสดุและอุปกรณ์สนับสนุนกิจกรรม (Material Borrowing Integration):** กิจกรรมส่วนใหญ่มีความจำเป็นต้องยืมครุภัณฑ์ (เช่น โปรเจคเตอร์, ไมโครโฟน) หรือเบิกวัสดุ (เช่น ปลั๊กไฟ, ป้าย) ต้องการให้สามารถระบุรายการขอยืมได้ทันทีตั้งแต่ขั้นตอนสร้างกิจกรรม และเชื่อมต่อตรงเข้าสู่ระบบยืม-คืนพัสดุหลักของโรงพยาบาล

## การตัดสินใจ (Decision)

### 1. โครงสร้างฐานข้อมูล (Data Modeling in Prisma)
ออกแบบโมเดลรองรับระบบกิจกรรมใน `prisma/schema.prisma` ดังนี้:

- **`HospitalEvent` (ตารางหลักกิจกรรม `hospital_events`):**
  - `id`: รหัสกิจกรรม (Autoincrement หรือ CUID/UUID)
  - `title`: ชื่อกิจกรรม
  - `description`: รายละเอียดกิจกรรม/วัตถุประสงค์
  - `location`: สถานที่จัดกิจกรรม (หรือเชื่อมโยงกับ `HospitalLocation`)
  - `bannerUrl`: ภาพโปสเตอร์หรือภาพปกกิจกรรม
  - `eventStartDate`, `eventEndDate`: วัน-เวลาเริ่มและสิ้นสุดกิจกรรม
  - `checkinOpenTime`, `checkinCloseTime`: วัน-เวลาเปิดและปิดรับสแกนเช็คอิน (หากไม่ระบุจะใช้วันที่เริ่ม-จบงานเป็นค่าเริ่มต้น)
  - `headOrganizerId`: รหัสสมาชิกผู้รับผิดชอบหลัก (`Member.id`)
  - `borrowRequestId`: รหัสใบขอยืมอุปกรณ์อ้างอิง (`equipment_borrow_requests.id`)
  - `qrToken`: โทเค็นเฉพาะประจำกิจกรรมสำหรับสร้าง Static QR Code
  - `status`: สถานะกิจกรรม (`UPCOMING`, `ONGOING`, `COMPLETED`, `CANCELLED`)
  - `fiscalYear`: ปีงบประมาณ พ.ศ. (เช่น "2569") สำหรับคำนวณและกรองคะแนน
  - `createdAt`, `updatedAt`

- **`EventOrganizer` (ตารางผู้รับผิดชอบร่วม `event_organizers`):**
  - จัดเก็บรายชื่อผู้รับผิดชอบร่วม (Co-organizers) หลายคน ผูกกับ `eventId` และ `memberId`

- **`EventRegistration` (ตารางการลงทะเบียนล่วงหน้า `event_registrations`):**
  - จัดเก็บข้อมูลบุคลากรที่กดลงทะเบียนแสดงความจำนงล่วงหน้า (`memberId`, `registeredAt`) เพื่อแสดงยอด "จำนวนผู้ลงทะเบียน" (ยังไม่ได้รับคะแนน)

- **`EventAttendance` (ตารางการเช็คอินเข้างานจริง `event_attendances`):**
  - บันทึกเมื่อผู้เข้าร่วมสแกน QR Code ผ่าน ThaID สำเร็จ
  - ฟิลด์: `eventId`, `memberId`, `citizenId` (Masked), `checkedInAt`, `pointsAwarded` (1 คะแนน), `ipAddress`, `userAgent`
  - มี Unique Constraint `[eventId, memberId]` เพื่อรับประกันว่า 1 คน สามารถเช็คอินและรับคะแนนได้เพียง 1 ครั้งต่อ 1 กิจกรรมเท่านั้น

---

### 2. กระบวนการเช็คอินผ่าน ThaID OAuth (ThaID QR Check-in Architecture)
1. **การสร้างและแสดงผล Static QR Code:**
   - ผู้รับผิดชอบกิจกรรมสามารถเปิดหน้า QR Code หรือดาวน์โหลดเป็นไฟล์ภาพ/PDF เพื่อพิมพ์ตั้งหน้างาน
   - URL ใน QR Code ชี้ไปที่: `/api/events/checkin/[qrToken]`
2. **การสแกนและตรวจสอบเงื่อนไขเวลา (Time-gated):**
   - เมื่อผู้เข้าร่วมใช้โทรศัพท์มือถือสแกนลิงก์ ระบบตรวจสอบช่วงเวลาปัจจุบันเทียบกับ `checkinOpenTime` และ `checkinCloseTime`
   - หากเวลาปัจจุบันยังไม่ถึง `checkinOpenTime` -> ระบบปฏิเสธและแสดงผล: *"ยังไม่ถึงเวลาเปิดเช็คอิน (เปิดรับสแกนเวลา ...)"*
   - หากเวลาปัจจุบันเกิน `checkinCloseTime` -> ระบบปฏิเสธและแสดงผล: *"หมดเวลาเช็คอินสำหรับกิจกรรมนี้แล้ว"*
3. **การยืนยันตัวตนผ่าน ThaID (DOPA OAuth):**
   - หากอยู่ในช่วงเวลาที่ถูกต้อง ระบบจะ Redirect ไปยัง ThaID Authorization Endpoint พร้อมระบุ `state` ที่เข้ารหัส `eventId` และ Nonce ไว้อย่างปลอดภัย
   - ผู้ใช้ยืนยันตัวตนบนแอป ThaID
   - DOPA Callback กลับมาที่ Endpoint เฉพาะ: `/api/auth/thaid/event-callback`
   - แลก Authorization Code เป็น `pid` (เลขบัตรประชาชน 13 หลัก)
4. **การจับคู่สมาชิกและการมอบคะแนน (1 Event = 1 Point):**
   - ค้นหา `username = pid` ในตาราง `members` ของโรงพยาบาลเถิน
   - หาก **ไม่พบบัญชีในระบบ**: แจ้งเตือน *"ไม่พบข้อมูลบุคลากรในระบบ กรุณาติดต่อฝ่ายทรัพยากรบุคคลหรือลงทะเบียนสมาชิก"*
   - หาก **เคยเช็คอินไปแล้ว**: แจ้งเตือน *"ท่านได้บันทึกการเข้าร่วมกิจกรรมนี้ไปแล้วเมื่อ [เวลา]"*
   - หาก **ถูกต้องสมบูรณ์**:
     - บันทึกแถวใหม่ลงใน `event_attendances` พร้อม `pointsAwarded = 1`
     - หากเคยลงทะเบียนล่วงหน้าใน `event_registrations` ให้อัปเดตสถานะเป็น `ATTENDED`
     - แสดงหน้าจอสำเร็จ: **"คุณ [ชื่อ-สกุล] ([แผนก]) เข้าร่วมกิจกรรม [ชื่อกิจกรรม] สำเร็จ 🎉"**
     - บันทึก `AuditLog` ผ่าน `@/lib/audit`

### 3. การเชื่อมโยงการยืมวัสดุ/ครุภัณฑ์ (Equipment Borrowing Integration)
- ในหน้าจอสร้างกิจกรรม (`/member/events/create`) มีส่วนของ **"ขอยืมอุปกรณ์และวัสดุสำหรับกิจกรรม"**
- รองรับการกดปุ่ม `+ เพิ่มรายการยืม` โดยมี Dropdown ให้เลือกรายการวัสดุ (`HospitalMaterial`) หรือครุภัณฑ์ (`HospitalAsset`) ที่มีสถานะพร้อมใช้งาน พร้อมช่องระบุจำนวนชิ้น
- เมื่อกดยืนยันสร้างกิจกรรม:
  - หากมีการเลือกยืมของ ระบบจะเรียกใช้ Service สร้างใบขอยืมใน `equipment_borrow_requests` อัตโนมัติ โดยระบุ `purpose = "ใช้ในกิจกรรม: [ชื่อกิจกรรม]"` และ `borrowDate = eventStartDate`
  - นำ `borrowRequestId` ที่ได้มาผูกเข้ากับ `HospitalEvent.borrowRequestId`
  - ข้อมูลใบยืมจะวิ่งเข้าสู่กระบวนการอนุมัติและตรวจจ่ายของเจ้าหน้าที่พัสดุตามปกติของโรงพยาบาล

---

### 4. ระบบกระดานอันดับคะแนน (Dense Ranking Leaderboard Engine)
- **กฎการจัดอันดับ (Dense Rank):**
  - บุคลากรที่ได้คะแนนเท่ากันจะครองอันดับเดียวกัน (เช่น อันดับ 1 ได้ 10 แต้ม, อันดับ 2 มีสองคนได้คนละ 9 แต้ม จะครองอันดับ 2 ร่วมกันทั้งคู่ และผู้ที่ได้ 8 แต้มจะเป็นอันดับ 3)
- **กระดานคะแนนระดับแผนก (Department Leaderboard):**
  - รวมคะแนนของบุคลากรทุกคนที่สังกัดในแต่ละแผนก (`members.department`)
  - นำเสนอ 2 มิติเพื่อความเป็นธรรม:
    1. **คะแนนรวม (Total Points):** จำนวนครั้งการเข้าร่วมทั้งหมดของสมาชิกทุกคนในแผนก
    2. **คะแนนเฉลี่ยต่อคน (Average Points per Member):** `คะแนนรวมของแผนก ÷ จำนวนบุคลากรในแผนก` เพื่อให้หน่วยงานที่มีบุคลากรน้อยสามารถแข่งขันได้อย่างเสมอภาค
- **ตัวกรองช่วงเวลา (Timeframe Filtering):**
  - ค่าเริ่มต้นแสดงตาม **"ปีงบประมาณ พ.ศ."** (เช่น ปี 2568, 2569 นับ 1 ต.ค. - 30 ก.ย.)
  - รองรับการเลือกดูแบบ **"ตลอดกาล (All-time)"** หรือ **"ประจำเดือน"**

### 5. โครงสร้างเส้นทางและส่วนประสานผู้ใช้ (Routes & UI Architecture)
ทุกหน้าจอสำหรับบุคลากรจะรวมศูนย์อยู่ภายใต้ `/member/events`:
- `/member/events`: หน้าหลักแสดงกิจกรรมที่จะเกิดขึ้นเร็วๆ นี้ (Upcoming), กิจกรรมที่กำลังจัด (Ongoing), ปฏิทิน, และแถบกิจกรรมที่ฉันลงทะเบียนไว้
- `/member/events/create`: ฟอร์มสร้างกิจกรรมพร้อมระบบเลือกผู้รับผิดชอบร่วม และตารางเลือกยืมวัสดุ/ครุภัณฑ์
- `/member/events/[id]`: รายละเอียดกิจกรรม, รายชื่อผู้ลงทะเบียน, รายชื่อผู้เช็คอินเข้างานจริง (เฉพาะผู้จัด/Admin), และปุ่มเปิด/พิมพ์ Static QR Code
- `/member/events/leaderboard`: หน้ากระดานอันดับคะแนน แยกแท็บ "อันดับรายบุคคล" และ "อันดับระดับแผนก" พร้อมตัวกรองปีงบประมาณ
- `/api/events/checkin/[token]` & `/api/auth/thaid/event-callback`: API Endpoint รองรับการสแกนและยืนยันตัวตนด้วย ThaID

## ผลกระทบ (Consequences)

### ผลเชิงบวก (Positive):
1. **สะดวกรวดเร็วและน่าเชื่อถือสูง:** เช็คอินผ่าน ThaID โดยตรง ป้องกันการลงชื่อแทนกัน 100% ไม่ต้องเสียเวลาล็อกอินเว็บโรงพยาบาลล่วงหน้า
2. **สร้างแรงจูงใจในการมีส่วนร่วม (Gamification & Recognition):** ระบบคะแนนและ Leaderboard ระดับแผนกช่วยกระตุ้นวัฒนธรรมการมีส่วนร่วมในกิจกรรมองค์กร
3. **ลดความซ้ำซ้อนของระบบ:** การยืมวัสดุผูกเข้ากับระบบยืม-คืนพัสดุเดิม ไม่ต้องแยกฐานข้อมูลสต็อกใหม่
4. **ปลอดภัยตามมาตรฐาน PDPA & Hospital Architecture:** จัดเก็บเฉพาะ Citizen ID ที่ผ่านการ Masking และบันทึก Audit Logs ทุกขั้นตอน

### สิ่งที่ต้องระวัง / ข้อจำกัด (Trade-offs & Mitigations):
1. **การเชื่อมต่อภายนอกกับ ThaID (DOPA Network):** หากระบบ ThaID ของกรมการปกครองล่มชั่วคราว ผู้จัดงานที่เป็นเจ้าของ Event หรือ Admin สามารถมีปุ่ม Manual Check-in ในหน้ากิจกรรม เพื่อค้นหาชื่อบุคลากรและกดเช็คอินสำรองให้ได้
2. **ความถูกต้องของสังกัดแผนก:** คะแนนระดับแผนกขึ้นอยู่กับฟิลด์ `department` ในตาราง `members` หากข้อมูลแผนกของบุคลากรว่างหรือไม่อัปเดต จะจัดกลุ่มเป็น "ไม่ระบุแผนก"
