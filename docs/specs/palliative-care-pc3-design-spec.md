# Design Spec: Palliative Care ตามกลุ่มโรคที่กรมการแพทย์กำหนด (PC.3)

หน้า: `/service/dashboard-rcm/palliative-care/pc-3` (เจ้าหน้าที่การเงิน/RCM และบุคลากรทางการแพทย์)  
ใช้ design tokens ชุดเดียวกับระบบ `ui-style-brief` ของโรงพยาบาลเถิน

---

## 1. ปัญหาของหน้าเดิม และสิ่งที่แก้

| ปัญหาเดิม | วิธีแก้ |
|---|---|
| การ์ดสถิติตัวเลข 7 ใบแยกกันหลากสี สไตล์ AI slop และมีไอคอนตกแต่งทุกการ์ด | รวมเป็น **แถบสรุปตัวเลขชิ้นเดียว (Metric Bar)** คั่นด้วยเส้นแบ่ง ตัวเลขเด่น 24-26px สบายตา ไม่มีไอคอนตกแต่ง |
| ใช้สีชมพู/บานเย็นสดฉูดฉาด ไม่สื่อความหมายทางระบบโรงพยาบาล | เปลี่ยนมาใช้สีมาตรฐานโรงพยาบาล: สี accent เขียว `#0b6b47` สบายตา และใช้โทนสีสถานะสื่อความหมาย 1 สี = 1 ความหมาย |
| ปุ่มเครื่องมือกระจัดกระจายและมีไอคอนปนข้อความ | จัดระเบียบแถบ Toolbar: แท็บเลือกช่วงเวลาเป็น Segmented Track (`#eef1ee`), ปุ่มสูง ≥ 44px, ป้ายกำกับชัดเจน |
| ช่องค้นหามีไอคอนแว่นขยายตกแต่งเกินจำเป็น | ปรับเป็น `input[type="search"]` สะอาดตา มี placeholder กำกับว่าค้นหา HN, CID, VN, หรือรหัสโรคได้ |
| รหัสหัวข้อหน้าเดิมเป็น `PC.1` ซึ่งไม่ตรงกับหมวดรายงานจริง | ปรับรหัสหัวข้อเป็น **`PC.3`** และย้าย URL เป็น `/service/dashboard-rcm/palliative-care/pc-3` เพื่อรองรับรายงานข้อย่อยอื่นๆ ในอนาคต |

## 2. โครงสร้างหน้า (บนลงล่าง)

| # | ส่วน | เนื้อหา |
|---|---|---|
| 1 | ส่วนหัว (Header) | `h1` ชื่อหน้า + ป้ายรหัส `PC.3` + คำอธิบาย + ปุ่มส่งออก CSV (ปุ่มหลัก) + ปุ่มรีเฟรช (ปุ่มรอง) (ไม่อิงปุ่มย้อนกลับซ้ำซ้อน เพราะใช้ Shell Sidebar/Breadcrumb) |
| 3 | แถบสรุปตัวเลข (Metric Bar) | แถบข้อมูลสรุป 7 ช่อง: ผู้ป่วยทั้งหมด, ACP, Opioid, มี Z515, ไม่พบ Z515, ชดเชยแล้ว, เสียชีวิต |
| 4 | แถบเครื่องมือ (Toolbar) | แท็บเลือกโหมดวันที่ (กำหนดเอง / รายเดือน / รายปีงบประมาณ) + เช็คบ็อกซ์สิทธิ UC + ดรอปดาวน์สถานะตาย + ดรอปดาวน์เงินชดเชย + ดรอปดาวน์กลุ่มโรค + ช่องค้นหา Live Search |
| 5 | แถบอธิบายสี (Legend Bar) | คำอธิบายแถบสีจำแนกสถานะ: เขียว (ชดเชยแล้ว), ชมพู (เสียชีวิต), ส้ม/เหลืองอำพัน (ไม่พบรหัส Z515) |
| 6 | ตารางข้อมูล (Table) | ตารางผู้ป่วย Palliative Care แสดงผล 27 คอลัมน์ รองรับการเลื่อนแนวนอน ตัวเลขใช้ `tabular-nums` ชื่อ-สกุล แสดงแนวนอนแถวเดียวไม่ซ้อนกัน |
| 7 | ส่วนท้ายตาราง (Pagination) | สรุปจำนวนรายการที่แสดง + ปุ่มสลับหน้า `« ‹ หน้า X / Y › »` |
| 8 | หน้าต่างรายละเอียด (Modal) | แสดงข้อมูลผู้ป่วยเชิงลึกเมื่อกดปุ่ม "ดูข้อมูล" ในแถว |

## 3. กติกาการแสดงผลและตรรกะ (Business Rules)

| หัวข้อ | กติกา |
|---|---|
| ค่าตั้งต้นสิทธิ UC | เช็คบ็อกซ์ "เฉพาะสิทธิ UC" ถูกเลือกไว้เป็นค่าเริ่มต้น (`default: true`) กรองเฉพาะ `inscl = 'UCS'` |
| สิทธิที่ถูกตัดออก | ตัดรหัสสิทธิ `H1` (ฟอกไตบัตรทอง), `35` (บัตรทอง ต่างอำเภอ A/E), `36` (บัตรทอง ต่างจังหวัด A/E) ออกจากรายงานเสมอ |
| เลขบัตรประชาชน (CID) | แสดงเลข 13 หลักเต็ม ไม่มีการ Mask ข้อมูล เพื่อให้เจ้าหน้าที่ตรวจสอบสิทธิ์ได้ตรงตัว |
| Advance Care Plan | จัดกลุ่มเมื่อตรงตามเกณฑ์วินิจฉัย `Dx = 'Y'` ร่วมกับรหัส `Z718 = 'Y'` |
| Opioid | จัดกลุ่มเมื่อเป็นโรคมะเร็ง `Cancer = 'Y'` ร่วมกับได้รับยากลุ่มโอปิออยด์ `Drug = 'Y'` |
| สถานะตาย | แสดงคอลัมน์ `สถานะตาย` หากผู้ป่วยเสียชีวิตจะขึ้นป้าย `เสียชีวิต (YYYY-MM-DD)` พร้อมไฮไลต์แถวสีชมพูอ่อน |
| สถานะว่าง (Empty) | แสดงข้อความ `ไม่พบข้อมูลผู้ป่วย Palliative Care ในช่วงเวลาหรือเงื่อนไขที่เลือก` |
| กำลังโหลด (Loading) | แสดงข้อความ `กำลังโหลดข้อมูล Palliative Care จากระบบ...` |

| แจ้งเตือน / ขาดรหัส | `#fdf1d6` | `#6b4100` | `#c98a10` | ป้าย `ไม่พบรหัส Z515`, แถวที่ต้องลงรหัสเพิ่ม |

| ข้อมูล / ACP | `#e6f0fb` | `#17467a` | `#d0e1f9` | หัวตารางกลุ่ม Advance Care Plan |

## 5. การตอบสนอง (Responsive Design)

| ขนาดหน้าจอ | พฤติกรรม |
|---|---|
| เดสก์ท็อป (≥ 1080px) | แสดงเต็มความกว้าง แถบ Metric Bar เรียง 7 คอลัมน์ ตารางเลื่อนแนวนอนได้ถ้าข้อมูลกว้างกว่าจอ |
| แท็บเล็ต / จอเล็ก | แถบ Metric Bar ตัดขึ้นบรรทัดใหม่อัตโนมัติ (`grid-template-columns: repeat(auto-fit, minmax(140px, 1fr))`) |
| มือถือ (< 640px) | ส่วนควบคุมยืดหยุ่นเป็นแนวตั้ง ตารางมี scroll container แยก ไม่ดันหน้าจอหลัก |

## 6. การเข้าถึง (Accessibility: a11y)

| รายการ | วิธีทำ |
|---|---|
| อัตราส่วนคอนทราสต์ | คอนทราสต์ข้อความกับพื้นหลัง ≥ 4.5:1 ทุกคู่สี (รวมสีในสถานะ) |
| ความหมายไม่พึ่งสีเพียงอย่างเดียว | ทุกสถานะและแถบสีมีข้อความระบุชัดเจน (เช่น `เสียชีวิต`, `จ่ายแล้ว`, `ไม่พบรหัส Z515`) |
| ปุ่มและการควบคุม | ปุ่มและ input มีความสูง ≥ 44px สำหรับเป้าสัมผัส |
| คีย์บอร์ดและ Focus | ทุก element ที่โฟกัสได้มี focus ring ชัดเจน |

## 7. ข้อมูลที่หน้านี้ใช้ (API Specification)

- **Endpoint:** `GET /api/service/dashboard-rcm/palliative-care/pc-3`
- **Parameters:**
  - `ds1`: วันที่เริ่มต้น (YYYY-MM-DD)
  - `ds2`: วันที่สิ้นสุด (YYYY-MM-DD)
  - `ucOnly`: `true` \| `false`
  - `deathStatus`: `ALL` \| `Y` \| `N` (ทั้งหมด / เฉพาะเสียชีวิต / เฉพาะมีชีวิต)
  - `compensated`: นิพจน์เงื่อนไขเงินชดเชย เช่น `ALL`, `0`, `PAID`, `>=750`, `>=1000`, `>9000`, `=5000`
  - `paidStatus`: `ALL` \| `PAID` \| `UNPAID` (ทั้งหมด / ชดเชยแล้ว / ยังไม่ได้รับชดเชย)
  - `filterType`: `ALL` \| `Chronic` \| `Opioid`
  - `search`: คำค้นหา (HN, CID, VN, Diag)
- **Security:** ตรวจสอบสิทธิ์ผู้ใช้ (Member Session: staff / admin / member) พร้อมบันทึก Throttled Audit Log

## 8. สิ่งที่ตัดออกจากหน้าเดิม (Subtraction Pass)

| ของเดิม | เหตุผลที่ตัดออก |
|---|---|
| ไอคอน Lucide หลากสีหน้าการ์ดสถิติทุกใบ | เป็นไอคอนตกแต่ง (AI slop) รกสายตา ไม่ได้ช่วยในการตัดสินใจ |
| การ์ดสถิติลอยแยก 7 กล่องหลากสี | รวมเป็น Metric Bar แถบเดียว คั่นด้วยเส้นแบ่ง อ่านค่าง่ายและเป็นระเบียบ |
| ไอคอนแว่นขยายในช่องค้นหา | ใช้ `input[type="search"]` แทน ชัดเจนตามมาตรฐานเบราว์เซอร์ |
| สีชมพู/บานเย็นสดแบบสุ่ม | เปลี่ยนเป็นโทนสีสะอาด สบายตาตาม Hospital UI Tokens |
