# Design Spec: ทะเบียนผู้ป่วย Palliative Care (PC.Reg)

หน้า: `/service/dashboard-rcm/palliative-care/registry` (พยาบาล/เจ้าหน้าที่ Palliative Care และเจ้าหน้าที่การเงิน/RCM)  
ใช้ design tokens ชุดเดียวกับระบบ `ui-style-brief` ของโรงพยาบาลเถิน (อ้างอิง `PC.1` และ `PC.3`)

---

## 1. ปัญหาของหน้าเดิม และสิ่งที่แก้

| ปัญหาเดิม | วิธีแก้ |
|---|---|
| การ์ดสรุปสถิติ 6 ใบแยกกันลอยๆ สไตล์ AI slop | รวมเป็น **แถบสรุปตัวเลขชิ้นเดียว (Executive Metric Strip)** คั่นด้วยเส้นแบ่ง ตัวเลขเด่น `tabular-nums` 24px สบายตา ไม่มีไอคอนตกแต่ง |
| แก้ไขข้อมูลต้องกดปุ่มเปิด Modal ทีละเคส ทำให้บันทึกการเยี่ยมบ้านและผลเคลมช้า | ปรับเป็น **Google Sheets Inline Editing Data Grid** สามารถคลิกพิมพ์แก้ไขหรือเลือกดรอปดาวน์ได้โดยตรงในตาราง บันทึกอัตโนมัติ (Auto-save) พร้อมกะพริบแจ้งสถานะ |
| ขาดแถบสลับหมวดรายงาน ทำให้ผู้ใช้ไม่รู้ว่าอยู่ในหมวดเดียวกับ PC.1 และ PC.3 | เพิ่ม **Palliative Navigation Tabs** ด้านบน ให้สลับระหว่าง `PC.1 End Of Life`, `PC.3 ตามกลุ่มโรค`, และ `ทะเบียนผู้ป่วย (PC.Reg)` ได้ทันที |
| สีสถานะกระจายหลายเฉดและไม่เป็นไปตามเกณฑ์ 1 สี = 1 ความหมาย | ปรับใช้ Design Tokens มาตรฐาน: สีหลักเขียวเข้ม `#0b6b47`, สีสถานะสำเร็จ/ได้เงิน `#e8f6f4` (`#0f5c53`), สีรอ/เตือน `#fdf1d6` (`#6b4100`), สีเคลม `#e6f0fb` (`#17467a`), สีความเสี่ยง/ติด C `#fbe6ea` (`#8f1d3a`) |
| ช่องค้นหามีไอคอนแว่นขยายตกแต่งเกินจำเป็น | ปรับเป็น `input[type="search"]` สะอาดตา มี placeholder กำกับชัดเจนว่าค้นหา HN, ชื่อผู้ป่วย, หรือรหัสโรคได้ |
| หัวตาราง 20 คอลัมน์แถวเดียวยาวเหยียด ทำให้อ่านยากว่าคอลัมน์ใดเกี่ยวข้องกัน | เพิ่ม **Grouped Table Headers** แบ่งกลุ่มคอลัมน์ชัดเจน: ข้อมูลผู้ป่วย, การวินิจฉัย/โครงการ, ติดตามเยี่ยมบ้าน (1-6), การเสียชีวิต, การเบิกจ่ายชดเชย |

## 2. โครงสร้างหน้า (บนลงล่าง)

| # | ส่วน | เนื้อหา |
|---|---|---|
| 1 | ลิงก์กลับ & ส่วนหัว (Header) | `h1` ทะเบียนผู้ป่วย Palliative Care + ป้ายรหัส `PC.Reg` + คำอธิบาย + แถบสถานะ Auto-save + ปุ่มส่งออก Excel (ปุ่มรอง) + ปุ่ม `+ เพิ่มทะเบียนผู้ป่วย` (ปุ่มหลัก) |
| 2 | แถบแท็บสลับหน้า (Sub-nav Tabs) | แท็บสลับหมวด: `PC.1 End Of Life` \| `PC.3 ตามกลุ่มโรค` \| `ทะเบียนผู้ป่วย & เยี่ยมบ้าน (PC.Reg)` |
| 3 | แถบสรุปตัวเลข (Executive Metric Bar) | แถบข้อมูลสรุป 6 ช่อง: ผู้ป่วยทั้งหมด, ดำเนินการขึ้นทะเบียนแล้ว, รอขึ้นทะเบียน, ลงข้อมูลส่งเคลม, ชดเชยแล้ว (ได้เงิน), ติด C / Deny |
| 4 | แถบเครื่องมือ & ตัวกรอง (Toolbar) | ช่องค้นหา Live Search + ตัวกรองสถานะขึ้นทะเบียน + ตัวกรองสถานะเคลม + ตัวกรองผลลัพธ์เคลม + ปุ่มรีเฟรช |
| 5 | แถบคำแนะนำและคำอธิบายสี (Legend & Guide Bar) | คำแนะนำการแก้ไขแบบสเปรดชีต + Legend อธิบายความหมายของแต่ละสีสถานะ |
| 6 | ตารางข้อมูลสเปรดชีต (Spreadsheet Data Table) | ตารางข้อมูล 20 คอลัมน์พร้อม Grouped Header รองรับการพิมพ์แก้ไขและเลือกดรอปดาวน์ในเซลล์ ตัวเลขใช้ `tabular-nums` |
| 7 | ส่วนท้ายตาราง (Pagination Bar) | สรุปจำนวนรายการที่แสดง + ปุ่มสลับหน้า `« ‹ หน้า X / Y › »` |
| 8 | หน้าต่างเพิ่มผู้ป่วยใหม่ (Intake Modal) | ฟอร์มบันทึกผู้ป่วยรายใหม่ (HN, ชื่อ-สกุล, ที่อยู่, เบอร์โทร, รหัสโรค) |
| 9 | หน้าต่างแก้ไขรายละเอียด (Edit Modal) | แบบฟอร์มสำรองสำหรับแก้ไขข้อมูลทั้งเคสอย่างละเอียด |

## 3. กติกาการแสดงผลและตรรกะ (Business Rules)

| หัวข้อ | กติกา |
|---|---|
| Google Sheets Inline Edit | คลิกที่เซลล์เพื่อแก้ไข: กล่องข้อความกด `Enter` หรือคลิกออกนอกช่องเพื่อบันทึก, ดรอปดาวน์เลือกแล้วบันทึกทันที |
| Optimistic UI & Auto-save | อัปเดตข้อมูลบนหน้าจอทันที ส่งคำสั่ง `PUT` ผ่าน API Gateway ไปยังฐานข้อมูล หากบันทึกสำเร็จเซลล์จะกะพริบสีเขียวอ่อน 1.5 วินาที พร้อมแถบสถานะแจ้งว่าบันทึกแล้ว |
| การติดตามเยี่ยมบ้าน | รองรับการลงวันที่และสถานะการเยี่ยมบ้าน 6 ครั้ง (`ยังไม่ได้เยี่ยม`, `เยี่ยมแล้วยังไม่ได้ลงข้อมูล`, `เยี่ยมแล้ว+ลงข้อมูลเสร็จ`) |
| การลงข้อมูลเสียชีวิต | รองรับการบันทึกวันที่เสียชีวิต และสถานะการลงข้อมูลจำหน่าย |
| สิทธิ์การใช้งาน (RBAC) | เฉพาะผู้ใช้ที่มีสิทธิ์ (`admin`, `staff`, หรือมีสิทธิ์ `edit_palliative_registry`) จึงจะสามารถแก้ไขเซลล์ในตารางได้ หากไม่มีสิทธิ์ เซลล์จะแสดงผลเป็น Text/Badge แบบ Read-only |
| ตัวเลขในตาราง | ตัวเลขทุกตำแหน่ง (HN, วันที่, ลำดับ, จำนวนคน) ใช้ `font-variant-numeric: tabular-nums` |
| สถานะว่าง (Empty) | แสดงข้อความ `ไม่พบข้อมูลทะเบียนผู้ป่วยตามเงื่อนไขที่เลือก` พร้อมปุ่มล้างตัวกรอง |

|---|---|---|---|---|
| Accent / ปุ่มหลัก | `#0b6b47` | `#ffffff` | `#0b6b47` | ปุ่มเพิ่มทะเบียนผู้ป่วย, Focus ring, แท็บที่เลือก |

## 5. การตอบสนอง (Responsive Design)
- **Desktop (≥ 1080px):** แสดงตารางเต็มความกว้างพร้อมแถบสถิติ 6 ช่องเรียงแนวนอน
- **Tablet / Small Desktop:** แถบสถิติปรับเป็น 3 คอลัมน์ 2 แถว, ตารางรองรับการเลื่อนแนวนอน (`overflow-x: auto`)
- **Mobile (< 768px):** แถบเครื่องมือและตัวกรองพับเรียงแนวตั้ง เป้าสัมผัสปุ่มและดรอปดาวน์สูง ≥ 44px

---

## 6. การเข้าถึง (Accessibility)
- คอนทราสต์ของข้อความทุกคู่สีผ่านเกณฑ์ WCAG 2.1 AA (≥ 4.5:1)
- เซลล์ที่แก้ไขได้รองรับคีย์บอร์ดเต็มรูปแบบ (`Enter` บันทึก, `Escape` ยกเลิก, `Tab` ย้ายเซลล์)
- มีป้ายกำกับและ `title` อธิบายการทำงานของทุกปุ่มและดรอปดาวน์
- ไม่ใช้สีเพียงอย่างเดียวในการสื่อความหมาย มีข้อความกำกับเสมอ

---

## 7. ข้อมูลที่หน้านี้ต้องใช้ (API Integration)
- `GET /api/service/dashboard-rcm/palliative-care/registry`: ดึงข้อมูลพร้อมการค้นหา, ตัวกรอง, แบ่งหน้า, และสรุปสถิติ `stats`
- `POST /api/service/dashboard-rcm/palliative-care/registry`: เพิ่มทะเบียนผู้ป่วยรายใหม่
- `PUT /api/service/dashboard-rcm/palliative-care/registry/:id`: อัปเดตข้อมูลรายฟิลด์ (Partial update สำหรับ Inline Editing)
- `DELETE /api/service/dashboard-rcm/palliative-care/registry/:id`: ลบเคส (จำกัดเฉพาะผู้ดูแลระบบ)
- สถาปัตยกรรม: 100% Zero-Database Socket ส่งผ่าน Thoen Hospital Centralized API Gateway
